# Plate-Local River Generation（Davis 2026）

## TL;DR

**"确定性 + 地形感知 + 下坡保证 + 无限域"这四件事第一次同时成立。** 解法是"**板块局部**"：确定性构造的板块种子（构造板块隐喻）同时给出**点值表示**（连续地形场 + 有界 warp）与**几何表示**（有界 Voronoi 式板块域），于是每个板块可以**独立**在低分辨率网格上追河（border-safe 约束 + 单调高度调整 + Strahler 序），**懒加载、逐板块缓存**（互不依赖、天然顺应 streaming）；全分辨率采样时**精确**计算到河流网络的距离、沿附近河段插值高度并按需混合——**混合结果本身不缓存**。下坡沿所有通道成立**由构造保证**（板块边界 warp 幅度被限制在河流边界余量之内）。参考配置实测：10 个板块缓存 **37.9 ms** 总构建、带河流查询的全分辨率采样 **1.13 µs/样本**（比纯地形 +0.85 µs）、缓存总占用 **0.169 MiB**。

> **一句话定位**：库内 PCG 谱系**首次落到"自然地形 / 水系"侧**——建筑/城市线（2001→2003→2006）回答"人造结构怎么长"，这条回答"**自然水网怎么在不存在的世界里保持诚实**"。对开放世界工程（NGR 一类）：**"按域切分 + 懒加载 + 构造性保证"是同一套流式世界语言在水文问题上的实例。**

## Problem（三难困境）

既有程序化河流两极分化（原文 Related Works 分两类）：

- **river-first**（先河后地形）与 **terrain-first**（先地形后河）**都只在固定域上工作**；要扩展到无限世界，通常要牺牲**网络相干性**（河网断裂/不连通）或**下坡保证**（水往高处流）；
- 无限域还带来工程问题：**没有全局预处理的机会**——不能等整个地形算完再追河。

**本文把目标写成四个同时成立的约束**：确定性（同种子同结果）、地形感知（河流随地形场变化）、**每一条通道下坡**（可验证的保证，而非"通常成立"）、无限域（逐块按需）。

## Core Idea（五步流水线）

```text
① 确定性板块种子 {c_j}（对偶表示）
     ├─ 点值表示：板块归属 = argmin |s_p·x + w(x) − c_j|（w = 有界 warp，|w| ≤ ~94 世界单位）
     └─ 几何表示：Voronoi 式有界域 B_i —— 用种子连线的中垂面裁剪：
        (p − m_ij)·n_ij ≤ 0（m = 两种子中点，n = 连向邻居的方向）
② 板块内低分辨率网格（100×100）：采样规划地形 H_plan；据到板块边界 ∂Ω 的距离
   标记 border-safe / lake-safe
③ 逐河溯源：按高度降序取 border-safe 源点 →
    始终走向"最低的 border-safe 且不相交的更低样本"；
    终点三选一：海平面（outlet）/ 已存更低节点（confluence）/ 死路（lake-safe 则成湖，否则弃）
    约束：每板块 K ≤ 50 条、源间距 s_min = 5 格；（n_max 步上限）
④ 单调高度调整：沿每条路径把河面高度单调化（保证"每段都下降"）+ 赋 Strahler 序
⑤ 懒加载逐板块缓存 → 全分辨率采样时按需混合：
    δ(x) = 到本板块全部河段的精确最小距离（穷举扫描，含湖泊圆盘）
    λ(x) = [min(1, δ/ω_river)]^α_river     H_final = λ·H_pre + (1−λ)·H_river
    ——混合结果不缓存，只缓存河网本身
```

### 保证如何成立（原文 §3.6–3.8 的论证链）

- 通道只在自己的板块内推进（border-safe 标记 + 步步检查）；
- **板块边界余量（100 世界单位）≥ warp 最大位移（~94 单位）** → 几何边界与点值边界之差不超余量 → **点值判定（归属）与几何判定（通道）不会打架** → "每段下降"由构造直接传递到最终地形；
- 作者用 16 点/段的采样做了**双重验证**：1,450 段全部下降；最终地形 23,200 个采样点无一处上升 > 10⁻⁹。

### 一个诚实的边界个案（原文自陈）

混合带（河槽开挖的影响范围）没有受到同样保证：92,800 个混合带采样中 **6 个（0.0065%）归属于邻板块 → 河槽外缘被裁掉**；**通道本身不受影响**。原文把它明确写出来而不是藏掉——这种"验证 + 报告反例"的做法在本库按"诚实记账"归档。

## Limitations

- **通道不跨板块边界**（设计使然；靠 border-safe 与约束缓解）——超长河流的"跨域连续性"不做承诺；
- 混合带 0.0065% 采样被邻板块裁剪（河槽外缘，通道无恙）；
- 查询是**穷举段扫描**（0.85 µs/样本）——未用空间索引，规模上探时有优化空间；
- 时间数据为"观察性测量"（非受控基准）；有限形状（立方星球）变体**无实测数字**；无引擎集成。

## Why It Works（本库读法）

1. **"先定域、后算河"**：此前无限域难题的根子是"河流需要全局视野"；本文用一个**确定性构造的有限分区**把全局问题切成互不依赖的局部问题——**"域的有界性"是一等公民**（与 Mira-Scene"稠密不够、有界才是关键"隔域同构）；
2. **懒加载的合法性来自"确定性"**：任何板块可以任何时候重建出同一结果（甚至先被丢掉的规划网格也不影响河网数值）——**确定性让"按需"变得自由**（可以任意丢弃、重建、并行）；
3. **保证靠构造、不靠修补**：单调高度调整（步骤④）+ 边界余量 ≥ warp（不等式设计）把"下坡"做成结构性事实，验证只是复核——**与"把约束写进结构"家族同源**（[[2026-09-30-Lens Flare Removal and Reconstruction|Lens Flare]] 的 1D 约束、Wonka 的 split 文法同族）。

## Game Development Relevance

- **开放世界基建的直接参考**（NGR 一类）：板块 = 生成分域，懒缓存 = chunk streaming，**"确定性"= 多人一致性 / 存档一致性**（同种子任何客户端得到同一地形与河网）；
- **河流是地形 PCG 的经典难点**（相干 + 下坡 + 无限域三选二）——本文给出"四者全要"的第一个构造性答案，且实现是 1,000 行量级的独立库（可直接移植）；
- **预算视角**：把"生成期"与"运行期"两本账算得极清楚——生成（缓存构建）一次性几十 ms 并随板块分摊；运行期查询 1.13 µs/样本、内存 0.169 MiB/10 板块——**这是 PCG 系统"运行时负载"的稀有好样本**（此前库内多为"离线生成快但运行期不可知"）；
- 与 [[Procedural Content Generation]] 的"成本账本"条目（2001：13K 建筑 ≈ 10 分钟生成）互为对照：**同一个域的两端（离线批量 vs 在线按需）的成本结构。**

## Unreal Engine Relevance

- 无直接实现；映射路径清晰：**要接入 UE 的 PCG Framework / 地形系统时，"板块"对应世界分块（World Partition cell / PCG graph partition），"懒缓存"对应 runtime PCG 的按需构建**；
- 河网结果（节点/段/宽度/Strahler 序）是**可以直接喂给 Water 系统样条**的中间表示形态——"程序化生成河网 → 引擎水体系统渲染"的接缝设计与本方法同构；
- 对照 [[Müller — Procedural Modeling of Buildings (2006)]] 的"离线生成量 ≠ 运行时负载"：本文是**反向样本**（运行时按需、生成摊薄）。

## Relationships

### Based On

- 程序化地形线（1970s–80s 分形 / Perlin 噪声；记名）：地形场本身的生成基础；
- **构造板块 / Voronoi 分域**：地质学的板块隐喻（原文核心设计选择）。

### Contrasts

- **river-first / terrain-first 两派**（固定域）→ 本文：**不选边，改问题域**（把"先谁后谁"换成"按域各自局部"）；
- 与 [[Parish-Müller — Procedural Modeling of Cities (2001)]] 对照：后者生成**网络状的人造结构**（路网）并显式提到 rivers 作为地形约束的邻居问题；本文生成**网络状的自然结构**（水网）——"网络化生成"的两个案例分属人造/自然两端。

### Related

- [[Procedural Content Generation]]（域入口）：PCG 谱系新增"自然地形 / 水网"分支的第一个 2026 样本；
- **"有界性"母题**（[[2026-09-20-Mira-Scene — Pixel-Aligned Layouts for Generative 3D Scene Reconstruction|Mira-Scene]]："稠密化不够、有界才是关键"；本库 9-23 借条）——本文是"有界域让全局问题局部化"的 PCG 实例；
- **"约束处置三档"**（拒绝 / 修正 / 有条件接受，[[Procedural Content Generation]] 第 2 条抽象）：死路 → lake-safe 则成湖（有条件接受）、否则弃（拒绝）——同一抽象的新样本；
- **"确定性"**：与 1997 Instant Radiosity 的 quasi-random（"用确定性换方差"）隔 29 年呼应——**但此处的动机是工程一致性而非降噪**。

## Learning Value

**四条可迁移抽象**：

1. **"把全局问题切成本地问题"的关键是找到一个确定性构造的域划分**——判据：*我面对的"需要全局视野"的问题，是否存在一个可确定性构造的分区，使每块能独立算？*（与空间哈希 / LOD 分区 / 图块渲染同一母题的 PCG 版）；
2. **"保证"应该来自构造而不是校验**——单调化 + 不等式设计（余量 ≥ warp），让"下坡"不可能是错的；**校验只用来复核，不用来兜底**；
3. **"懒加载 + 确定性 = 自由的丢弃权"**：规划网格建完即弃（4.10 MiB 可回收），因为任何时候可以重建——**内存账本与"可重建性"直接兑换**（与"重放换存储"第三次同构：**确定性 = 可重放 = 可丢弃**）；
4. **"诚实反例"的价值**：0.0065% 边界个案的明确报告，使"保证"一词有了精确的适用范围——**边界写进笔记**（本库规范的外部印证）。
