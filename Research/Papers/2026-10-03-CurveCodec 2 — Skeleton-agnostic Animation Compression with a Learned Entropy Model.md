# CurveCodec 2: Skeleton-agnostic animation compression with a learned entropy model

> **入库 2026-10-06（Run #28）。** HKU（Mingyi Shi / Huancheng Lin / Taku Komura）× Adobe Research（Xuelin Chen）；前作 **CurveCodec 1（"Neural Codec for Skeletal Animation Compression"）已被 SIGGRAPH Asia 2026 Conference Papers 接收**（DOI 10.1145/3829340.3842192），本篇是它的重写版（"v2 replaces v1"）。10-3 提交、经 API"未公告先见"通道捕获。**本文开启库内一个新域：[[Animation Compression]]——动画数据被"存"和"传"的那一半问题**。

## TL;DR

**把"动画压缩"拆成两半：决定"哪些样本不编码"的有损阶段（经典算法，逐关节、闭环、经前向运动学验证）+ 把剩余整数编到极限的无损阶段（一个小学习模型，只做熵编码）——由此得到"骨架无关"的生产级编解码器。** 每个片段在 0.01–1 cm 的**误差契约**下验证（最坏情形或平均误差两种口径，失败则回退并计数）；模型：**108 K 参数因果 Transformer（870 KB），整型推理跨平台位精确**。结果：**0.01 cm 最坏情形契约下只要 ACL 的 0.37× 字节；0.1 cm 平均契约下 0.22×**；解码单核 **2.1 s / 百万关节样本**（55 关节骨架 ≈ **8,700 fps**）。

> **一句话定位**：**"误差定预算"语言进入动画数据域的第一个完整形态**——Ward 1988 用容差 a 决定"哪里要重算"，CurveCodec 2 用误差契约决定"哪些样本不编码"；且它是今天"分工判据"最干净的一份**反例向**样本：三组测量证明**该由学习模型接管的只有熵编码，'补中间帧'交给网络全部不划算**。

## Problem（为什么这是个真问题）

- 每个关节、每一帧都存变换（四元数+平移 = 28 B/关节）——**绝大部分比特是"身体先验"（由骨架结构隐含），不是"动作在说什么"**；
- 生产编解码器（如 ACL）必须对**任意骨架**、在**声明的误差界**内工作——"误差界"是生产合同的一部分（动画可以压狠一点，但破坏性误差必须被界定）；
- 前作缺口：CurveCodec 1 用"稀疏锚点 + 学习先验"匹配了 ACL 的平均误差，但**最坏情形不稳定**，且按浮点数计数（不是真实比特）；
- 核心提问（原文）：**"骨骼运动的冗余到底在哪里？一个学习模型应该接管编解码器的哪一部分？"**——用三组测量回答（见下）。

## Core Idea（两阶段 + 契约）

### ① 有损阶段（只跑一次，编码器侧）：逐关节的"哪根键不编"

- 每条子轨道变成 **log map 空间的一条曲线**；闭环里做两种动作：**长大量化步**或**丢键**（不编码的样本）；
- **接受条件**：新动作的"每省一比特所增失真 ΔD/ΔR ≤ λ" **且** 通过前向运动学验证后**误差契约仍成立**；λ 逐步抬升直到误差预算花完；
- **误差度量的关键选择——"壳误差"（shell error）**：每个关节挂三个虚拟顶点（δ = 3 cm，沿关节轴），误差 = 前向运动学后三个顶点在世界/物体空间的最大位移——**它天然包含所有祖先关节的误差**（原文：`e(j,t) = max over axes |T(t)·δe − T̂(t)·δe|`）；
- 两个反直觉的测量结论：
  - **"丢键"每比特只增"长大步"的 1/5–1/10 失真**（0.03 vs 0.17 单位）——省比特的边际最优动作是"少编一个样本"；
  - **层级决定谁被编**：关节误差会传给所有后代 → **根关节保留最多样本**（0.01 cm 下根旋转保留 86.9%，深度 6+ 只保留 56.7%），ACL 只能整帧丢（每关节都可线性插值才丢，0.01 cm 下只 0.38% 的帧够格）。

### ② 无损阶段（网络唯一出现的地方）：残差的熵模型

- 固定预测器（每个整数从**自己的过去**预测）→ 残差 `r = n − n̂`；
- **108 K 参数因果 Transformer** 给出残差分布 → **rANS** 编码；解码器**逐位同步重放同一模型**——整型推理，**跨平台位精确**（生产要求）；
- 消融（移除单一组件后的相对开销）：① **预测**（从自身历史）2.34–2.99×——最大单笔收益；② **选键**随界放松增大（最大契约下 1.08→1.69×，平均契约下 1.32→2.23×）；③ **学习熵模型**再 +7–10%；④ Transformer 比 MLP 多 4–5%；⑤ 组件"变薄"收益 ≈ 0。

### ③ 三组测量（回答"冗余在哪里"）

1. **最大收益 = 从曲线自身历史预测**（不是任何"生成"）；
2. **其次 = 逐关节、闭环、经层级决定"哪些样本不编码"**；
3. **缺口上，学习式补帧不成立**：*"在编码器留下的缺口上，百万样本的最近邻 oracle 都不比线性插值好，我们试过的所有学习式 in-betweener 都不回本"*——**网络真正学到的是"残差的分布"，而不是"动作的样子"**。

## Why It Works（为什么成立）

- **分工正确**：有损决策（编码什么）用经典闭环算法——误差可在**前向运动学链路**上直接验证；无损后端用学习——只需对"残差分布"负责。原文对此的总结句：*"一个更小的流需要的，是'编码什么'的不同决定，而不是更好的后端。"*
- **契约 + 回退**：每个片段**逐个验证**（最坏情形或平均口径），失败片段回退到 ACL 并**计数**——质量保证是显式的、可审计的（工程诚实：回退纳入统计）；
- **骨架无来源自表示**：log map 曲线 + 逐关节处理 + 网络只吃残差 → 迁移无需重训（连物种都行）；
- **位精确整型推理**：跨平台一致性是生产编解码的硬需求（跨 PC/主机/移动端播放同一数据）。

## Limitations（原文承认 + 边界澄清）

- **不是运行时编解码器**（原文 Q&A 直答 "Could it replace ACL? **No.**"）：无随机访问、按片段顺序一次性解码（装载时）、非无状态、编码器慢（闭环）；换来的是更小的字节数与位精确；
- **与 ACL 的真实分工**：ACL 为"运行时最优"设计——无状态、内存里保持压缩态、**只解当前帧需要的姿态**、随机访问、最小化内存触碰（作者原话："接近纹理压缩的哲学（BC7）：压缩格式直接在内存里用，没有中间解包步骤"）；CurveCodec 2 适合**冷存档 / 传输 / 装载时解码**——**互补而非替代**；
- **最弱场景**：短、稀疏、低帧率片段（开销摊不薄、没样本可丢）；
- 学习边界样本：in-betweener 方向"全军覆没"——不是每个环节都值得神经化。

## Game Development Relevance

- **直击引擎内存预算**：动画数据是角色内容的常驻大头（文本引用 ACL 作者：现代游戏 **>100k clips**；单个角色一帧可能要解 **3–20 个片段**）；0.37×/0.22× 意味着**同内容的内存账单可以直接重写**，且精度是"声明 + 验证"的（生产可用性的前提）；
- **"误差契约"进入预算语言**：动画档位 = **误差界档**（0.01 / 0.1 / 1 cm 连续可调）——与你的五档思路同构：**同一个动作，不同档位给不同误差预算**；且"契约（含回退）+ 计数"是比"平均指标"更工程化的质量声明形式（呼应 Ward 的 a 容差、Budgeted-GS 的对偶证书——**"预算的可认证性"第三例**）；
- **ACL 作者邮件（项目页收录，一手）提供两条引擎侧硬知识**：① **update pass（延迟约束、随机访问、少碰内存）vs evaluate pass（吞吐约束、批量线性）**——动画在 CPU 上常是最慢的帧内项之一，且移动端/Switch 的 CPU cache 极小；② **导入时间的历史账**："旧 UE5 编解码器导入/压缩 1–2 分钟的过场动画最长要 45–90 分钟，ACL 只要几秒"——**编解码器的成本是三本账：内存 / 解码速度 / 导入时间**；
- **对 NGR 一类项目的直接含义**：若在寻找"动画内存砍半"的路径，本篇是"装载时/存档侧"选项的当前最优样本；运行时流式仍归 ACL 体系。

## Unreal Engine Relevance

- **ACL**：开源库，以插件形式广泛用于 UE / 多家引擎与工作室（本库"[[Animation Compression]]"概念笔记的工程锚点）；CurveCodec 2 暂为研究原型（代码已放出、有浏览器 demo）；
- 潜在组合路径（原文立场之外的工程推断，标注为推断）：**冷数据（过场/低复用剪集）用 CurveCodec 2 压缩存档 → 装载时解到内存**；热数据（高频混用的 locomotion 片段）保留 ACL 随机访问路径——但需先解决"解码后的内存布局与运行时接管"问题，论文未涉及。
