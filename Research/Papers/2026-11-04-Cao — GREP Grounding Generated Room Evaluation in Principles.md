# GREP: Grounding Generated Room Evaluation in Principles（UW × Tencent AI Lab, 2026）

> 这篇论文的主角不是生成器，是**评测**。它要回答的是一句被反复回避的话：**"这个生成的房间，到底哪里不好？"**

## TL;DR

**打分只能排序，报告才能修改。**

GREP 把"房间好不好"拆成**三层递进**（物理合法 → 视觉协调 → 人类可用）+ **八个指标**，让一个 Agent 自己去找证据、自己判断"证据够不够"，最后**同时给出分数和一份点名到物体的诊断报告**。

两个结果，第二个才是重点：

- **与人类多数偏好一致率 86.7%**（整体 VLM 评判 62.2%，纯物理指标 53.3%；15 组两两比较 / 6 个场景 / 5 位标注者）；
- **只给分数会让场景变差**：三轮修订后，报告组 0.585 → **0.676**，只给分数 **0.585 → 0.543**，完全不给反馈 0.543 附近。**改动的动作率：报告 15/15，分数 5/15，不给 6/15。**

**一个连"我没有把握"都说不出来的评测器，给出的分数只是噪声。** GREP 让 `insufficient` 成为一个合法输出——这一个小设计，比分数公式重要。

## Problem

LLM 已经能"选资产 + 摆位置"生成像样的家具房间，但评测还停在两个不合格的形态：

| 现状 | 病 |
|---|---|
| **固定视角 / 固定问题**（SceneEval、LEGO-Eval） | 检查清单由输入描述或标注决定 ⇒ **描述里没有的东西查不到**（图 1C：一组"面对面 0.16 m"的椅子，两个基线都因为"没标注这一对"而漏掉） |
| **整体 VLM 打分**（holistic judge） | 只看一张全局图 ⇒ **"看起来还行"**（图 1B：1.8 m 长的鞋，全局视角看不出比例错） |
| **硬几何规则** | **分不清"贴墙"和"穿模"**（图 1A：镜子离墙 0.0008 m，纯接触规则判成"悬空"） |

**三者的共同病根是同一个：它们都在回答"这个场景过不过"，而不是"这个场景哪里不对"。**

## Historical Context

评测这件事在图形/视觉里被反复重造，每一次都是"把某个标量换成一组有名字的量"：

```text
图像质量：PSNR → SSIM → LPIPS →（Giroux 2023：15 个 IQA 指标在人判断上≈随机）
  ↓
生成质量：FID / CLIP-Score → 结构化问题（DSG 的原子问题图）
  ↓
3D 场景：碰撞/支撑的硬规则 → SceneEval / LEGO-Eval（固定检查表）
  ↓
2026-11  ★ GREP：三层原则 + Agent 自主取证 + 报告
```

**注意这条线上反复出现的一个事实：越"整体"的指标，越容易被人类判断打脸。** 见 [[Giroux 2023 — Towards a Perceptual Evaluation Framework for Lighting Estimation|Giroux 2023]]：高光材质 / 无参照的可信度任务上，标准 IQA 指标与人类的一致率**接近随机**。

## Previous Work

作者划的三类：**结构化评测器**（DSG / weak-verifier / SceneEval / LEGO-Eval / SceneTeract）、**模型型评判**（reference-free 指标、VQA、LLM/VLM judge）、**证据驱动观察**（AffordBot / A3R / Chain-of-View）。

GREP 的位置：**用 VLM，但每个判断都被"场景特定的检查 + 保留下来的证据"约束**——不是"让 VLM 看一眼打个分"。

## Core Idea

### ① 三层原则，八个指标

| 层 | 问什么 | 指标 | 这一层能抓住什么 |
|---|---|---|---|
| **A 物理合法** | 它是不是真的存在得下去 | collision（碰撞，**要区分"故意接触"与"穿模"**）· out-of-bounds · support | 桌子插进地毯、椅子悬空 |
| **B 视觉协调** | 它看起来搭不搭 | scale · style · pairing | 1.8 m 的鞋、风格打架、同一张挂画重复八次 |
| **C 人类可用** | 人能不能用它 | placement · function | 椅背贴墙、膝盖顶着墙、面对面的椅子间距 16 cm |

**三层是递进的**：物理合法的房间可能视觉荒谬，视觉协调的房间可能没法住人。**这个阶梯本身就是一份"缺陷严重度"的定义**——比任何加权都更可解释。

### ② 让 `insufficient` 成为一等公民

Agent 对每个检查先看"手上的证据够不够"，不够就**自己去取**，三种操作：

1. **量**（距离 / 相对角度 / 重叠 / 间隙）；
2. **取已有视角**（同一物体组的 function 检查共用一个证据库）；
3. **渲新视角**（换相机、场景不动）——并要求新视角**真的补上了缺的那条证据**，否则丢弃。

**预算耗尽时强制给二元判决，但记录里标明"这是被迫的"。** 基线做不到这件事：它们的视角在判断前就固定了，**没有"我不知道"这个状态**。

### ③ 分数与报告同源

$$S_m=100\,(1-\alpha P_m)\left(1-\frac{B_m}{N}\right)^{\gamma},\qquad \alpha=0.4,\ \gamma=4$$

$P_m$ 是该指标下最严重事件的罚分，$B_m$ 是全部事件的罚分总和，$N$ 是房间物体数。**关键在分母**：按物体数归一化 ⇒ "大房间里一个坏椅子"和"小房间里一个坏椅子"分数不同，这是有意的。

**报告不是分数的附属品，是同一批检查记录的另一种投影**：每条记录 = 检查类型 + 目标物体/关系 + 判决 + 理由 + 支撑证据（测量值或视角）。**证据缺口也写进去。**

## Technical Approach

**基准**：30 个场景（20 开放空间 + 10 简单矩形墙的户型）；三种生成设定——**模型原生规划**（8 个模型：GPT-6 Astra / GPT-5.6 Sol / Claude Opus 5 / Claude Fable 5 / Claude Sonnet 5 / Kimi K3 / GLM-5.3 / HY4 Preview）、**专用管线**（LayoutGPT 一类手写规则）、**Agent 外壳**（同一模型套不同的 harness）。

**评测器**：GPT-5.6 Sol 当 judge。

## Results

### ① 与人类偏好的一致率（15 组两两比较，5 位标注者，6 个场景）

| 评测器 | 一致率 |
|---|---|
| **GREP** | **86.7%** |
| 整体 VLM（GPT-5.6 Sol，只看全局图） | 62.2% |
| 纯物理指标 | 53.3%（≈随机） |

**人类自己的一致性**：5 位标注者在 15 组里有 11 组全票一致，4 组 3:2。**GREP 只在 2 组上和多数不一致**——这是很高的一致性，但注意样本只有 6 个场景。

### ② 报告 vs 分数（最实用的一张表）

| 反馈形式 | 起始分 | 三轮修订后 | 布局实际改动 |
|---|---|---|---|
| **诊断报告** | 0.585 | **0.676**（+0.091） | **15/15** |
| 只给分数 | 0.585 | 0.543（−0.042） | 5/15 |
| 不给反馈 | 0.585 | 0.543 附近 | 6/15 |

**"只给分数"比"完全不给"还略差，而且几乎不改布局（5/15）。** 作者的解释很直接：**分数不提供方向**——模型收到"0.54 分"，唯一能做的是随机重排；收到"餐椅与餐桌重叠、间隙 −0.12 m"，它知道该动哪一把。

### ③ 重复性（决定"这个分数能拿来比什么"）

12 个场景 × 5 次重复（输入、配置、judge 全冻结）：

- **每场景标准差中位数 2.9 分**（范围 0.4–7.3）；**最高与最低之差中位数 7.2 分**（最大 17.2）；
- 场景之间的差异远大于重复差异：**ICC = 0.92**，重复间 Spearman 0.70–0.98（中位 0.90）；
- 换算：10 个场景取均值时标准误 ≈ 1.3 分，两个均值之差 ≈ 1.9 分 ⇒ **模型均值差小于约 4 分的，不要当成差异。**

### ④ 一个关于生成模型的意外观察

给同一批模型加**更严格的约束（要求资产多 20%）**时：**强模型反而变差**——GPT-5.6 Sol 在 harness 下"守着原有计划不肯改"，而弱模型被 harness 补上了规划能力反而受益。

作者的表述：**"更强的规划，现在伴随着更差的对外部约束的适应。"** 阶段划分是"依赖 → 冲突 → 整合"，现在的模型在第二阶段。

## Why It Works

### 把"评分"当成"压缩"，把"报告"当成"索引"

一个标量把 N 条检查记录压成一个数，**压缩必然丢信息**。问题不在"压缩得不好"，在**下游只能拿到压缩结果**。

- 分数够用的场景：**排序、选型、做表**（哪个模型更好）；
- 分数不够用的场景：**修改**（哪里要动）。

**GREP 的证据是"报告没有额外成本"**——它和分数来自同一批检查记录。**这也解释了为什么"只给分数"会让人（或模型）乱改：它拿到了结论，没拿到依据。**

### 三层原则的真正作用不是分类，是"排序修复顺序"

同一份报告里同时有"桌子穿模"和"椅子朝向不对"时，**先修哪个？** 三层的递进给了默认答案：物理不合法时，视觉和功能的判断本身就不成立（穿模的桌子，"桌面高度是否合适"这个检查没有意义）。

**这是一个几乎没人明说、但所有自动评测都需要的东西：缺陷之间的优先级。**

## Limitations

1. **单一 judge 模型，而且它自己也在被测**：全部实验用 GPT-5.6 Sol 当 judge，而 GPT-5.6 Sol 是 8 个被测生成器之一。作者自己点名了自偏好风险（LLM 评判器会认出并偏袒自己的生成），跨 judge 检验只覆盖 6 个场景——**"GREP 的 86.7% 里有多少是 judge 的功劳"，本文答不了**；
2. **覆盖的是"已经提出来的检查"**：检查由固定的检查类型在提交的物体上实例化，**不能保证 Discovery 阶段把房间里所有相关物体/关系都找到了**；
3. **预算下的被迫判决**：证据取不够时会给二元判决，记录里标明来源，但**它可能是错的**；
4. **一致性实验的样本太小**：6 个场景、15 组、5 位标注者——**86.7% 的置信区间不窄**；
5. **只能评"摆得对不对"，评不了"好不好看"**：风格/审美的上限由 scale/style/pairing 三个粗糙指标决定，**没有光照、没有材质、没有相机**。

## Game Development Relevance

**它不是游戏技术，但它处理的是游戏管线里一个真实的缺口：生成内容的验收。**

1. **室内/关卡摆件的自动 QC**：现在这类检查靠 TA 写规则（碰撞、悬空、可达性），规则写不全就漏。**三层阶梯是一份现成的检查清单**，而"报告点名到物体"正是美术能直接动手的粒度；
2. **"只给分数会更差"这条，对任何自动反馈回路都成立**：关卡自动评测、程序化生成的选择压力、AI 辅助的关卡修订——**如果你只把分数喂回去，被优化的会是分数，不是关卡**。**这是 reward hacking 的一个具体形态，而且是可测的**；
3. **`insufficient` 状态值得抄**：任何自动 QA 工具都该能说"这一项我看不清/量不到"，否则它会把"没看见"当成"没问题"。**这是自动化的假阳性来源，比漏检更难查**；
4. **重复性数字是决策门槛**：**差值 < 4 分不要当差异。** 任何"用自动评分对比两个版本"的项目，第一步都该量这个数——否则你在追噪声。

**不该拿它做的事**：评美术质量、评性能、评玩法。它评的是"这个房间作为房间成不成立"。

## Unreal Engine Relevance

**没有引擎内映射**（它是离线 Agent 评测）。可迁移的是**结构**：三层原则 ≈ 一份 Editor Validation 的分级规则集（Error / Warning / Info），报告格式 ≈ 可直接点进 `FMessageLog` 的条目（目标 actor + 检查项 + 测量值 + 证据截图）。**UE 的 Data Validation 插件缺的正是后两项：数值与证据。**

## Technology Evolution

```text
2023-24  结构化原子问题（DSG）：把"像不像"拆成可判定的子问题
  ↓
2024-25  场景级检查表（SceneEval / LEGO-Eval）：从"图文一致"到"物理合法"
  ↓
2025-26  模型型评判（VLM judge）：泛化好，但不可解释、会被骗
  ↓
2026-11  ★ GREP：三层原则（定优先级）+ 自主取证（补证据）+ 报告（给方向）
          · 86.7% vs 62.2% / 53.3%
          · 报告 0.585→0.676，只给分 0.585→0.543
```

**这条线的形状是"从'像不像'到'能不能用'"**，而每一步都把"谁的判断"往前提：指标 → 检查表 → 模型 → **模型 + 证据 + 可拒绝**。

## Relationships

### Based On

- **SceneEval / LEGO-Eval**（检查表的直接前身）：被超越的地方很具体——**它们的检查词表由输入描述决定，GREP 由场景上下文决定**；
- **Chain-of-View / AffordBot**（自适应取证）：GREP 把它从"affordance 推理"搬到"场景质检"。

### Contrasts

- [[Giroux 2023 — Towards a Perceptual Evaluation Framework for Lighting Estimation|Giroux 2023]]：同样是"评测"，那边的结论是**标准指标与人类判断≈随机，但可以用少量二选一训练出项目专用指标**（SVR 0.786–0.889）。**两篇合起来是一条完整的方法论：先证明单指标不行，再给一条"用报告/偏好对训练评测器"的路**；
- **传统程序化 QA 的硬规则**：不是替代关系——GREP 的 collision 检查也是几何测量。**差别在"规则覆盖不到的地方，它能不能说'我要再看一眼'"**。

### Related

- [[Procedural Content Generation]]：生成侧的另一半。**本页补上了 PCG 长期缺的"验收"一节**——此前库内的 PCG 讨论全部集中在"怎么生成"，没有一页讲"怎么判断生成得对不对"；
- [[2026-11-02-Guo — FlowRig Unified Skeleton Generation for 3D and 4D Meshes via Flow Matching|FlowRig]]：**同一批"离散量"问题的另一面**——那边是"离散量不能压"，这边是"离散判决不能只有分数"。

### Followed By

- （待观察）**评测器自身可训练**：Giroux 那条路（几十组二选一训一个项目专用指标）与 GREP 这条路（Agent 报告）大概率会合成一件事——**报告当训练信号，指标当推理时的快路径。**

## Personal Knowledge State

**Normal（结论层 15 分钟：图 1 的三层 + 报告 vs 分数那张表 + 重复性数字）**

- **Easy**：为什么要自动评测、VLM judge 会自我偏袒、碰撞/悬空/可达性这些规则本身；
- **Normal**：三层为什么是递进而非并列（= 修复优先级）、`insufficient` 为什么是一等公民、为什么"只给分数会更差"、重复性数字怎么用；
- **Hard**：Agent 的取景策略与预算控制细节（附录 A）——**要用再读**。

## Learning Value

**两条可以直接搬进任何管线的判据：**

1. **反馈的粒度决定它能被用来做什么**：分数 → 排序；报告（点名 + 理由 + 证据）→ 修改。**如果你的自动反馈只有分数，那它只能用来选，不能用来改**；
2. **一个评测器必须先能量自己的重复性，才能用来比东西**。GREP 自己给了这个数：**同样输入重复五次，单场景标准差 2.9 分、极差中位数 7.2 分** ⇒ 均值差 4 分以内不算差异。**任何"用自动分对比两版"的会议结论，先过这一关。**

**读图**：三步流水线。**① 提检查**：VLM 先过一遍场景，按三层原则在具体物体上实例化检查（注意它列的是检查**类型**，不是固定清单）；**② 取证与判决**：每个未决检查去拿"量到的数"（间隙 $d$、角度 $\theta$）或"看得见的视角"，中间那个菱形是本文的关键——**"证据够不够？"不够就回到取景器渲新视角**；**③ 打分并诊断**：判决先汇总成 metric → room → scene 三级分数，**同时**生成物体级的诊断记录（目标 / 检查项 / 判决 / 证据）。**看这张图只抓一件事：分数和报告是同一个节点的两个输出，不是两套流程。**（图 2，Cao et al. 2026）

- **judge 与被测重叠这件事，作者写得比大多数人都诚实**：Limitations 第一条就是它，并且承认跨 judge 检验只覆盖 6 个场景、**无法证明任一 judge 是否偏袒自己的模型家族**；
- **一个没被强调但很重要的设计**：function 检查按"物体组"共享证据库（同一组桌子-椅子-灯只取一次景），**这是把"证据成本"也当成预算来管**——与库内 [[Real-Time VFX Performance Budgeting]] 的"预算"语言同构，只是计价对象换成了"渲染几个视角"；
- **分数公式里的 $\gamma=4$ 很陡**：$B_m/N$ 稍微大一点，$(1-B_m/N)^4$ 掉得极快。这意味着**它惩罚"少量严重缺陷"远大于"很多轻微缺陷"**，与三层递进的设计一致，但**这两个常数（0.4 / 4）没有消融**——是设计决定，不是拟合结果。
