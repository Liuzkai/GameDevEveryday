# RLSplat: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting

## TL;DR

**"预算是给产物的，还是给生产过程的？"** 现有可预算前馈 3DGS（EcoSplat / F4Splat）只做到了前者：**先预测一大堆高斯，再按预算裁掉**——于是**产物小了，生产成本没变**：延迟与峰值显存几乎与预算无关（图 1c 的两条平线）。

RLSplat 把"裁剪"换成"**分配**"：给定预算 $B$，一个**高斯分配策略**直接决定每个锚点区域分到多少个高斯（$\sum k_n=B$），**正好生成 $B$ 个**；再用**资源线性解码器**（每个高斯只对邻居做局部 cross-attention，$O(BK)$ 而非 $O(B^2)$）精修。结果：**表示大小、推理延迟、峰值显存三者都随 $B$ 线性下降**。

数字（ACID，RE10K 零样本）：2K 预算下比 F4Splat **高 0.9 dB**，同时**峰值显存少 9.6×、速度快 4.1×**；24 视角下用 **24K** 高斯打出 25.58 dB，而 SPFSplat 用 **1536K** 才 25.00 dB——**少 64 倍**。

> 一句话对读者：**"事后裁剪"的预算只约束了验收单，"过程内分配"的预算才约束了工位**。这条区别在任何"预算"体系里都成立——包括你的 SABC。

![[Research/Files/Pictures/Kim 2026 — 图1 预算-显存-延迟三联曲线.png]]
**读图**：三联图把全篇的主张摆在一张图上。(a) 任意预算下 PSNR 都最高；(b) 同一个 2K 预算点，RLSplat 的峰值显存比 F4Splat 低 9.6×，PSNR 还更高（曲线越靠左上越好）；(c) 关键的一格——预算从 64K 降到 2K 时，**只有 RLSplat 的延迟跟着线性下降**，两条基线是水平的（"Nearly constant"）。（图 1，Kim et al. 2026）

## Problem

前馈 3DGS（FF3DGS）一次前向就出场景，天然适合"资源受限"的场合；进一步地，**可预算**版本允许推理时指定高斯数量 $B$，以适配存储上限或渲染延迟要求。但现有两条路线都有结构性缺陷：

1. **像素对齐派**（NoPoSplat / SPFSplat / AnySplat）：每个像素或体素一个高斯，**数量由输入分辨率与视角数决定，不由内容决定**——重叠视角产生大量冗余，且用户无法指定数量；
2. **可预算派**（EcoSplat：保留不透明度最高的 $B$ 个；F4Splat：多尺度预测后选 $B$ 个）：**先稠密预测，再裁剪/选择**——产物是 $B$，但**前向计算量、峰值显存仍是稠密那一档**。

于是出现一个很别扭的局面：**用户把预算调小，省了存储与渲染，却省不了"生成这个资产"的时间与显存**。在端侧/流式场景里，后者往往才是瓶颈。

## Historical Context

```text
2023  3DGS：显式高斯基元 + 可微光栅化 → 实时新视角合成
2023-24  逐场景优化（分钟~小时级）；压缩/剪枝线开始（减产物）
2024  pixelSplat / Splatt3R 等前馈 3DGS：一次前向出高斯（免逐场景优化）
2025  query-based（C3G / GlobalSplat）：固定数量的可学习 query → 数量由架构定死
2026  EcoSplat（按预算保留最高不透明度）/ F4Splat（多尺度后选）：
      "预算可调"但仍是"稠密预测 + 裁剪"——成本不随预算变
2026  ZipSplat（同期）：推理时对视觉 token 聚类控制数量
2026  ★ RLSplat：把"裁剪"换成"分配"，把"全注意力"换成"局部注意力"——
      产物 / 延迟 / 峰值显存三者同时线性
```

这条线其实是**整个 3DGS 预算史的一个缩影**：先能压产物（压缩），再能压渲染（LOD/排序），最后才有人问"**生成这个产物要花多少**"。

## Previous Work

- **逐场景 3DGS 的省法**：剪枝冗余高斯、在加密阶段就按预算放置（Fang & Wang、Mallick 等）——但都依赖逐场景迭代优化；
- **前馈 3DGS 的省法**：pixel/voxel 对齐（数量被动）、query 解码（数量由架构定）、预算条件化（先稠密后裁剪）；
- **策略优化**：策略梯度 / PPO / GRPO / **GSPO**（按整条序列的似然算重要性比并在序列级裁剪）——本文借 GSPO 来优化"离散分配"这个不可微决策；
- **邻域搜索**：KNN / 层次化搜索——本文用它把"全注意力"降成"局部注意力"。

## Core Idea

**把"生成多少"变成一个可学习的分配决策，而不是一个事后裁剪动作。**

$$k \sim \mathrm{Mult}(B,\; p),\qquad p=\pi_\psi(\{a_n\},B),\qquad \textstyle\sum_n k_n = B$$

- $\{a_n\}$：几何骨干输出的**锚点 token**，每个代表场景的一块局部 3D 区域；
- $p_n$：策略预测的"该区域应得的预算比例"；
- $k_n$：实际分配数（多项分布采样，天然满足总和 = $B$）；
- 每个锚点按 $k_n$ 生成 $k_n$ 个高斯 token → **总共正好 $B$ 个**。

**两个"线性"来自两处**：① 生成线性——不再有"稠密候选"；② 解码线性——每个 token 只 attend 邻居（$O(BK_{gs})$），而不是全局自注意力（$O(B^2)$）。

![[Research/Files/Pictures/Kim 2026 — 图2 分配式生成总览.png]]
**读图**：左边是"分配"这一步（锚点 → 策略 → 离散配额 1/4/3/2/6…，总和 = $B$）；右边是"线性解码"（按配额 spawning 出正好 $B$ 个 token → 层次邻居搜索 → 局部 cross-attn 精修）。**注意图里没有"裁剪"这个动作**——这是与所有基线最本质的差别。（图 2，Kim et al. 2026）

## Technical Approach

### 1) 分配策略怎么训：把渲染质量当奖励

- 分配是**离散且不可微**的（而且只能通过"渲染出来看"来评价），所以直接上策略优化：
- 每步采一组 $C$ 条分配 $k^{(c)}\sim\pi_{old}$（梯度截断），各自解码 + 渲染 + 算重建损失 $L_{recon}$（MSE + LPIPS），**奖励 $R_c=-L^{(c)}_{recon}$**；
- 组内标准化得优势 $\hat A_c$（GRPO 式，无需 value 网络）；
- 重要性比按 **GSPO** 的"序列级长度归一化"算：$s_c=\exp\big(\frac1B\sum_n k_n^{(c)}\log\frac{p_n}{\mathrm{sg}(p_n)}\big)$，再裁剪后最大化目标；
- **3DGS 光栅化极快 → 一次采多条 rollout 的训练开销可以忽略**（这是"用渲染当奖励"能成立的前提）；
- 推理时**不走采样**：把期望计数 $Bp$ 用确定性取整规则（附录 B）凑成恰好 $B$。

**两阶段训练**：先 base（随机分配 + 全预算范围采样，40,000 步）让解码器见过各种配额；再 policy（加策略头，5,000 步；**不加 KL**，因为 base 阶段没有参考策略；预算采样**偏向低端**——低预算处分配选择最要命）。

### 2) 线性解码怎么保精度：局部注意力的三个前提

局部注意力只有在"**真正的邻居确实在父锚点的邻域里**"时才成立，所以配了三个约束：

| 组件 | 作用 | 去掉会怎样（消融） |
|---|---|---|
| **层次邻居搜索** | 先找 $K_{anc}$ 个最近锚点，再在这些锚点的子高斯里找 $K_{gs}$ 个最近邻 | 全量搜索 220.8 ms → 8.1 ms（27×），端到端 539.2 → 328.3 ms |
| **Voronoi 损失** | 高斯必须离自己父锚点质心更近，不能漂进邻域 | 邻居命中率 99.0% → **60.2%**；PSNR −2.51 dB |
| **offset 损失** | 限制残差位移（相对局部锚点间距 $\delta=0.5$） | PSNR −0.53 dB |
| **投影损失** | 把锚点的高斯投回它编码时的图像块 | **去掉直接训崩**（PSNR 5.80 / SSIM 0.007） |

### 3) 预算怎么"分"才对：分配 vs 启发式

![[Research/Files/Pictures/Kim 2026 — 图4 同预算下分配对比.png]]
**读图**：同样 8K 总预算。楼梯栏杆这种**细高频结构**：EcoSplat 留 2,521 个、F4Splat 留 3,026 个、RLSplat 分到 **5,388** 个 → 局部 PSNR 17.79 / 20.00 / **23.51**；而平滑墙面反而分得更少（右列 tile 热力图）。**"预算按细节密度走"** 在这里是可看见的。（图 4，Kim et al. 2026）

但**必须诚实读表 4**：把策略换成启发式，差距很小——

| 分配方式 | PSNR |
|---|---|
| 随机/base | 24.18 |
| 均匀 | 24.53 |
| **Sobel 边缘启发式** | **24.76** |
| 学习策略（GSPO） | **24.83** |

**策略只比"按边缘强度分配"高 0.07 dB**。所以这篇的真正贡献不在"RL 很神"，而在**"分配"这个形式本身**（→ 成本线性）+ **"边缘启发式就能拿到九成收益"这个可用结论**。

## Key Contribution

1. **指出并量化了一个被忽略的账**：可预算方法只控制了**输出规模**，没控制**生产成本**（延迟/显存与预算脱钩）；
2. **把生成形式化为分配**（而非裁剪/选择），用 GSPO 在"渲染质量"这个不可微奖励上训练；
3. **资源线性解码**（局部 cross-attn + 层次邻居搜索 + 两个局部性正则），把 $O(B^2)$ 降到 $O(BK)$；
4. **全预算区间占优**：任意预算下 LPIPS/SSIM/PSNR 都最好，且**预算越小优势越大**（8 视角下对 F4Splat：4K +0.74 dB → 2K +0.99 → 1K +1.22）。

## Why It Works

- **"分配"消灭了稠密候选**：成本函数里那一项"先算 100% 再裁到 10%"被删掉了，剩下的成本正比于 $B$；
- **局部性是可以被训练出来的**：Voronoi + offset 两个正则把"邻居就在附近"从假设变成约束，邻居命中率 99% 后才敢用局部注意力；
- **奖励用渲染质量而不是代理指标**：分配好坏只能靠"画出来像不像"判断，而 3DGS 光栅化快到可以让"画一次"进训练循环；
- **预算被喂进了策略输入**：同一个网络服务所有预算（$B$ 是条件而非架构），这是"单模型多档位"的前提。

## Limitations

- **前沿仍是前馈重建**（RE10K/ACID 室内外场景、256×256 评测），**离"游戏资产管线"还有距离**：没有材质/PBR 通道、没有 LOD 层级、没有流式；
- **分配只按"重建误差"**：不感知下游用途（碰撞、导航、光影），游戏里"看不见但要用"的区域（碰撞代理）可能被分到 0 个高斯；
- **训练依赖策略优化**：虽然消融显示启发式也够用，但论文的主线仍是 RL——**工程上完全可以先用 Sobel 版**（作者自己的表 4 就是许可证）；
- **基线选择偏窄**：主要对比 EcoSplat / F4Splat；对 pixel-aligned 方法（表 2）的比较是"少 16–64 倍高斯"，但分辨率/场景类型不同，不能直接外推；
- **未报告训练成本**：40k + 5k 步、多卡？论文正文未给（附录未核）。

## Game Development Relevance

**这篇对读者的价值不在 GS，而在"预算"这个词的定义：**

1. **预算必须同时约束"产物"与"生产过程"**——你的 SABC 模板里，Niagara 发射器数 / 同屏粒子数 / 贴图尺寸都是**产物预算**；**制作成本**（艺术家调一版要多久、编译一次要多久、跑一遍性能测试要多久）从来没有进表。RLSplat 的表 1/图 1c 就是这个缺口的量化样本：**产物砍 32×，成本只降 1×**；
2. **"事后裁剪"是最贵的省法**：先做满再做减法，峰值成本永远按满配算。对应到 VFX：**特效如果按"最华丽版本"做完再降级，性能与人力都按最贵那档付账**；按档位**直接生成**（发射器数按档位参数化）才是线性的；
3. **"启发式拿到九成"是可用结论**：不必等一套学习式分配器——**按"细节/误差密度"分配预算**这条启发式（Sobel 边缘 ≈ 你的"屏幕占比 × 运动速度"）就能拿到大部分收益；
4. **一个反向警示**：分配只按"重建误差"优化，会**把预算从"看不见但要用"的地方抽干**——游戏资产的预算必须带**用途约束**（碰撞、导航、光影探针），这正是纯渲染指标做不到的。

## Unreal Engine Relevance

- **接口形态**：给定 $B$ 出资产，天然适配"**导入时按平台档位烘焙**"的流程（PC_High / Android_Mid 各导一份），比"导一版再运行时裁剪"更接近引擎侧的资产管线；
- **与 Nanite 的对照**：Nanite 是"几何侧连续 LOD + 运行时按屏占比取"，RLSplat 是"**生成侧按预算分配**"——一个管"取多少"，一个管"做多少"；两者结合才是完整账本；
- **Niagara 类比**：发射器预算如果只在最后"砍发射器"，等于 EcoSplat；**按技能档位直接配发射器数量**（S≤12/A≤8/B≤4/C≤2）才是 RLSplat 式——你现在的模板其实已经是后者，这篇给了它一个外部理论样本。

## Technology Evolution

```text
"预算"在 3DGS 里的三代问法：
2023-24  产物多大？      压缩 / 剪枝 / 量化            → 只管存
2025-26  渲染多快？      LOD / 前缀 / 排序线          → 只管画
2026     ★ 做它多贵？    RLSplat：分配式生成 + 线性解码 → 管"造"
```

第三代问题一旦提出，前面两代的"最优解"都要重算——因为**总成本 = 造 + 存 + 画**，而此前所有工作只优化了后两项。
