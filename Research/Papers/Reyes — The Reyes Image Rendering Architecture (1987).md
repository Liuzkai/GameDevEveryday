## TL;DR

**它做了一件在当时看是"反直觉"的事：先着色，再问看得见吗。**

Reyes 把一切几何**先细分成"微多边形"（micropolygon，屏幕空间约半像素边长的平面着色四边形）**，然后**对整个 grid 着色**，最后才用 z-buffer 逐采样点判可见。于是：

- **着色成本 ∝ 输出分辨率**（微多边形数 ≈ 屏幕面积 × 着色密度），**与模型复杂度脱钩**；
- 被挡住的微多边形**也已经付过着色钱**——这是"结构性 overdraw"最早、也是最干净的形态；
- **半像素不是审美选择，是 Nyquist 极限**：一个采样间距对应半个波长，所以一个微多边形一个颜色就够。

> 一句话对读者：**你今天的"像素预算"和"overdraw 账"，源头是这篇 1987 年的架构选择——把成本的计量单位从"场景里的三角形"换成"屏幕上的采样格"。** 见 [[Overdraw]] 与 [[Budget Units]]。

## Problem

1987 年的目标写得很硬：**"fast"= 一年做完一部长片；"high-quality"= 与实拍难以区分；"complex"= 像真实场景一样丰富**。按 24 fps、2 小时片长折算，需要**约 3 分钟一帧**。

三条硬约束同时压着：

1. **模型必须无上限**——不能因为"装不进内存"就限制图元数；
2. **渲染时间必须与模型规模线性**——否则复杂场景直接不可用；
3. **不能有走样**——锯齿、摩尔纹、时间频闪、高光闪烁都得消掉。

当时的两条主流路线都不满足：**光线追踪**要能随机访问模型任意部分（模型一大就分页抖动，"geometric locality"彻底丢失）；**扫描线 + 逐图元着色**则把着色绑在几何上（模型越复杂越贵）。

## Historical Context

```text
1974  Catmull 细分曲面（PhD）：曲面 → 小块多边形
1980  Whitted 光线追踪：递归反射折射，但随机访问模型
1984  Cook 分布式光线追踪 + shade trees：把"一个像素一个样本"换成"多个样本"
1984  Goral 辐射度：把间接光变成面片之间的矩阵
1986  Kajiya 渲染方程
1987  ★ Reyes：把"着色"从几何上摘下来，挂到屏幕采样格上
1988  RenderMan Interface：Reyes 成为工业标准接口
1990s PhotoRealistic RenderMan 全线产品化；微多边形管线成为动画长片的主力
2000s GPU 可编程管线：**次序反转**——early-Z 先判可见再着色
2010s 延迟着色 / tile-based：着色再次按屏幕网格组织（本质是 Reyes 的思路在实时管线上回归）
2020s 可见性缓冲 / 变率着色（VRS）：**显式地"按屏幕区域决定着多少色"**
```

**这条线的形态很有意思**：Reyes 是"先着色后可见"，GPU 早期是"先可见后着色"（early-Z 省掉了被遮挡的着色），而**延迟着色/可见性缓冲又把"着色与几何解耦"这一半拿回来了**——只是这次把"着色密度"做成了可调参数（VRS）。**同一件事在四十年里被反复发明，每次都换一个成本压力。**

## Previous Work

- **Catmull 1974**（细分曲面）：把曲面变成可渲染的小块，Reyes 的 dice 直接继承这条；
- **Clark 1979**（参数曲面快速渲染）与 **Lane–Carpenter** 细分：自适应细分的算法基础；
- **Cook 1984 分布式光线追踪 / shade trees**：把"一个像素一个样本"变成"多维度抖动采样"，Reyes 的随机采样直接引用；
- **Catmull 1974 的 z-buffer**：Reyes 用它做可见性；
- **Crow 1984 summed-area tables / Blinn 1978 凹凸贴图**：纹理滤波与位移的先例。

## Core Idea

**统一表示 + 自然坐标 + 线性成本。**

三条原则支撑整个架构：

1. **统一表示**：所有图元都变成 **micropolygon**（平面着色四边形），着色与可见性**只对微多边形做**；
2. **自然坐标**：每类计算在它最自然的坐标系里做——**纹理在 uv 空间（物体局部）**、**可见性在屏幕空间**。所以**没有裁剪、没有逆透视变换**；
3. **线性**：渲染时间 ∝ 微多边形数 ∝ 屏幕面积 × 着色密度。

**代价（也是它最值得记的地方）**：因为着色发生在可见性之前，**遮挡不省着色**。这不是疏忽，是架构的必然——换来的是"模型可以无限复杂、时间线性、无需裁剪"。

## Technical Approach

### 1) 八条设计原则（原文第 2 节）

| # | 原则 | 内容 |
|---|---|---|
| 1 | 自然坐标 | 纹理在 uv 空间、可见性在屏幕空间；**图元只在 uv 空间细分，绝不在屏幕空间重分** |
| 2 | 向量化 | 相似计算一起做（整张 grid 一起着色），吃并行与流水线 |
| 3 | 统一表示 | 一切皆微多边形 |
| 4 | 局部性 | (a) 几何局部性：一个图元的计算不引用别的图元；(b) 纹理局部性：只留当前要用的纹理 |
| 5 | 线性 | **渲染时间随模型规模线性增长** |
| 6 | 大模型 | 图元数**无上限** |
| 7 | 后门 | 留一个口子让别的渲染器画某些物体（把光追/辐射度"点采样"进同一张图） |
| 8 | 纹理贴图 | 每表面多个纹理；用位移贴图承载"模型复杂度" |

### 2) 流水线（原文图 3 的八阶段）

| 阶段 | 做什么 | 坐标系 |
|---|---|---|
| **bound** | 算包围盒，变换到屏幕空间 | 眼空间 → 屏幕 |
| **cull** | 视锥外 / hither–yon 外则丢弃 | 屏幕 |
| **split** | 跨 ε 平面且可分裂的，切开放回模型流头部（**split-until-cullable**） | — |
| **dice** | 细分成微多边形 grid，算法线与切向量 | **uv / 物体局部** |
| **shade** | **整张 grid 一起着色**（此时还不知道谁被挡） | uv |
| **break** | grid 拆成单个微多边形 | — |
| **sample / visibility** | 每微多边形的屏幕包围盒内逐采样点：在片内则插值 z，与 z-buffer 比较 | **屏幕** |
| **filter** | 对可见采样点滤波成像素 | 屏幕 |

**ε 平面**是这套设计的关节：紧贴眼前放一个 z 常数平面，跨它的图元被 split，直到可剔除或可 dice——**于是不需要 hither 裁剪，也不需要逆透视**。

### 3) 微多边形：半像素的理由

- **定义**：平面着色的四边形，"**每边约 1/2 像素**"；
- **理由**：半像素是图像的 **Nyquist 极限**——采样间距对应半个波长，所以**一个微多边形用一个颜色就足以表达**，不会丢信息；
- **自适应**：在眼空间按图元屏幕尺寸决定 diced 多细（对双三次 patch 用前向差分）；
- **grid 与限制**：一个图元的微多边形组成二维数组（grid），共享顶点只存一次；实现里**设了最大 grid 尺寸**，会超的图元强制标记为"不可 dice"→ 走 split。

**这一条是整篇最可迁移的判据**：**着色率的上限不是调参调出来的，是采样定理给的**。你的"每像素多少样本 / 每屏幕多少着色点"有一个硬下界，越过它只是白花钱。

### 4) 采样、运动模糊、景深

- **随机采样**：每像素分 **16 个子像素（典型值）**，每子像素一个采样点 + 抖动（jitter）——**用噪声换走样**（噪声比锯齿更不刺眼）；
- **运动模糊**：每个采样点把微多边形**移到该采样点对应的抖动时刻**；
- **景深**：按**抖动的镜头位置**在 x/y 上平移微多边形；
- **z-buffer + bucket**：屏幕切成矩形 bucket，**只需装得下一个 bucket 的 z-buffer**——这是"大模型/大分辨率"的内存解。

### 5) 两类纹理

| 类型 | 条件 | 后果 |
|---|---|---|
| **CAT**（相干访问） | $s=au+b,\ t=cv+d$（常数），可按 uv 顺序顺序访问 | 若 s/t 是 1/2 幂的整数倍且纹理预滤波成金字塔，**运行时无需滤波** |
| **RAT**（随机访问） | 其他（环境贴图、decal） | 慢但通用；**显著减少对光线追踪的需求** |

**"用纹理近似非局部效果"是 1987 年的核心工程判断**：环境贴图替代反射、贴图阴影替代阴影计算——**这条判断今天仍然成立**（SSAO、贴图化 GI、neural 近似都是同一条）。

## Key Contribution

1. **架构级解耦**：着色成本与几何复杂度脱钩（成本 ∝ 屏幕采样格）；
2. **微多边形**作为统一货币：把"图元"这个异构概念归一成"屏幕空间的小四边形"；
3. **线性时间 + 无上限模型 + 无裁剪**三件同时成立；
4. **随机采样统一处理**抗锯齿、运动模糊、景深（同一个 16 子像素机制，换抖动维度）；
5. **bucket z-buffer**：把"全屏深度缓冲"降级为"一块区域的深度缓冲"。

## Why It Works

- **成本挂到"输出"上而不是"输入"上**：输出分辨率有界，输入模型无界——挂错一边就完蛋；
- **自然坐标减少变换**：纹理在 uv 做、可见性在屏幕做，**没有一次"为了计算方便"的额外坐标变换**；
- **局部性换来流式**：图元一个接一个流过系统（bound→cull→split→dice→shade），内存只需容纳正在处理的图元 + 一个 bucket；
- **随机采样把三种"模糊"统一成一个机制**：抗锯齿（子像素）、运动模糊（时间）、景深（镜头）——**同一份抖动预算，三个维度**。

## Limitations

**原文自陈（第 6 节）**：

1. **着色先于采样 ⇒ 运动模糊不完全正确**：着色时还不知该采样点对应哪个时刻，所以材质/光照无法按时间求值；
2. **blob 一类图元难以转成微多边形**；
3. **bucket-sort 版本需要图元包围盒良好**，粒子系统难以包围；
4. **多边形没有天然的 dice 坐标系**（原文以双三次 patch 为主，很少用多边形）——**这一条在 1990s 的多边形时代成了真问题**。

**我从今天回看的四条**：

5. **遮挡不省着色**：被挡住的微多边形也已付过色。这是"结构性 overdraw"的原型——**今天的 early-Z 正是把这一步反转过来省掉的**；
6. **深度复杂度被"先着色"放大**：层数越多，浪费越大；半透明/CSG 时每采样点要存多个 hit 并排序，代价更高；
7. **没有 LOD 概念**：细分级别由屏幕尺寸自动决定，但**没有"这个物体该用几级资产"的上层控制**（那是 Clark 1976 / Nanite 的题目）；
8. **它是离线架构**：3 分钟/帧的目标是"一年一部片"，与 16.6 ms 无关。**把它当"实时架构的祖先"读是对的，当"实时方案"读是错的**。

## Game Development Relevance

- **它是"像素预算"的第一份法理**：先把"要着多少色"写死（半像素 ≈ 4 个/像素²的着色点密度），再谈几何——**与你把 overdraw 从"粒子数"改成"屏占比 × 层数"是同一件事**；
- **"先着色后可见"与"先可见后着色"是两套账**：

| | Reyes 1987 | 现代 GPU（early-Z / 延迟） |
|---|---|---|
| 次序 | shade → visibility | visibility → shade |
| 被遮挡的像素 | **付过着色钱** | 通常不付（early-Z 剔除） |
| 成本 ∝ | 屏幕面积 × 着色密度 | 可见像素 × 着色复杂度 + 几何 |
| 什么时候会退化 | 深度复杂度高（overdraw 严重） | 无法 early-Z 时（alpha test / 半透明 / 位移 / 计算着色写深度） |

**这张表能直接解释一件工程事实**：为什么"半透明 / alpha test / 遮罩材质"在 GPU 上特别贵——**它们把管线临时拉回了 Reyes 的次序**（先着色，再判可见/混合），于是 overdraw 重新变成真金白银；

- **变形/位移的代价**：Reyes 用位移贴图承载"模型复杂度"，代价是**必须在 dice 时才知道真实几何**——这与今天的虚拟几何/位移查询是同一个张力（本库 [[2026-10-15-DisplacementQueries — Geometric Queries on Tessellation-Free Displaced Surfaces|DisplacementQueries]] 是 2026 年的回答）。

## Unreal Engine Relevance

- **没有直接落点**（它是离线架构），但有三个"血统"上的落点：
  1. **Nanite 的 cluster 细分**在思想上等于 dice 的现代版：**按屏幕尺寸决定细分密度**，而不是按资产原始密度；
  2. **可变速率着色（VRS）** 是"半像素"这条规则的显式化：**着色率是可设的，采样率不是**；
  3. **Niagara 的粒子排序/半透明**痛点是"Reyes 次序"的残留：**混合必须按次序，次序必须付排序钱**（见 [[Overdraw]] 与 [[Everitt — Interactive Order-Independent Transparency (2001)]]）。

## Personal Knowledge State

**Normal（结论层）/ Easy（机制层）**。

- 机制层你早就熟：z-buffer、细分、抖动采样都是日常；
- 结论层要新拿的只有三条：① **半像素 = Nyquist**（着色率有下界，不是越少越好也不是越多越好）；② **shade-before-visibility 是 overdraw 的制度性来源**；③ **成本挂输出、不挂输入**。

## Learning Value

- **最高价值**：它给你的"像素预算"提供了**法理依据**——不是你拍脑袋定的 $k$，而是"采样密度 × 层数"这个结构决定的量；
- 次之：**"次序决定谁付钱"** 这条判据。同一份着色，先判可见就省钱、后判可见就费钱；**你的 alpha test / 半透明材质贵，不是材质贵，是次序贵**。
