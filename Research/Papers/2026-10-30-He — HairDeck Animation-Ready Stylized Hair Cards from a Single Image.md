# HairDeck —— 发型没有顺序

> `2610.40599`，27 页 23 图（含大量附录）。**一句话**：动漫/游戏角色的头发是由美术**一条一条摆出来的发片**组成的，这些发片**天然没有顺序**；而此前唯一的生成方法是把它们当成**一条长序列**逐点回归。**把"序列"换成"集合"这一件事，同时买到了 44% 的精度和 33× 的速度。**

## TL;DR

- **它的核心不是模型，是"单位"**：一条发片 = 一个 token $x=(p_1,d_1,z,s,e)\in\mathbb R^{40}$；整个发型 = **192 个无序槽位**；set diffusion transformer **不用位置编码** ⇒ 对槽位置换等变 ⇒ **"第几条发片"这个概念被彻底取消**；
- **两级"换单位"要分开算账**（这是全文最干净的一张消融）：把 CHARM 的"控制点序列"换成"一条发片一个 token"，CD 从 **0.0117 → 0.0078**；再把"逐条自回归"换成"集合一起去噪"，**0.0078 → 0.0066**，并且快 **6.8×**。**两级各管一半，谁也不是全部**；
- **33× 是这么来的**：CHARM 33.7 s → HairDeck **1.01 s**（CD 同时 −44%，朝向误差 40.0°→16.8°）。而"检索训练集里最像的一个发型"CD = 0.0119——**CHARM 的精度大约等于"回忆"**；
- **它还顺手把"能动的部分"也生成出来**：第二条 Chain DiT 生成**弹簧骨链**（48 槽 × 27 维），再用固定几何蒙皮绑上。朝向美术的骨链：recall **0.625** vs 检索 0.289，运动相关性 **0.702** vs 程序化规则 0.538；
- **最诚实的一处**：card VAE 的收益**在 CD 上几乎看不见**（0.0066 vs 0.0068），**真正的差别是"卡片是不是光滑"**——折角中位数 **14.2° vs 21.9°**（美术原版 14.1°）。**指标看不见的差别，恰好是唯一肉眼看得见的差别**。

## Problem

游戏/虚拟形象里的**风格化**头发不是发丝，是**发片（hair cards）**：几十到上百条由美术摆放的带状几何，**几何本身就是可见的头发**（不是现实毛发那种"用 alpha 贴图假装很多根"的扁片，而是菱形/三角形截面、宽度厚度沿长度变化的实体带）。它们靠**弹簧骨（spring bones）**驱动——从头骨挂下来的短骨链，末端每帧模拟，于是头发会晃、会落定（Unity 的 Dynamic Bone、VRChat 的 PhysBones、UE 的 Kawaii Physics、Godot 的同名节点都是这个东西）。

问题在于：**这条资产链上所有环节都是手工的**，而生成模型给不出这个形态。

| 现有路线 | 输出 | 为什么不能用 |
|---|---|---|
| 发丝生成（含风格化输入的） | 几万根曲线 | 游戏里跑不动，也不是美术要编辑的单位 |
| 发片抽取（strands → alpha cards） | 现实毛发的扁片 | 目标形态不同（那是"用贴图假装"的另一条路） |
| image-to-3D（TRELLIS / Hunyuan3D） | **一个融合的壳** | 没有卡片，**没有东西可以绑骨、可以动** |
| CHARM（唯一做风格化发片的） | 控制点**长序列** | 慢（33.7 s）、且把一个"集合"当成"序列"来生成 |

**所以真正的缺口不是"生成得像不像"，是"生成的东西是不是美术手里的那个单位"。**

## Historical Context

毛发这条线在库里已经有完整的六个节点（[[Hair Rendering]]）：经验侧 Kajiya-Kay 1989、物理侧 Marschner 2003、实时工程侧 Scheuermann 2004、多散射近似 Zinke-Yuksel 2008、能量守恒 d'Eon 2011、生产化 Chiang 2016。**但那条线全部是"怎么把一根头发着色正确"，本篇在另一条轴上：怎么把"美术手里的发片"这个单位生成出来。**

```text
着色轴（库内已闭合）
1989 Kajiya-Kay → 2003 Marschner → 2004 Scheuermann → 2008 Zinke-Yuksel → 2011 d'Eon → 2016 Chiang
                                                                                 ↓
                                                                        物理/工程/生产闭合
资产轴（本篇落点）
2016 之前：全手工（美术摆每一条卡片、绑每一条骨链）
2024 CHARM：第一条自动生成路线（控制点序列，自回归）
2026 ★ HairDeck：把"序列"换成"集合"，并附赠骨链      ← 本篇
```

**资产轴的判据和着色轴完全不同**：着色轴问"这个 BRDF 对不对"，资产轴问"**这个输出能不能直接进引擎、能不能被动画驱动**"。HairDeck 的摘要第一句就把这条判据写死了——"animation-ready"。

## Previous Work

- **风格化发片生成**：CHARM 是唯一前作，也是本篇的基准与数据集来源（VRoid 角色，36,440 个训练发型 / 100 个测试发型 / 76 个有完整模型的测试角色）。CHARM 的做法是把发型解码成**一长串控制点**；
- **发丝生成**：DiffLocks 等（本篇把它的发丝转成卡片作对照，失败率 17.5% in-the-wild，但**在真实照片上是唯一没崩的**——见 Limitation）；
- **image-to-3D**：TRELLIS.2 / Hunyuan3D-2.1 / MeshAnything V2 / DeepMesh / BPT——输出一个壳或一堆三角碎片，**没有卡片**；
- **集合式生成**：set diffusion / permutation-equivariant transformer 在点云、布局、多物体生成里已有，**但没有人把它用在"美术原语"上**。本篇的贡献之一就是把这条通用配方落到一个具体资产上，并证明它比自回归好。

## Core Idea

### 一、一条发片 = 一个 token，一个发型 = 192 个无序槽位

$$\text{card token } x=(p_1,\ d_1,\ z,\ s,\ e)\in\mathbb R^{40}$$

| 分量 | 维数 | 是什么 | 为什么必须有 |
|---|---|---|---|
| $p_1$ | 3 | 发根位置 | 位置 |
| $d_1$ | 3 | **发根法向**（卡片在根部的宽度方向） | 消融：去掉后朝向误差 **16.8°→26.4°** |
| $z$ | 32 | card VAE 的潜变量（整条卡片的形状） | 定长表示，替代"变长控制点" |
| $s$ | 1 | 截面类型（菱形 −1 / 三角 +1） | CHARM 只有菱形，本篇允许两种 |
| $e$ | 1 | **存在标志**（+1 有 / −1 空槽） | 让"一共几条"在去噪过程中自己定下来 |

**$e$ 这一维是全文最巧的一处**：序列模型必须先决定长度（或吐出终止符），而**集合模型可以让"有几个"和"每个长什么样"一起收敛**。消融很直接：去掉存在标志、改成"先预测张数"的头，生成出来**偏少**（62.8 vs 68.9 条，真值 67.4）。

### 二、card VAE：把变长折线压成定长，并且**沿弧长**解码

编码器是一个小 transformer：每个控制点带**弧长比例** $u_i=j/(n-1)$（外加 Fourier 特征），加一个 `[CLS]` 汇总 token，输出 $\mu,\log\sigma^2$ 得到 $z\in\mathbb R^{32}$。解码器**先预测点数 $n$（分类头）**，再在 $n$ 个**均匀弧长**位置上求值，用 adaLN-Zero 由 $z$ 调制。损失 = 世界单位下的位置/宽/厚平方误差 + $n$ 的交叉熵 + 很小的 KL。

> **"按索引解码"和"按弧长解码"是两种完全不同的东西**：索引解码（StrokeFusion 的做法）会让**采样点沿卡片疏密不均**，出来的是折线；弧长解码 + 世界单位损失，出来的是光滑卡片。见消融（Table 3）：索引解码 CD 0.0079、折角 **25.3°**；弧长解码 CD 0.0066、折角 **14.2°**。

### 三、set DiT：不用位置编码，就是不要顺序

- 192 个槽位一起去噪；**不加位置编码** ⇒ 对槽位置换等变 ⇒ **"第几条"从未被定义**；
- 每个 block：槽位间 self-attention + 对条件 token 的 cross-attention + MLP，全部由时间步与池化条件做 adaLN-Zero 调制；
- **flow matching**：$X_t=(1-t)X_0+t\epsilon$，回归速度 $v_\theta$；损失里**发根位置与存在标志权重 4，其余 1**（因为它们的量纲/重要性不同）；
- 条件可以是点云（CHARM 的基准输入，冻结 Dora-VAE 编码）或**单张图**（冻结 DINOv3 ViT-L/16 + SAM 3 抠头发/脸）；
- 采样 50 步 Euler + guidance 2；解码所有 $e>0$ 的槽位。

### 四、Chain DiT：把"能动的部分"也当成集合

第二条 set DiT，**48 个链槽 × 27 维**，条件是**已生成的卡片 token**；出来的是弹簧骨链，再用**固定几何蒙皮**把卡片绑上去。

**判据在这里很清楚**：骨链不是"每张卡一条"，而是**一组共享的链**（一个发型 48 条），所以它也天然是集合，不是序列。**同一条配方第二次奏效，是这套"原语 → token → 集合去噪"的方法论最强的证据。**

### 五、head frame：把"头的大小"从生成任务里拿掉

数据集的帧把每个角色缩到身高 1，于是**头的大小和位置各不相同**（耳朵算不算身高都会影响）。解法是做一次 $p\mapsto kp+b$ 的相似变换：把脸宽 $w$ 缩到训练集中位脸宽 $W$、把脸顶移到公共点 $O$，宽厚同比缩放；**输出时再用每个角色自己的 $k,b$ 变回去**。

消融：不加 head frame，CD（未对齐）从 0.0136 涨到 0.0189，重投影 IoU 从 0.829 掉到 0.798——**而"对齐后"的 CD 不变（0.0089）**。**这条很值得记：head frame 解决的是"摆在哪"，不是"长什么样"，所以它只在"未对齐"指标上显形。**

## Key Contribution

1. **把"发型 = 无序的原语集合"这件事显式化**，并给出可训练的集合扩散配方（无位置编码 + 存在标志 + 每原语一个 token）；
2. **证明"换单位"在这个任务上的两级分解**：tokenization 换单位（0.0117→0.0078）与生成方式换单位（0.0078→0.0066 + 6.8×）**各占一半**；
3. **同一条配方第二次奏效**（骨链也是集合），并给出"卡片 → 骨链 → 蒙皮"的完整可动资产链；
4. **一个可直接搬的归一化**：head frame（相似变换把脸宽/脸顶对齐）把"头的大小位置"从生成任务里删掉。

## Why It Works

1. **为什么集合比序列好**：自回归解码要求模型**自己维护一个数据里不存在的顺序**——它得记住"我刚才生成到哪儿了"，而这个顺序对最终发型毫无意义。**去掉顺序 = 去掉一层不必要的历史依赖**（这与 [[2026-10-30-Böttcher — Total Deformation-based MPM for Perfectly Elastic Solids|Böttcher 2026]] 的"别积分它，从当下重算"是同一个病的两种解法：**一个去掉历史依赖，一个去掉历史的必要性**）；
2. **为什么快 6.8×**：192 个槽位**一次前向全部更新**，而自回归要跑 60–70 次前向（每张卡一次），且**每次都要重新注意前面所有卡**；
3. **为什么存在标志有效**：它把"有多少张"从**离散的结构决策**变成**连续的去噪变量**，与形状共享同一套梯度；
4. **为什么 CD 看不出 VAE 的贡献而折角看得出**：CD 是**点到点距离的均值**，对"卡片在局部抖一下"不敏感；折角是**二阶量**，对光滑度敏感。**两个指标量的不是同一件事**。

## Limitations

1. **只学 VRoid 风格化发型**：超短发、以及现实毛发那种 **alpha-textured cards** 都在训练分布外；
2. **只出几何 + UV，不出贴图**（"generates the geometry and UV coordinates of the cards but no textures"）——**这不是一个小缺口，这是资产链的一半**；
3. **会把帽子和蝴蝶结当发片生成**（VRoid 里有些角色用发片建模头饰），作者的建议是"从训练数据里滤掉"；
4. **Chain DiT 只在 VRoid 常见的链布局上可靠**，对"从头顶放射出很多条链"这种不常见布局**会生成偏少**；
5. **"失败率"的定义是作者自定的**（卡片数少于真值 25%，或头皮裸露），**跨论文比较要小心**；
6. **所有计时不含建网格**，且 batch=1——**这是"到卡片"的时间，不是"到可用资产"的时间**。

## Game Development Relevance

**这是本周与本项目最直接相关的一篇**（`game_relevance: 5`），原因不是它多先进，而是**它生成的东西正好是产线上那个单位**：

- **发片是风格化角色头发的实际形态**，不是发丝、不是融合壳。所以它的输出**直接进资产管线**：卡片几何 + UV + **骨链** + 蒙皮，一步到位；
- **它把"绑骨"也自动化了**，而绑骨在真实产线上往往比建模更贵（一个角色几十条链，每条要调长度、刚度、阻尼）。**工序价值 > 造型价值**——造型错了美术改两笔，绑骨错了要重做一遍；
- **1.33 s/图 意味着它可以进"草稿阶段"**：策划/美术在概念图阶段就能拿到"能动的头发"看动效，而不是等原型；
- **它对"资产生成"的判据是可直接套用的**：**你生成的东西，是不是美术手里的那个单位？** 不是的话，再像也不能用（三个 image-to-3D 的失败率 13%–77% 就是这个判据的反面）。

## Unreal Engine Relevance

- **UE 5.8 已经内置了 groom → hair card 的转换**（原文引用了 *Hair card generator for grooms* 的官方文档），**这意味着"卡片"是 UE 官方承认的一等资产**，HairDeck 的输出形态与它对齐；
- **弹簧骨在 UE 的对应物**：Kawaii Physics（社区插件）或 UE 自带的 AnimDynamics / 骨链约束。**本篇输出的"链拓扑 + 每链刚度"可以直译成这几套系统的参数**，但**没有做这个映射**（论文里没有 UE 实验）——这是一个明确可做的后续；
- **最有价值的用法可能不是"生成"，是"重绑"**：Chain DiT 只读卡片 token，所以它能**给美术已经做好的、没绑骨的发片补一套骨链**（§4.6 "Rigging existing hairstyles"）。**这条对存量资产的价值远大于对新资产的价值**——它把"补绑骨"从几小时压到一秒；
- **不建议**把它当"最终资产"：无贴图、只 VRoid 分布、失败率 3.5% 仍在。**当"草稿 + 绑骨助手"用，风险最低**。

## Relationships

### Based On

- **set diffusion / permutation-equivariant transformer**：无位置编码 + 槽位级 attention，是本篇"取消顺序"的全部技术基础；
- **flow matching**：训练目标（直线路径速度回归）；
- **[[Hair Rendering]] 的资产侧脉络**：发片作为"可见几何"而非"alpha 贴图的载体"，这条分野在 [[Kajiya-Kay — Rendering Fur with Three Dimensional Textures (1989)|Kajiya-Kay 1989]] 就已经出现（texel ↔ 几何切换），本篇站"几何"这一侧。

### Extends

- **CHARM**：同一个数据集、同一个基准、同一个输出单位；**改的是"怎么生成"（序列→集合）与"生成什么"（+骨链）**；
- **[[2026-10-27-Kaushik — Hexels Compact Hexagonal Primitives for Scene Rendering|Hexels]] 的"原语容量"问题**：那篇问"一个原语能代表多少"，这篇问"**一个 token 能代表多少条发片**"——答案恰好都是"**一**"，并且都靠"原语本身的形状自由度"换效率。

### Related

- [[2026-09-17-HairCS — Reconstructing Strand-Based Hair from Hair Cards]] — **反向**：那篇把发片**升档**成发丝，这篇从图**降档**成发片。两篇合起来说明"发片 ↔ 发丝"是一条**双向**的档位阶梯（[[Scalability and Quality Tiers]] 里"可上可下"的样本）；
- [[2026-10-30-Liao — Walk on Multiscale Media Compiling Editable and Composable Transport Medium Prefabs|WoMM 2026]] — **同日的"换单位"另一半**：那篇把"介质"换成"带端口的预制件"，这篇把"发型"换成"卡片集合"。**共同点：新单位是"无序的、可组合的"，旧单位是"有顺序的、一次性的"**；
- [[2026-10-26-Zhang — RADIANT Object-Centric Feed-Forward Global Illumination|RADIANT]] — **"换单位 vs 调额度"的第二号证据**：RADIANT 换单位 +3.3 dB 而调 token 预算 ≤0.04 dB；本篇换单位 0.0117→0.0066 且快 33×，而"换更小的模型"只掉 0.0006。**两条独立证据指向同一句：先换单位，再调参数**；
- [[Motion Tokenization]] — **同一个动作在动画域的版本**：那边问"一条动作该切成几个 token"，这边问"一条发片该是几个 token"——**答案不同（动作要切、发片不切），但判据相同：切法要匹配下游的复用单位**；

## Learning Value

1. **"序列是模型编出来的"**：数据里没有顺序，模型却要维护顺序——**这是自回归在集合型资产上系统性吃亏的根因**，而且它有明确的量化后果（6.8× + CD 0.0078→0.0066）；
2. **"指标会看不见你唯一在乎的东西"**：CD 0.0066 vs 0.0068 几乎无差别，折角 14.2° vs 21.9° 是肉眼可见的差别。**这条与 [[2026-10-30-Liu — Texture Consolidation of Generated Multi-View Renderings|Texture Consolidation]] 的 SSIM 反转是同一类问题**：选指标时要问"它会不会奖励我的失效模式"；
3. **"归一化要归一化那个'不该由模型学'的量"**：head frame 把"头多大、在哪"删掉，代价为零、收益明确（未对齐 CD 0.0189→0.0136）。**任何生成任务都该先问一遍：哪些量是我可以先用一个变换消掉的？**

## Notes

**证据形态**：arXiv 预印本（v1，2026-10-29），27 页含大量附录（数据集统计、实现细节、失败案例 Fig 23）。项目页 `hyzcluster.github.io/HairDeck` 在摘要中出现；**代码未确认放出**（预印本未给仓库链接）。图 1/4/8 取自原文，原图为 3840 px 宽，已按 1/2 缩放到 1920 px 控制体积。

**三处必须跟着数字走的口径**：
1. **33× 是"到卡片"的时间**（"from the input to the cards, before meshing"，batch 1，A6000）——**不含建网格、不含贴图**；
2. **−44% CD 是相对 CHARM 在 CHARM 自己的测试集上**（100 个 VRoid 发型）；网图失败率 10% 是另一套 40 张的集合，**两个数不能混**；
3. **"检索基线 CD 0.0119"这个对照极强**（"CHARM is about as accurate as recalling a training hairstyle"）——引用时建议连这句话一起引，否则会显得在贬低前作。

**一处排版造成的误读风险**：Table 1 里"卡片级自回归"用的是**本篇自己的 token**（0.0078），不是 CHARM（0.0117）。**两级换单位的分解全靠这一行**——如果没有这一行，读者会把 33× 全部归给"集合"，而实际上 tokenization 已经先拿走了一半的 CD 收益、集合只多拿了 6.8× 的速度。

**未能核实**：CHARM 的原始论文（2024）不在库内，其"33.7 s / 40.0°"两个数**直接取自本篇的复现表**，未做独立验证。
