# Liu et al. — AnyGameRenderer: Entity-Consistent Generative Rendering Across Games (2026)

## TL;DR

**编码 agent 现在几分钟能做出一个能玩的游戏，但画面全是"程序员美术"：灰盒、彩色几何体、平的语义色块。这篇做的是给这些游戏"补一层渲染"。**

1. **任务**：输入一段粗糙 gameplay 视频（灰盒 / 彩色图元 / 语义图 / 线框都行）+ 一句风格描述，输出**同一段玩法**、**同一镜头**、**同样的实体位置与时序**，但画质达到成品级。**不需要 G-buffer、不需要类别标签、不需要 low-poly 代理**——只要"一段视频"；
2. **做法不新，数据与验收新**：LoRA（rank 128）微调 **MiniMax-H3 ref2va**（33B 参考视频条件生成模型），20 步 Euler 采样。真正的贡献是**三源配对数据（10,330 段 / 14.8 小时）**与**一套实体级评测**；
3. **核心机制是"对应关系契约"**：字幕不是随便写，而是按四条规则写成"**哪个色块 = 哪个实体，位置/尺寸/时序/人数严格保留**"。其中最有价值的一条是**故意保留噪声**——字幕里列出游戏里**所有可能出现**的角色（哪怕这一段根本没出现），逼模型学会"**从视频判断谁存在，而不是从文本**"；
4. **数字**：temporal match **50.9% → 62.9%**、position match 57.1% → 61.9%、漏渲染率 4.1% → 2.9%、幻觉率 52.1% → 46.0%；**漏掉的人数变化 34.7% → 21.3%**；
5. **但它是离线工具**：33B 骨干 + 20 步采样，1344×768 / 24 fps 输出，**没有任何实时性主张**。同一批人做的 [[2026-10-21-Zhang — Matrix-Game 4.0 Harnessing Video Models for Real-Time Playable Game Worlds|Matrix-Game 4.0]] 为了 83 FPS 付出了"必须吃 low-poly 代理 + 三阶段蒸馏"的代价；这篇反过来，**为了通用性放弃了速度**。

**一句话对读者**：这是"**生成式渲染层**"这条线上第一份**把"实体账"当主要指标**的工作——它衡量的不是"好不好看"，是"**该出现的是不是都出现了、该消失的是不是都消失了**"。

![[Research/Files/Pictures/Liu 2026 — 图1 粗模到成品的生成式渲染总览.png]]
**读图**：上半三块是"一个 checkpoint 能吃多少东西"——**跨品类**（塔防/自走棋/幸存者/回合制/卡丁车/人群跑酷）、**跨输入形态**（线框白模、粗模、2D 语义图、彩色椭球）、**一输入多风格**（同一段灰盒 → 写实/卡通/赛博/动漫）。下半是流水线与卖点：**agent 写代码 → 引擎出灰盒 → 本文渲染成成品**，于是"建模/贴图/动画"三步被跳过（$T_2<T_1$）。**看图重点**：输入那几格**真的只是色块**，没有任何几何细节——模型是从"位置 + 颜色 + 字幕"里把角色"想"出来的。（图 1，Liu et al. 2026）

## Problem

**"引擎管状态、模型管像素"这个分工已经成型了，但每一家都在用不同的中间表示。**

到 2026 年 10 月，这条线上已经有一排并发工作：CWM（12 类语义代理视频）、PWM（状态增强的 3D 有向框 + ControlNet）、[[2026-10-21-Zhang — Matrix-Game 4.0 Harnessing Video Models for Real-Time Playable Game Worlds|Matrix-Game 4.0]]（引擎 low-poly 代理 + 蒸馏因果 DiT）、StreamRender-H3（13 类语义图流式输入）、SolarRenderer（六种结构视频、四步、支持流式）。

**它们共同缺三样东西**：

1. **品类窄**：绝大多数只在第三人称、第一人称、驾驶这几类素材上演示——而这**恰恰不是 agent 生成的游戏的主要品类**。agent 做出来的是塔防、自走棋、俯视幸存者、回合制、卡丁车、人群跑酷；
2. **实体账对不上**：帧级指标（edge agreement、光流轨迹、成对人工打分）**看不出单个实体对不对**。十二个敌人死了三个应该剩九个——帧级指标对这个几乎无感；更糟的是**edge agreement 甚至会奖励"不渲染"**（灰块留着，边缘反而更"对"）；
3. **输入太贵**：要 G-buffer、要类别标签、要 low-poly 代理——这些东西 agent 生成的小游戏**根本产不出来**（GEAR 能导出多通道是特例，不是通例）。

本文的定位很清楚：**"我们不争论这个设定，我们做一个更能吃输入、更忠实保留的渲染层。"**

## Core Idea

三个性质，对应三个设计决定：

| 想要的性质 | 设计决定 | 代价 |
|---|---|---|
| **跨品类** | 用 GEAR 导出的 38 款 agent 游戏做多流渲染（每段五个对齐通道：成品 / 图元 / 粗模 / 12 类语义 / 深度） | 数据只能用"能导出多通道"的游戏 |
| **保住实体账** | 用 UE **脚本化制造零样本失败场景**（同色组人数变化、20–600 px 尺寸、四种机位），再用**字幕契约**把"谁是谁"写死 | 需要 per-clip 的"颜色→身份"映射 |
| **吃纯视频** | 一切输入都当"参考视频"，走 MiniMax-H3 的 ref2va 模式 | 丢掉了几何先验，只能靠数据补 |

**最有洞察力的一步是第三行与第二行的组合**：既然没有几何先验，那就**把"对应关系"从表示层搬到语言层**——用一段结构化字幕当"合同"。这条思路和 [[2026-10-19-InfiniDream — Open-Ended Photorealistic 3D Worlds Through Procedural Generation|InfiniDream]] 的"不要让 VLM 写代码，要让它改"是同一族：**把模型的自由度限制在一个"说得清"的接口上**。

## Technical Approach

### ① 模型与训练

- **底座**：MiniMax-H3 的 **ref2va**（reference-to-video+audio）模式，33B DiT，24 fps、最高 768p；
- **可训练参数**：所有 transformer block 上的 **LoRA，rank 128**，标准 flow-matching 目标，**骨干全冻**；
- **推理**：**20 步 Euler**（base + LoRA），无蒸馏、无缓存；
- **训练**：16 × H200（141 GB），全局 batch 16，**每步 129 秒**，3 个 epoch ≈ **48 小时**；bf16 + 梯度检查点 + block swapping + FlashAttention-3（每步快约 30%）；
- **部署技巧**：域内用 LoRA 系数 1.0；**域外纯文本风格（无锚图、风格没见过）用 0.7**——"回到零样本的画质，但保留对应关系的增益"。这是一条很实用的经验：**LoRA 强度是"保结构 vs 保画质"的旋钮**。

### ② 三源数据（10,330 段 / 14.8 小时 / 124 帧 @24fps / 1344×768）

| 来源 | 粗输入 | 段数 | 占比 | 作用 |
|---|---|---|---|---|
| **GEAR**（38 款 agent 游戏） | 图元通道 / 粗模通道 / 12 类语义通道 | 3,221 | 31% | **跨品类 + 跨输入形态** |
| **Unreal Engine**（双流渲染） | 灰盒 + 彩色角色块（主角恒蓝，其余六色） | 3,910 | 38% | **教实体账**（见下） |
| **真实录像** | 3D 框检测后渲染成实心框/线框/圆柱/椭球 | 3,199 | 31% | 真实镜头运动与场景分布 |

**UE 那一源是"照着失败模式造数据"的样板**——不是随便采，是**脚本化地制造零样本必错的场景**：

- **同色组的人数变化**：2–20 人的队伍走进/生成/走出/消失，密集簇、纵队、散开三种队形 → 专治"一群人被渲染成一坨"和"晚到/不来的实体"；
- **不同颜色角色进出** → 专治"进出时机错"；
- **实体像素尺寸 20–600 px**（含 boss 体量与朝镜头走来的）→ 专治"远处小怪融进背景"；
- **四种机位**：跟随 35% / 俯视 30% / 等距 20% / 侧视 15% → 防模型只会一种视角。

**这是"数据即测试"**：先写下模型会怎么错，再把每一种错做成一个可控变量。**这条方法论比模型本身更可迁移。**

### ③ 字幕契约（correspondence contract）——全文最值钱的部分

沿用底座模型的六段式格式，加了四条规则：

1. **主体是实体，粗形状是它的"表示"**：不是"这是一个蓝色圆柱"，而是"**`<Video 1>` 里每一个蓝色圆柱都是一个蒙面黑衣狼人**"；颜色→身份的映射**逐片段设定**，群体用类级描述并明确"它们存在"；
2. **retention 段把"什么必须跟输入走"写死**：位置、视觉尺寸、时序、**人头数**严格保留；**外观**交给提示词；
3. **空的地方要正面描述**："`<Video 1>` 里空的区域保持空；不添加任何在 `<Video 1>` 里没有对应图元的角色"；
4. **只用肯定句**：底座没有负向提示，而且**否定式描述倾向于生成它命名的东西**（作者原话："no HUD" 稳定地生成一个 HUD）。

**外加一条最反直觉的**：字幕**由引擎元数据程序化生成**，且**故意保留噪声**——每段字幕都列出这款游戏里**所有可能出现的角色**，哪怕这一段里一个都没有。目的是**逼模型学会"从视频判断谁存在，而不是从文本"**。效果是：模型几乎不会渲染"字幕里有、输入里没有"的角色。

> **这一条可以单独拿走用**：任何"条件生成"任务里，**条件里带上未被使用的候选**，会显著降低模型对条件的过度依赖。**噪声不是脏数据，是正则项。**

### ④ 评测：实体级，而不是帧级

**Benchmark**：59 个 held-out 案例 / **753 个标注实体**（UE 11 + 真实录像 14 + GEAR 6 款未见过的游戏 34），每例用训练外的片段、未见过的风格或角色，同 seed、同 20 步、同字幕。

**四个主指标**（都是"逐实体"平均）：

| 指标 | 定义 | 抓什么错 |
|---|---|---|
| **Temporal match** | 输入里该实体存在的帧集合 vs 输出里它被跟踪到的帧集合，IoU | 晚出现、消失后不回、身份互换 |
| **Position match** | $1-d/(0.5s)$，$d$ 为质心偏移、$s$ 为输入框尺寸 | 位置漂移 |
| **Unrendered rate** | 输出里"输入色块仍是平的色块"的实体帧占比 | 没渲染 |
| **Hallucination rate** | 跟踪到但匹配不上任何输入实体的帧占比 | 多渲染 |

**三个辅指标**：准点出现（$|\Delta_{on}|\le4$ 帧 ≈0.17 s）、从未出现率、**漏掉的人数变化率**（输入 6 帧内涨 ≥2 人算一次变化；输出 60 帧内是否跟上）。

**检测管线**：SAM3 开放词表分割（用字幕里的主体短语 + 通用 person/vehicle 词）→ 去阴影/反射 → 连成轨迹 → 匈牙利匹配（IoU ≥0.3 或质心偏移 ≤ 半个框）。

### ⑤ 结果

| 指标（59 例） | 零样本 | 本文 | **GT 天花板** |
|---|---|---|---|
| Temporal match ↑ | 50.9 | **62.9** | 80.9 |
| Position match ↑ | 57.1 | **61.9** | 79.3 |
| Unrendered ↓ | 4.1 | **2.9** | 0.1 |
| Hallucination ↓ | 52.1 | **46.0** | **34.1** |
| 准点出现 ↑ | 55.9 | **67.6** | 93.6 |
| 从未出现 ↓ | 26.0 | **20.2** | 0.7 |
| 漏人数变化 ↓ | 34.7 | **21.3** | 0.0 |

**分源看，故事完全不一样**：

- **UE 双流（训练分布内）**：temporal 80.2 → **96.6**，接近天花板 98.5，**零漏检**——**说明"教"是有效的**；
- **GEAR 多流**：47.6 → 60.7，漏人数变化几乎腰斩；
- **真实录像（域外）**：46.5 → **51.1**，几乎没动——**跨域仍然是墙**。

**"GT 天花板"这一列是全表最该看的东西**：把**真值视频**喂进同一套检测+匹配管线，temporal match 只有 80.9，**hallucination 高达 34.1**。也就是说：**这套度量本身有 ~34% 的假阳性**。所以 62.9 不是"78% 正确"，而是"**从 50.9 走到可测上限 80.9 的 38%**"。作者把这一列放出来，是这个领域少见的诚实。

## Key Contribution

1. **一个"纯视频输入"的通用游戏渲染层**：单 checkpoint 吃掉五类输入形态、跨九个品类，且**不需要任何引擎侧表示**；
2. **一个实体级 benchmark 与四个指标**：把"生成得像不像"变成"**每个实体在不在、在不在对的位置、在对的帧**"。这是本文最可能被后人继承的部分；
3. **字幕契约**：把"实体对应"从模型结构搬到语言接口，附带"程序化生成 + 故意噪声"这条可复用技巧；
4. **一份靶向数据配方**：UE 双流那一源的脚本化设计（人数变化 / 尺寸跨度 / 四机位），是可以直接照抄的"失败模式驱动采数"模板。

## Why It Works

**因为它把"实体账"从"模型要学会的事"改成了"数据里被显式制造出来的事"。**

- 零样本模型错在三处：留着色块不渲染、换掉机位、凭空加角色。这三件事**都不是"画得不好"，是"没在记账"**；
- 本文的对策不是加模块，是**在数据里把账本做厚**：同色组人数变化（教会数数）、20–600 px 尺寸跨度（教会别丢小的）、四机位（教会别换视角）；
- 再叠一层**字幕契约**，把"谁是谁"从像素层面提升到语言层面——模型不需要从颜色里"猜"身份，它被**告知**了；但它仍要从视频里**判断谁在场**（这就是"故意噪声"的训练目标）。

**换句话说：它没有让模型更聪明，它让任务的定义更清楚。**

## Limitations

1. **不是实时的，差得很远**：33B 骨干 + 20 步 Euler，无蒸馏、无 KV 缓存、无流式。对照 MG 4.0 的 83 FPS，本文的定位只能是**离线/后期**（做 preview、做风格探索、给 agent 生成的游戏做"美术升级"）；
2. **跨域是墙**：真实录像只从 46.5 涨到 51.1，几乎等于没涨。作者没有解释原因，但从数据构成看——**真实录像那一源的粗输入是"3D 框渲染成的几何体"，与游戏灰盒的视觉统计差别很大**；
3. **俯视最难**：分品类看，top-down 对两个模型都差。**这恰好是 agent 生成游戏最常见的机位**——最需要的地方最弱；
4. **幻觉率 46% 仍然很高**，而且**度量的天花板本身就是 34.1%**——意味着"幻觉"里有多少是真幻觉、有多少是检测器的误报，目前分不开；
5. **不是全自动**：需要 per-clip 的"颜色→身份"字幕。虽然可以程序化生成，但**仍然依赖"这段视频里有哪些角色"的先验知识**——纯黑盒输入（只给一段视频、不给任何元数据）时，这套方法退化成"猜"；
6. **固定分辨率与时长**：1344×768、124 帧（5.17 s）。长视频要靠分块接，接缝处的实体账没讨论。

## Game Development Relevance

**对三类人意义完全不同：**

### ① 做 agent 生成游戏 / vibe coding 的人

这是**目前最完整的一条"美术后处理"流水线**：代码 + 灰盒 → 成品画面。它的真正卖点不是画质，是**风格可切换**（改一句提示词，整款游戏换皮）与**免建模/贴图/动画**。**对原型与小体量产品，这直接砍掉了美术产能瓶颈**。

### ② 做传统管线的人（包括你）

**这套评测指标可以直接搬来当"生成式渲染层"的验收标准**。任何一层生成式渲染（DLSS 5 那一类、或者未来引擎内的生成式后处理），只要它**生成内容而不只是补细节**，就必须回答四个问题：

1. 该出现的实体**都出现了**吗？（unrendered rate）
2. 它们**在对的帧**出现/消失吗？（temporal match）
3. 它们**在对的位置**吗？（position match）
4. 有没有**凭空多出来**的？（hallucination rate）

**对你的技能特效工作，这四个问题可以逐字平移**：粒子数对不对、出现帧对不对、位置/挂点对不对、有没有多出来的拖尾/残影。**"看起来像火"是主观的，"粒子数在 3000 以内且第 12 帧出现"是可测的**——后者才是预算表该管的。

### ③ 做世界模型的人

本文与 MG 4.0 是**同一个月、同一个分工、两个相反取舍**的样本：MG 4.0 用 low-poly 代理换实时，本文用纯视频换通用。**这条轴（通用性 ↔ 实时性）在 2026 年底还没有第三个点**——谁能在"纯视频输入"上做到 30 FPS，谁就拿下这条线。

## Unreal Engine Relevance

- **UE 是它的数据源之一**：双流渲染（同一次仿真、同一机位，渲两遍：一遍灰盒+彩色角色块，一遍成品）。**这是一个可以立刻在自己项目里复现的采数方法**——UE 的 Custom Depth / Stencil 或后处理材质就能出"色块版"，不需要改渲染管线；
- **不是运行时方案**：没有 UE 插件形态，也不可能在 16 ms 内跑 20 步 33B；
- **可借鉴的形态**：如果把 LoRA 系数 0.7 那条经验搬过来——**"保结构 vs 保画质"的强度旋钮**在 UE 里对应的是后处理强度（比如 DLSS 5 的生成强度），而本文给的是一条可量化的调法：**结构指标（temporal/position）随强度下降得很慢，画质上升得快**。

## Learning Value

- **"验收标准"比"方法"更长寿**：这篇的方法明年可能被更强的底座取代，但**那四个指标会留下来**。看论文时优先记"它怎么定义对错"，而不是"它用了什么模块"；
- **"噪声是正则项"这条可以直接用**：任何条件生成，**条件里带上未被使用的候选**，都会降低模型对条件的过度依赖。这条在材质生成、动作生成、甚至 prompt 工程里都成立；
- **"GT 天花板"这个习惯值得学**：报告指标时**同时报告度量本身的极限**，是区分"工程报告"与"营销材料"的一条硬线。**你写性能预算报告时同理**：给出"这个指标最好能到多少"，比给出"我们到了多少"更有说服力。
