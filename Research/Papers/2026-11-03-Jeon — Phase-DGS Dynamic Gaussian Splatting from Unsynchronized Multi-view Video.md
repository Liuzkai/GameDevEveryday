# Phase-DGS: Phase-guided Dynamic Gaussian Splatting from Unsynchronized Multi-view Video（ETRI × Seoul National University, 2026）

## TL;DR

**不同步的相机之间，共同变量不是"此刻几点"，是"动作进行到哪了"。**

Phase-DGS 把 4DGS 的时间戳 $t$ 整个换成**语义相位** $p\in[0,1]$——它从单帧图像里无监督学出来，表示"这一帧处于运动周期的哪个状态"。同一状态在不同相机、不同时刻拍的帧共享同一个 $p$，于是"同步"这个前提被删掉了，而不是被修补。

在严重不同步（随机时间偏移 + 10% 丢帧 + 5–10 帧冻结）下比 FreeTimeGS 基线高 **+5.3 ~ 6.5 dB**，作者报的最高场景增益 **+8.5 dB**；代价是训练 **+30% 显存、2.1× 慢**，**推理开销不变**。

## Problem

动态高斯泼溅（DGS）的时空重建**在定义上要求所有相机逐帧同刻**。真实拍摄里这个假设经常破，而且破的方式不止一种：

| 破坏方式 | 现象 | 为什么难 |
|---|---|---|
| 时间偏移（shifted） | 各机起始帧差 20–30 帧 | 每台机器的偏移量还可能是时变的（漂移） |
| 丢帧（dropped） | 单机丢 10% 帧 | 偏移不再是常量，是**逐帧缺失** |
| 冻结（freeze） | 单机卡住 5–10 帧 | 同一个时间戳对应多帧同一画面 |

后果是 floaters、ghosting、几何塌陷。**注意这三种破坏有一个共同点：它们破坏的是"时刻"，不是"状态"。**

## Historical Context

4DGS 的整个形式都把时间当自变量：$G(\mathbf{x},t)$，形变场吃 $t$。于是"不同步"天然被表述成"$t$ 不准"，解法自然分成两族：

1. **把 $t$ 修准**：硬件 genlock / PTP / 音频对齐 / 视觉特征匹配 / Sync-NeRF 联合优化每相机一个时间偏移。
2. **不要 $t$**：本文。

第 1 族的共同上限：**它们都假设"存在一个正确的 $t$"**。而丢帧/冻结的情形下，正确的 $t$ **根本不存在**——某台相机就是没有那一帧。Sync-NeRF 每相机只估**一个**偏移，遇到逐帧缺失直接失效。

**这是"估参数"和"换变量"的分界**：前者在旧坐标系里找最优点，后者换坐标系让问题消失。

## Previous Work

作者的表列得很清楚，值得整段保留（这张表本身就是一篇"同步方案综述"）：

- **硬件**：Genlock / Timecode / SMPTE——精度最高，但要专用硬件与布线，且信号漂移引入的误差**事后无法校正**；
- **协议**：PTP / NTP——便宜，但吃网络，丢包即漂；
- **音频对齐**：依赖受控声学环境，大场景里声速延迟不可忽略；
- **几何/特征匹配**（VisualSync）：弱纹理、大视角差、遮挡下退化；
- **姿态跟踪**（PoseSync）：要求画面里有人；
- **重建耦合学习**（Sync-NeRF）：联合优化偏移与辐射场，但每相机单偏移、要求帧连续、**需要位姿**——而不同步录制里位姿估计本身就是难题。

## Core Idea

### 相位是什么

$$p_i^f=\mathrm{MLP}\Big(\tfrac{1}{HW}\sum_{n}\big[\mathrm{ViT}(u_i^f)\big]_n\Big)$$

对第 $i$ 台相机第 $f$ 帧：裁到运动密集的 ROI → DINOv2 ViT 编码 → **对 patch token 做空间平均**得到全局特征 $z_i^f$ → 三层 MLP → sigmoid 到 $[0,1]$。

**一个标量，替代一个时间戳。** 这一步之所以能成立，靠的是三个性质：

1. **状态可比**：同一运动状态在不同视角下语义一致（"完全坐下"就是"完全坐下"）；
2. **一维同型**：$p$ 与 $t$ 都是标量、都沿时间单调 ⇒ **可以原地替换，不动 backbone**；
3. **不含绝对时间**：它只给序，不给原点。

### 怎么让它不塌

单靠"渲染损失"学不出相位——**退化解太容易**：把所有帧的相位都输出成同一个常数，特征库一致性损失完全满意，渲染则退化成"一个静态场景"。两个损失专门堵这个洞：

**相位一致性损失**（拉齐跨相机）：用当前相位 $p_i^f$ 去可学习的特征库 $\mathcal{B}_i\in\mathbb{R}^{(Fk)\times d}$ 里做注意力检索（$w=\mathrm{softmax}(-|P_i-p_i^f|)$），要求检索回来的特征等于当前特征：

$$\mathcal{L}_{\text{phase}}=\big\|z_i^f-\textstyle\sum w\,\mathcal{B}_i\big\|^2$$

**单调损失**（定住方向）：

$$\mathcal{L}_{\text{mono}}=\sum_i\sum_f \mathrm{relu}\big(-\Delta_i^f+\tfrac{1}{Fk}\big),\qquad \Delta_i^f=P_i^{f+1}-P_i^f$$

**这一条是全篇最承重的一行**：消融里去掉它，Jumping 场景 **−4.97 dB**、Bike **−5.31 dB**，而且作者说训练直接崩。它就是那个"锚"——没有它，$p$ 有整体重参数化的自由度，优化会漂到一个无意义的解。

### 怎么接进 DGS

$$G(p_i^f)\ \leftarrow\ G(t)$$

因为 $p$ 是标量、沿时间单调，**接口同型**，所以能即插即用：论文在 FreeTimeGS（显式运动表示）与 RealTime-4DGS（隐式运动表示）两个 backbone 上都验证过。**不需要改 backbone，不需要位姿，不需要时间戳校正。**

## Technical Approach

```text
多视角视频（各机独立，可能偏移/丢帧/冻结）
   ↓ 每帧 ROI 裁剪 → DINOv2（冻结）→ patch 空间平均
全局特征 z_i^f
   ↓ 3 层 MLP（d→256→128→64→1）+ sigmoid
相位 p_i^f ∈ [0,1]
   ↓ 替换 4DGS 形变场的输入 t
4DGS（FreeTimeGS / RealTime-4DGS）
   ↑ 渲染损失 + 相位一致性（特征库检索）+ 单调损失
```

- **特征库可学习是关键**：初始化后冻结会掉 4.59 dB。DINOv2 特征是逐图独立的、不含时间信息，**时间信息只能由这个库承载**；
- **上采样因子 $k$** 处理不同帧率/交错时间戳，$k=2$ 最优（$k=1$ 抓不到亚帧不同步，$k=4$ 在固定预算下反而收敛不好）；
- **ViT 尺寸影响很小**（S/B/L 差 <0.6 dB）：**相位捕捉的是"运动整体进程"，不是细节**——这是个有信息量的负结果；
- **ROI 裁剪影响 <0.2 dB**：整图也能跑，只在物体占比很小时明显。

## Key Contribution

1. **把"同步"从前提变成不需要的东西**：不是估偏移，是换变量。
2. **无监督的语义相位**：不需要任何相位标注，靠渲染 + 一致性 + 单调三条损失联合学出来。
3. **即插即用**：一维标量接口，换 backbone 不改代码结构。
4. **在丢帧/冻结这类"没有正确时间戳"的情形下也能work**——这是第 1 族方法原理上做不到的。

## Why It Works

**它把"时刻"投影到了"状态"，而投影掉的恰好是那个不可靠的维度。**

三层拆：

1. **共同变量的维度可以更低**。同步问题在"时间"这个一维连续量上无解（因为有的相机根本没有那一帧）；但"运动状态"这个量在**所有**帧上都良定义——包括冻结帧（它就是同一个状态重复了 10 次）。**换一个更低维、且处处有定义的变量，问题从"病态"变成"良态"。**
2. **一维 + 单调 = 可以原地替换**。这是它能"即插即用"的全部技术原因。**如果相位是二维的（比如同时编码"动作相位 + 呼吸相位"），就接不进 $t$ 的位置**——换变量要考虑"新变量能不能塞进旧接口"。
3. **单调损失是在做规范固定**。$p$ 与 $\phi(p)$（任意单调变换）在"状态一致性"意义下等价——这是一个**规范自由度**。不加单调约束，优化可以漂到任意单调重参数化上；加了之后，"相位值"才与"时间顺序"对齐。**消融里 −5 dB 的差距，就是这个自由度的代价。**

## Limitations

- **周期性运动会崩**。Balloon1 场景（人反复上下移动气球）里，时间上相距很远的帧视觉几乎相同 ⇒ 相位投影器给它们相似相位 ⇒ 监督歧义、重建失败。**根因是"状态"这个变量在周期运动上不是单射**——一个周期内同一状态出现多次。这是结构性边界，不是调参能解决的。作者的缓解方向（引入帧间因果、跨相机信息）本质上是**给相位补一个"第几个周期"的维度**——那就不是一维了。
- **相位是相对量**。它只给序不给原点；全局相位戳要靠"所有相机相位的平均"或"单参考相机"，**原点仍然是外部给的**。
- **依赖 backbone**。RealTime-4DGS 约 60k 迭代后过拟合、测试 PSNR 骤降且相位一致性变差；FreeTimeGS 能稳到 500k。**"相位监督"没有让 backbone 更稳，只是让它在不同步下不那么崩。**
- **评测协议有循环**。相位参考要用"各视角帧索引 ↔ 源视频索引"的对应关系——**这个对应关系只有模拟数据才有**，真实拍摄里拿不到。测试时还要在 $\tilde p\pm0.05$ 内搜最高 PSNR（虽然 $W=0$ 的对照表明 4.8–7.0 dB 的增益不是搜出来的）。
- **训练成本**：500k 迭代 / 2.5 h / 场景（RTX 5090），**这是离线资产管线**。

## Game Development Relevance

**相关性中等，但方向明确：它打的是"捕获"这一端，不是"渲染"这一端。**

- **动捕棚 / 体积捕获**：不用 genlock 就能多机位重建，**降低了"多机位"的门槛**——小团队租几台机器手持拍也能出 4D 资产；
- **参考素材重建**：把演员表演的多机位参考视频重建成可自由视角的东西，供美术比对（比 photogrammetry 多了时间维）；
- **虚拟制片里的自由视角回放**：现有多机位回放要么固定机位、要么要求硬件同步。

**对游戏生产的现实距离**：2.5 h / 场景 + 需要多机位 + 需要位姿 ⇒ **目前是"做一次资产"的工具，不是"每帧跑"的技术**。它的价值在于**降低了输入门槛**，而不是提高了输出上限。

## Unreal Engine Relevance

**基本没有运行时映射，不强行对应。** 唯一相关的位置是离线：如果 UE 侧要做"多机位参考 → 自由视角回放"，这套东西在 DCC / 离线工具链里，对应的是 Movie Render Queue 之外的第三方重建管线。**不要试图把它塞进 Niagara 或材质系统，它不是那类东西。**

## Technology Evolution

**4DGS 的"时间轴"这条线，到今天出现了第三种立场：**

```text
2023-24  时间戳是输入，同步是前提            （原始 4DGS / Dynamic 3DGS）
   ↓
2024    时间戳不准 → 估一个偏移             （Sync-NeRF：每相机一个标量）
   ↓
2025    偏移不是常量 → 逐帧/逐相机可变形的时间编码
   ↓
2026    不要时间戳 → 换成"运动状态"          （Phase-DGS：相位是状态量，不是时刻）
```

**这条线和 [[Wave Function Collapse]] 的"相位"是同一个词的两个用法，值得对照**（见 [[2026-11-05]]）：WFC 里的 phase 是"沿空间某方向必须一致的那个偏移量"（砖缝在一行里的位置），Phase-DGS 里的 phase 是"沿时间必须一致的那个状态量"。**两者都是"被携带的量"——它不能局部决定，必须由一个共同的参照系给出来。**

## Learning Value

**可迁移的判据**：

> 当**对齐用的那个量本身不可靠**时，先别修它——问一句"我要的到底是这个量，还是它背后的某个状态？"如果答案是后者，就去换变量；换完记得补两样东西：**一个方向（单调性）**和**一个原点（外部给）**。

这条判据在别处也成立：动画同步（用姿态而非时间码对齐）、音频对齐（用节拍而非采样点）、分布式仿真（用逻辑帧而非墙钟）、甚至版本管理（用内容哈希而非时间戳）。
