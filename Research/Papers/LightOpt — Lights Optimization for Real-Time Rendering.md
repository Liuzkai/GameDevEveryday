# LightOpt: Lights Optimization for Real-time Rendering

> **2026-11-15 重写。** 本页此前只有"官方描述层面"的内容（摘要 + 项目定位，无方法细节）。**读者于 11-14 在另一设备产出了本篇的完整中文全译（21 页，`Research/Files/PDF/LightOpt-中文全译.pdf`，CC BY 4.0 非官方译本，插图沿用原作）**，本页据此重写为内容级笔记，并补齐作者原版 PDF（`Research/Files/PDF/LightOpt 2026.pdf`，10 页，34.7 MB）。**原文与译本冲突时以原文 PDF 为准**；本页所有数字均来自原文表格与图注。

## TL;DR

**把"灯架"当成一个可以整体求解的资产，而不是美术一帧一帧摆出来的结果。**

- **目标不是画面，是辐照度场**：在场景表面撒点，先算原灯架在这些点上的辐照度 $E(x)$，然后**只要求新灯架在同样这些点上复现它**。目标是**视角无关**的——所以一份解可以给所有相机、所有平台用。
- **两个新损失**：**重叠损失**（一个采样点被超过 $n_{\max}$ 盏灯照到就罚，权重 ∝ $1/E_i$ ⇒ 优先删弱灯）与**吸引损失**（把附近灯拉向欠照点，或扩大其作用范围）。
- **优化过程中动态增删并灯**：删（重要性 $\gamma_i<\varepsilon_i$）、并（两灯照亮点集的 Chamfer 距离最近的一对）、增（欠照点 DBSCAN 聚类后补一盏）。
- **实测（五个真实游戏场景，Unity + Tiled-Z 延迟）**：活跃灯 **−20%~−53%**，光照开销 **−18%~−52%**，去延迟着色阶段加速 **1.37–2.07×**；同灯数下保真度**优于美术手工精简**。

> **本篇真正的锋利之处不是"少灯"，是"换了一个计量对象"**：业界按**每视口灯数**做预算（截到 32 盏），原文表 2 显示**灯数砍掉 74%，逐像素重叠只降 23%**；而按**重叠数**优化，灯数只降 53%，重叠却降了 56%。**"限灯数"和"降重叠"根本不是同一个旋钮。**

## Problem

现代游戏场景动辄几百盏灯，视觉密集处**单点被 10–50 盏灯同时覆盖**。逐像素的光照开销随"该像素要算几盏灯"增长，而且不止是 BRDF 求值：**光影响的空间差异会造成像素级执行分歧（divergence）、破坏缓存局部性**——这两项在低端 GPU 上比算术本身更贵。

三条已有的路都不解决"灯本身太多了"：

1. **剔除**（tiled 2009 / clustered 2012 / Tiled-Z 2017）：把屏幕切成 tile/cluster，每块维护一张灯表——**表本身不变短**。
2. **采样**（ReSTIR 2020 / MegaLights 2025）：每像素随机抽几盏 + 时域复用——**灯集合不变**，且有常数开销与拖影。
3. **手动精简**：美术为低端机另做一套灯——**两套配置要长期同步维护**，而且原文实测它比自动优化**又慢又差**（表 2：山谷手工版 83 盏 / RMSE 0.073，本方法 57 盏 / RMSE 0.046）。

**跨平台把这个问题放大成流程问题**：高端机一套多灯配置、低端机一套少灯配置，"既费人力也难长期维护"。所以真正的需求不是"渲染得更快"，而是——**能不能只维护一套灯，让它自己适配所有平台？**

**这条线有一个稳定的形状：每往前走一步，"可解的变量"就多一组，而"必须固定的东西"换一批。**

| | 可解 | 必须固定 | 目标 | 时间尺度 |
|---|---|---|---|---|
| 1993 | 强度（颜色） | 位置、方向、个数、几何 | 用户画的图 | 分钟（线性求解） |

> **这张表最该看的一列是"必须固定"**：1993 固定了"灯在哪"，所以问题变成线性的；2026 固定了"相机与材质"——**不是因为它们不重要，而是因为固定它们之后，解就可以跨相机复用**。这是本库 11-14 那条判据（"代理的合法性由冻结了哪些轴定义"）在**优化问题**上的同构版本：**解的可复用性，由你冻结了哪些输入决定。**

## Core Idea

### 一、为什么目标是辐照度，不是像素

渲染方程里 BRDF 在半球积分**内部**，直接对"最终像素"求导既贵又不稳。本篇退一步：**用表面辐照度场当外观的代理**。

$$E(x)=\int_{\Omega^+}L_i(x,\omega)\,(n\cdot\omega)\,d\omega \;=\; \sum_{i\in L} E_i(x)$$

三个后果（前两个是原文写的，第三个是我的推论，标出来）：

1. **可微**：$E(x)$ 对灯参数（位置、强度、颜色、方向、半径、锥角）都有解析或半解析梯度；
2. **只算直接光**：多次反弹的 GI 通常已预烘焙，所以不必进优化环；
3. **【推论】解与相机无关** ⇒ 一份灯架可以服务所有视角与所有平台。**这正是"跨平台只维护一套灯"的技术根据**——不是因为优化器聪明，是因为**目标里根本没有相机**。

### 二、软支撑：为什么要先把半径乘 2

灯有一个**作用半径** $r_i$：超出即无贡献。这个"有/无"在数学上是**阶跃**——灯一移动跨过边界，$E_i(x)$ 从 0 跳到非 0，**梯度要么是 0 要么是无穷**。

原文的办法：**优化时把每盏灯的作用半径扩大到 2 倍**，再配一个随距离平滑衰减的几何惩罚项。于是：

- 采样点集合 $S_{\text{all}}$ 里**既有被照亮的点（橙）也有没被照亮的点（蓝）**；
- 灯"走出"原范围时，惩罚项连续变大而不是突然消失——**梯度始终存在**；
- 顺带解决了"暗处必须保持黑"这个约束：不只匹配亮处，**也匹配暗处**。

![[Research/Files/Pictures/Chen 2026 — 图3 作用半径扩到两倍保证可微.png]]
**读图**：橙色虚线 = 灯的实际作用半径，蓝色虚线 = 优化时用的 2 倍半径；蓝点是 2 倍半径内的采样点（含原本不亮的），橙点是原本亮的。**多出来的那一圈蓝点就是"梯度存在的空间"**。（图 3，Chen et al. 2026）

> **这条工程手法比它的名字重要**：**引擎里每一个"影响半径"都是硬截断（性能语法），而优化需要一个软场（数学语法）。** 同一个参数，两种用法，必须显式区分——这与 11-12 DTM 那篇"$\alpha$ 是覆盖率、在纱线边缘不连续、所以光滑网络必然振铃"是同一类问题的两次出现。

### 三、两个损失：一个推、一个拉

| | 重叠损失（overlap） | 吸引损失（attraction） |
|---|---|---|
| 罚什么 | 一个采样点被 **超过 $n_{\max}$ 盏灯**覆盖（缩放函数在 $|L_x|>n_{\max}$ 后开始罚） | 欠照点（$E<\varepsilon_u$，默认 **0.1**）到**最近候选灯边界**的距离 |
| 采样点集 | 多灯共同覆盖处 | 所有灯边界之外的地方 |
| 权重 | 软权重 ∝ $1/E_i(x)$（$\beta_w$ 控制陡峭度）⇒ **先删弱灯、留主灯** | 候选灯需满足"在表面正面"且足够近；搜索半径由灯自身有效半径定 ⇒ **小灯扩得更积极** |
| 作用 | 削掉冗余覆盖 | 把灯**拉过去**或**撑开**去补暗区 |

两个损失**都罚"到灯边界的距离"**，但采样点集不同——所以一个把灯推离密集区，一个把灯拉向空缺。**这是全篇最像"设计"而不是"推导"的地方**：同一把尺子，量两个方向。

![[Research/Files/Pictures/Chen 2026 — 图5 重叠损失权重a_o的质量-效率权衡.png]]
**读图**：四列自左至右 $a_o$ = 0 / 0.001 / 0.1 / 5（图注）；上排渲染、中排误差、下排重叠热图。**读数：ALO 4.34 → 3.81 → 3.33 → 2.42，RMSE 0.0232 → 0.0286 → 0.0367 → 0.0552，着色 0.87 → 0.67 → 0.60 → 0.54 ms。** 这是一条**干净的兑换率曲线**——**本篇的"档位"其实就藏在这四个数里**。（图 5，Chen et al. 2026）

![[Research/Files/Pictures/Chen 2026 — 图6 吸引体积v的消融.png]]
**读图**：自左至右为输入、$v=0$、$v=15$、$v=100$。**橙框是关键**：关掉吸引（$v=0$）后，新加的灯会被重叠损失推离高重叠区，导致**局部欠照**；$v$ 过大（100）则把光摊到本该黑的地方、丢掉细节。（图 6，Chen et al. 2026）

### 四、离散操作：删、并、增

连续优化只能挪灯，挪不掉"多出来的一盏"。三个离散动作让**灯数本身**成为变量：

| 动作 | 判据 | 细节 |
|---|---|---|
| **删** | 重要性 $\gamma_i$ = 该灯对全场景辐照度的总贡献；$\gamma_i<\varepsilon_i$（默认 **4**）即删 | 先删再优化，避免弱灯占着位置 |
| **并** | 两灯照亮点集的 **Chamfer 距离** + 相对重要性 ⇒ 合并代价；只取**最低的 10%** 候选对 | 合并须同时满足：新灯**降低重叠损失** + **>80% 采样点正面朝向**新灯；颜色/位置/衰减参数按重要性加权平均初始化；所需锥角 > **130°**（$A_{\text{point}}$）则改点光源 |
| **增** | 欠照点用 **DBSCAN** 按欧氏距离聚类；簇的累计重要性 > $\varepsilon_i$ 就补一盏 | 新灯用簇内平均目标辐照度/法线初始化，位置沿平均法线搜索使簇内差异最小 |

> **"合并"这一条最值得抄**：它把"两盏灯能不能并"拆成**三个独立的检查**——几何上像不像（Chamfer）、并了会不会更省（重叠损失降）、并完还照不照得到（80% 正面）。**三个条件缺一不可，而它们各自都可能单独通过。** 这正是工程上"合并资产"这类操作的通用形状。

### 五、昼夜时变（ToD）：把时间当第四个轴，但只在关键帧上积分

生产里的 ToD 灯是**一组稀疏关键帧 + 段间线性插值**。本篇直接**取所有灯关键帧的并集** $T$，在 $T$ 上做**非等距梯形积分**（权重和归一化为 1）：

$$\min \sum_{k} w_k \sum_{x\in S_{\text{all}}} \Delta s\,\big\|\hat E(x,t_k)-E(x,t_k)\big\|^2$$

**这一步没有新数学，但它决定方法能不能进生产**：不做 ToD，就只能优化"正午"的灯；做了 ToD，一套灯架才对应"一整天的广场"（原文广场场景 314 盏 → 249 盏）。

## Technical Approach（光模型与离散化，两段）

- **光模型**：点光 + 聚光，采用 Unity 的光照模型（最早见于 Frostbite，Lagarde & De Rousiers 2014）：$E_i(x)=V_i(x)\,D_i(x)\,A_i(\omega)\,c_i I_i$，距离衰减 $D_i$ 带平滑参数 $a_i$ 与半径 $r_i$，角衰减 $A_i$ 用内外锥角 $\theta^o_i,\theta^i_i$；**可见性 $V_i\equiv 1$**（原文：实际管线里只有少数灯投影，故不建模）。
- **离散化**：表面泊松盘采样（Yuksel 2015），采样半径 $r_0=0.25$，每点代表面积 $\Delta s=\pi r_0^2$；把每盏灯半径 ×2 收集采样点得 $S_{\text{all}}$；**只算直接光**（GI 预烘焙）。

## Key Contribution

1. **第一次把"灯架整体"做成实时游戏场景里的可微优化对象**：位置、强度、颜色、方向、**个数**同时是变量。
2. **两个面向"覆盖结构"的损失**：重叠（推）与吸引（拉）——**它们优化的不是亮度误差，是覆盖的几何**。
3. **动态离散重组**：删/并/增三件套，使灯数可增减，而不是只能调参。
4. **视角无关的目标 ⇒ 一套灯架跨平台**：这是它对**流程**的贡献，比对帧率的贡献大。
5. **ToD 扩展**：把时间轴以关键帧积分的方式纳入同一目标。

| 无吸引损失 | 0.066 / 0.106 | 0.074 / 0.089 | 0.098 / 0.110 | 0.078 / 0.103 | 0.080 / 0.087 |
| 无补灯 | 0.053 / 0.089 | 0.067 / 0.082 | 0.096 / 0.109 | 0.039 / 0.055 | 0.066 / 0.073 |
| **两者都有** | **0.045 / 0.068** | **0.041 / 0.061** | **0.043 / 0.053** | **0.037 / 0.049** | **0.033 / 0.034** |

**读法**：**缺一个就掉一档，两个一起缺才掉得狠**——"吸引"与"补灯"是**互补而非冗余**：附近有灯可挪时吸引够用；附近没灯时，**必须新增一盏，多一个自由度**。原文这句话是整篇最实用的一句诊断：

> **"如果附近没有合适的光源，就必须通过新加光源引入新的自由度。"**

**动态重组本身值多少**（图 7）：关掉删/并/增，重叠水平看着差不多，**实际欠照明显**——**因为重叠是一个"数得出来"的量，而欠照是"看得出来"的量；只压前者会买到后者。**

## Limitations（六处冷水）

1. **目标里没有镜面。** 辐照度是余弦加权积分，**镜面高光与视角相关项完全不在目标内**（原文自述）。高光泽材质或照明剧变处会有可察觉偏差。**这既是它的效率来源，也是它的天花板**——而"很多小灯打在高光上"恰好是灯数最贵的场景之一。
2. **可见性恒为 1。** 阴影灯不建模（理由是性能上"只有少数灯投影"）。**于是"这盏灯的阴影能不能删"这类问题它答不了**——而这在游戏里恰恰是灯成本的大头之一。**21 年前的 [[Walter 2005 — Lightcuts A Scalable Approach to Illumination|Lightcuts]] 也把可见性界取成 1**，同一个洞，两代人绕着走。
3. **ALO 不是成本，只是成本的代理。** ALO 是**每像素平均重叠数**，而分块/分簇管线的真实成本更接近**每 tile 的最大列表长度**与**像素覆盖率**的乘积。**ALO 下降 ⇒ 成本下降这个推断，在"重叠分布很不均"的场景里会失真**（一像素 30 盏、其余 0 盏，均值仍很低）。
4. **离散操作不可微。** 删/并/增是启发式 + 阈值，**不是梯度**。所以结果对 $\varepsilon_i$、$n_{\max}$、$a_o$ 这几个超参有依赖（图 5/6/8 三张消融就是在展示这种依赖），**没有"最优"的承诺**。
5. **成本口径含糊。** 原文只说"约 10 min/场景""数个批次"（16 km × 16 km 开放世界按空间分区）。**没有报总墙钟、没有报单批次方差**，也没有报失败率（多少个场景调不出可接受结果）。
6. **困难场景明确**：**植被、薄片几何、强重叠区**都会残留欠照（图 11）。原因不难猜：泊松盘采样在薄片/叶片上取不到稳定法线，辐照度场描述不了"针叶透光"这类效果。

![[Research/Files/Pictures/Chen 2026 — 图11 植被与强重叠的困难情形.png]]
**读图**：左输入、右优化后，右上角是逐像素重叠。**植被区明显欠照**——不是参数没调好，是"表面辐照度"这个表示在薄片几何上本身不够用。（图 11，Chen et al. 2026）

## Game Development Relevance

**这篇是本库"动态灯光 ≤3/≤2/≤1/0"那一行的直接上游。**

1. **灯数的上限，可以从"外观误差"反解出来，而不是拍的。** 现在的 SABC 表把"动态灯光"写成绝对数量（S≤3 / A≤2 / B≤1 / C=0），**这个数的依据从来没人说得清**。本篇给了可执行的三步：定 $n_{\max}$（最大允许重叠）→ 定 $a_o$（重叠/误差兑换率）→ 跑一次，**读出"为了达到这个误差，最少需要几盏"**。**预算从"经验值"升级为"曲线的读数"。**
2. **灯这一维的正确计量对象是 ALO，不是灯数。** 表 2 已经证明两者可以脱钩（−74% 灯数换 −23% 重叠）。**建议 SABC 表把"动态灯光"拆成两列**：**灯数**（资产复杂度、影响 CPU 侧提交与阴影）与**峰值 ALO**（像素侧填充成本）。这跟 10-25 提的"补一行像素预算"、10-29 提的"驻留/流量拆两半"是同一类修订。
3. **一套灯架，五档画质。** 如果目标是视角无关的辐照度，那么"低画质"不等于"另一套灯"，而等于**同一套灯架下更大的 $a_o$ / 更小的 $n_{\max}$**。**这对"五档画质"的实际含义是一次流程简化**：不用维护 Android_Low 专用灯组，只需在打包时决定误差容限（前提：灯架本身由优化器产生）。
4. **十分钟这个数字决定了它进哪个环节。** 一次技能改灯光后重跑 10 分钟——**可以进"资产入库前校验"，不能进"美术实时调光"**。所以它的正确落点是**CI 检查项**：提交灯组 → 自动精简 → 报"灯数 / 峰值 ALO / 误差上界"三个数 → 超阈值则打回。
5. **VFX 侧的用法**：技能光常常是"5 盏灯打同一片区域"（重叠高、单灯贡献低）。**这正是重叠损失最擅长删的形状**——但它删的是"冗余"，不是"风格"；**闪、脉动、变色这类随时间变的灯不在 ToD 关键帧模型里**（ToD 只处理平滑的强度/颜色/开关变化）。**技能光要做，得把时间轴切成关键帧再喂进去**——工程上可行，论文没做。

## Unreal Engine Relevance

- **直接对应**：Clustered Deferred 的 per-cluster light list、Lumen / MegaLights 的 light count budget。**本篇的输出是"更短的列表"，可与这些系统叠加**（原文明确说可与运行时光源选择配合）。
- **潜在落地形态**：Editor 工具/命令行 —— 选一组灯 → 解一次 → 得到"精简后灯组 + 误差报告"。**关键设计：报告必须给"最坏视角的误差"，不是平均**（否则美术无法判断能不能接受）。这一点可直接借 [[Walter 2005 — Lightcuts A Scalable Approach to Illumination|Lightcuts]] 的"每簇上界"语言。
- **不能照搬的地方**：本篇假设 **Unity/Frostbite 的点光+聚光模型与硬半径**；UE 的灯有 IES、Rect Light、Light Function、Volumetric Scattering——**每一项都会让"辐照度场 = 灯参数之和"这个可微结构变复杂**。Rect Light 原文明确列为未来工作（"不存在根本障碍"）。
- **Lightmass / 烘焙线的对照**：本篇是"**改灯**，不动烘焙"；[[Lightmass in the Rendering Knowledge Map|Lightmass]] 是"**不改灯**，改预计算"。两者解决的是同一个预算问题的两端——**改内容 vs 改缓存**。

## Technology Evolution

```text
【线一：灯作为变量（离线 → 实时）】
1993  Painting with Light —— 解强度（约束最小二乘，离线）
2016  Coverage Optimization —— 解灯数（NNLS + 聚类 + cut）
2024  Adjoint Light Tracing —— 解位置/强度/方向（伴随法，离线）
2026  ★ LightOpt —— 解全部 + 增删并 + ToD（实时游戏，10 min）

【线二：多光源的"少算"（运行时）】
1994  Ward 排序 → 2005 Lightcuts（树+切+界） → 2007 MRCS → 2011 LightSlice
2020  ReSTIR（复用） → 2025 MegaLights（每 tile 可见表 + 随机直接光）
2026  ★ LightOpt 从另一侧切进来：不改查询，改资产
```

**两条线在 2026 年交叉**：线一把"灯"变成可解变量，线二把"查询"变成可近似对象。**LightOpt 的位置是"线一终于追上了线二的工程可行性"**——它不需要光线追踪、不需要新的 GPU 特性，只需要一个可微的解析光照模型和十分钟。

### Contrasts

- **[[Walter 2005 — Lightcuts A Scalable Approach to Illumination|Lightcuts 2005]]**：**改查询 vs 改内容**。Lightcuts 保留全部灯、把"一次算几盏"降下来（639,528 盏 → 305 节点）；本篇**改掉灯本身**（121 → 57）。**一个在每帧付账，一个在资产时付账。**
- **[[2026-11-14-Sancho — Neural Render Proxies for Interactive and Differentiable Lighting|NRP 2026]]**：**冻结的轴正好互补**。NRP 冻结**相机与材质**、只让灯动（一个视角一个网络，19 GB 缓存）；本篇冻结**灯架**（优化完就固定）、让相机随便动。**一个买"灯可编辑"，一个买"相机自由"。**
- **业界 32 灯基线**：**视角相关 vs 视角无关**。前者每帧重排、每平台一套；后者解一次、全平台共用。
