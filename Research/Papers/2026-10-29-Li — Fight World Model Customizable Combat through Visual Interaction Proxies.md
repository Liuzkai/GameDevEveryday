# Fight World Model —— 让规则改得动，让画面不用重训

> Oxford × Imperial College London × Tsinghua × NTU，`2610.40607`，18 页，2026-10-29。
> **一句话**：世界模型最尴尬的地方不是画不出打斗，是**改一条规则就要重新训练**。FWM 把"规则执行"和"画面渲染"彻底分开：一个可执行引擎算状态与事件，一个**确定性编译器**把它压成一张**交互代理**（框 / 朝向 / 动作窗 / 技能窗 / 受击闪 / 血条），渲染器只吃这张代理——**改伤害、改免伤、改吸血，代理格式不变、渲染器不重训**。

## TL;DR

- **它解决的是"规则可编辑"，不是"画面更真"**：现有视频世界模型能生成合理的打斗，但**受击反应与血量更新跟规则对不上**——因为它们是"从录像里学出来的动力学"，不是"执行出来的结果"；
- **交互代理的三条分层依据只有一句**：**规则能独立改动的地方，就必须独立编码**。于是"尝试的动作"（动作窗 / 技能窗）、"瞬时的反应"（受击闪）、"持久的状态"（血条）三件事**分成三条通道**——因为"被保护的一击"要求"有反应、不掉血"，一根通道表达不了；
- **代价与收益都极干净**：改规则（吸血）后，血量误差 **0.19 vs 10.46**（用文本编码规则）、联合保真度 **99.87 vs 16.83**；身份绑定把换边后的外观遵循度从 **53.68% 拉到 98.27%**（+45 点）；
- **消融证明三层确实各管一件事**：去掉受击事件线索 → 反应 99.79→**80.42**（血量仍准）；去掉血条 → 血量误差 0.15→**2.18**、联合保真度 98.48→**57.24**（反应仍准）。**两条通道互不替代**；
- **一处必须说清的边界**：规则干预那组实验的"真值"就是代理本身，所以它测的是**"渲染器有没有忠实执行代理"**，不是"规则引擎算得对不对"。**这正是它想证明的命题，但不能当成"游戏逻辑正确性"来引用**；
- **品类边界很硬**：固定 2D 视角、Street Fighter II/III 一个品类、5B 视频骨干。**它的"可定制"是规则层的，不是镜头层的。**

## Problem

一个"可玩的、可编程的游戏世界"要同时满足三件事：**持久状态**、**可执行规则**、**可扩展机制**。视频世界模型把这三件事都塞进了生成器：

- 状态转移是**学出来的**（从录像里学"打中会掉血"），于是**改规则就必须改模型**；
- 更糟的是——**模型会保留训练时见过的"动作—后果"关联**，即使你把新规则写在提示词里，它也会按老习惯生成；
- 而如果只做"状态预测"（比如 StatePlay 那种并行预测血量的分支），**预测不等于可编辑**——你有一个数，但没有一条能改它的规则。

**所以真正缺的不是"更好的生成"，是一个"规则结果 → 画面"的接口。**

## Historical Context

[[World Models for Games]] 这条线在库里已经分成两派，FWM 是"薄接口"派在**格斗品类**上的一次完整实现：

```text
2026-10-20  WorldStream    记录（Record）→ 编译（Compile）→ 几何；几何可丢弃，记录才是资产
2026-10-26  UniWorld       窗口状态：深度只在接缝读一次
2026-10-29  BoxWorld       三个字段的状态（盒子/类别/存在），规则写成**可执行代码**
2026-10-29  ★ FWM          规则引擎 → **交互代理**（框/朝向/动作窗/技能窗/受击/血量）→ 渲染器
        ↓
      "接口越薄，规则越可改；但接口越薄，能表达的东西越少——
        BoxWorld 只表达'有没有'，FWM 表达'谁在什么时候被什么打到了'"
```

**BoxWorld 与 FWM 是同一天的两极**：前者把状态压到"存在与否"，换来规则完全可执行；后者把状态扩到"动作窗 + 事件 + 血量"，换来**打斗里的时序**能被表达。**两次都是在同一个问题上做加减法：接口里该放多少"时间"。**

## Previous Work

- **游戏世界模型**：Genie / Oasis / Matrix-Game / Yume —— 动作条件生成，但后果由学到的动力学决定；
- **状态预测**：StatePlay 并行预测血量与技能槽——**有数，无规则**；
- **多实体控制**：ReactiveGWM v1/v2、WorldMind —— 能指定"谁做动作"，但**不决定"规则改了后果该怎么变"**；
- **代码驱动世界模型**：Code World Model / Programmable World Model / Oneira —— 状态在生成器外执行，但**只给空间代理**（深度/语义/实例/3D 框），**没有动作窗、没有受击、没有持久血量**。**这正是 FWM 的切口**。

## Core Idea

> **把"意图、事件、状态"拆成三条通道——因为它们会被规则独立地改动。**

一句判据贯穿全篇：

| 想知道什么 | 编码成什么 | 为什么必须单独一条 |
|---|---|---|
| **他想做什么**（未必打中） | 动作窗 / 技能窗（条纹与洋红块） | "尝试"与"结果"是两件事，规则可以只改结果 |
| **刚刚发生了什么**（瞬时） | 受击闪（4 帧反色） | "被保护的一击"要求**有反应、不掉血** |
| **现在是什么状态**（持久） | 血条长度 | 反应会消失，血量要留到下一回合 |

**如果只编码一个"hit"信号，"保护状态下的受击"就表达不出来**——这不是工程细节，这是接口的表达力边界。

## Technical Approach

### 1. 引擎与编译：确定性，且与渲染器解耦

$$(S_{k+1},e_{k+1})=F_R(S_k,u_k)$$

引擎按规则 $R$ 推进状态并产出事件；**事件先对齐到视频帧时间轴**，再由**确定性光栅器**画进共享画布：

$$\pi_t=\mathcal D(s_t,E_t)$$

- $s_t$：可见状态投影（框 / 朝向 / 姿态 / 动作标签 / 血量）；
- $E_t$：活动记录（动作窗与受击事件的**身份、起始、时长**）。

**改规则 = 换 $R$ 重跑引擎**，代理随之变化，**渲染器参数一个不动**；**改外观 = 换参考图**，代理一个不动。

### 2. 代理长什么样（编码细节决定成败）

| 元素 | 编码 | 为什么这么编 |
|---|---|---|
| 角色 | 框 + 朝向 + 姿态 + 粗动作标签 + 血量，**共用身份色** | 身份色是"谁"的唯一载体，跨换边仍成立 |
| 攻击 | **横条纹 = 拳、竖条纹 = 踢，覆盖度 = 轻重** | 六类攻击用几何而不是标签，**VAE 压不坏** |
| 技能 | 施法者前方一块**洋红块**，随位置与朝向移动 | **52 种技能共用同一个标记**——技能差异交给文本 |
| 受击 | 框填充与血条**反色 4 帧** | 4 帧是"能活过 VAE 时空压缩"的下限 |
| 血量 | 血条**长度**独立编码 | 与受击反色解耦，才能表达"有反应不掉血" |

**"4 帧反色"和"条纹要粗"这两条是同一个约束的产物**：代理要经过 VAE 的时空压缩，**太细的线索会被压没**。这是"接口必须按通道的物理特性设计"的少见明写。

### 3. 身份绑定：让参考图跟着"人"走，不跟着"位置"走

每个角色从一个**学习到的码本**里取一个 slot（训练时**不放回随机分配**，避免码本项与外观形成固定映射），slot embedding 加到三处：**首帧视频 latent 的对应区域**、**代理序列的全部帧**、**该角色参考图的所有 token**。加权用**软框覆盖度**。

**效果（Table 1）**：不换边 78.43% → **99.16%**；**换边 53.68% → 98.27%**。**换边是最狠的测试**——外观相同但左右互换，如果绑定靠位置，它必然失败。

### 4. 渲染：共享 VAE，token 拼接，只有视频 token 被解码

视频 / 参考图 / 代理**共用一个 VAE 与 patch embedding**，token 按 `video–reference–proxy` 顺序拼接，参考与代理两路带**学习到的通道门控**。代理 token 与对应视频 token **共享时空 RoPE 位置**；参考 token 用**视频网格之外**的位置。**只有视频 token 被解码。**

## Key Contribution

1. **一个"规则可编辑"的战斗世界模型**：改伤害倍率 / 限次免伤 / 吸血 / 多段技能，**渲染器不重训**；
2. **交互代理**：把"尝试 / 事件 / 状态"三分，且**格式对规则改动不变**；
3. **身份绑定**：把外观参考绑到**持久身份**而不是屏幕位置，换边不丢人；
4. **FightWorld Corpus**：**112,618** 训练样本，**52** 种技能特效、**187** 种外观变体、**15** 个场景。

## Why It Works

**因为它把"生成"从"预测后果"降级成了"渲染后果"。**

生成器最不擅长的事是**精确的离散状态机**：血量减 7、免疫还剩 2 次、技能第 3 段才生效——这些是符号运算，扩散模型学不准也不该学。而生成器最擅长的事是**把已知的空间/时间条件画得像**。

FWM 的分工正好卡在这条线上：**符号运算交给引擎，像素交给渲染器，中间只传一张"画得出来的代理"。**

**Table 2 是这句话的证据**：纯空间代理（框 + 朝向）在"移动"上已经有 99.19%，但**技能只有 46.58%**——因为空间代理**没有时间**。加上文本能到 92.43%，加上状态 token 到 82.42%（文本更强），而**交互代理把三者同时推到 99% 以上**。**差的从来不是"信息量"，是"信息的形状"。**

## Limitations

1. **固定 2D 视角、单一品类**（Street Fighter II/III）：镜头一动，代理的空间布局就要重定义；
2. **5B 视频骨干**：生成质量受骨干限制，且不是实时；
3. **代理是瓶颈**：它只说"谁在何时被什么打到了"，**不说"怎么打的"**——动作的细节（受击方向、部位、力度）全靠渲染器自己补；
4. **（补）评测的循环性**：规则干预那组实验里，目标就是代理本身，所以指标测的是**渲染器忠实度**，不是**规则正确性**。**这个区分在引用时必须保留**；
5. **（补）"外观可定制"的边界**：187 个变体 + 15 个场景是**训练分布内**的定制；未见过的美术风格能不能零样本保持，论文没有回答。

## Game Development Relevance

**这是今天四篇里与你的工作最直接相关的一篇。**

- **技能窗口是一等公民**：代理里"洋红块随施法者移动"就是**技能的作用时间窗 + 空间范围**。**这与你的 SABC 预算表是同一套语言**——你按"触发频率 × 难度 × 伤害"分档，它按"起始帧 + 持续帧 + 命中判定"编码。**两套语言可以对齐：S 档技能 = 长窗口 + 多段事件 + 多次受击闪**；
- **52 种技能共用同一个标记**：这条对**特效预算**有直接含义——**技能的"机制"与"表现"可以分开记**。机制（判定窗、段数、命中次数）进代理/配置；表现（粒子、材质、拖尾）进渲染。**你现在的 SABC 表混着记，导致"这个技能为什么贵"说不清是机制贵还是表现贵**；
- **"有反应不掉血"是一个通用的表达力测试**：任何"状态 + 事件"的编码方案，都该能表达**"发生了什么但状态没变"**。**这条可以直接拿去审 Niagara 的事件系统与 Gameplay Ability 的接口**：能不能只发事件、不改状态？
- **换边绑定 = 多人同屏的身份问题**：VFX 里"这个特效属于谁"同样存在（同一技能两个角色同时放）。**friendly/enemy 配色是位置无关的身份编码，与本文的身份色同理。**

## Unreal Engine Relevance

- **Gameplay Ability System**：FWM 的"引擎 + 编译"就是 GAS 的"Ability → GameplayCue"——**GameplayCue 本来就是"事件的可视化代理"**。FWM 的贡献是把 cue 的格式设计成"渲染器能直接吃"的样子（几何化、抗压缩、身份绑定）；
- **Niagara 的 User Parameter 就是代理**：位置/朝向/技能 ID/强度——**但通常没有"持久状态"这一路**（血量、免疫次数）。如果要接生成式渲染，**这一路必须补上**；
- **不适用处**：固定视角。UE 项目里的第三人称自由镜头，代理的空间布局要随相机重投影——**这是本文方法最直接的一道墙**。

## Learning Value

- **最值钱的一条判据**：**拆分的界线，应该画在"谁会被独立地改动"上。** FWM 把 hit 拆成"反应"与"血量"，不是因为它们物理不同，是因为**规则可以只改其中一个**。这条比"一笔账拆成两笔"更硬——它给出了**拆在哪里**的依据；
- **第二条**：**接口的线索要按"通道的物理特性"设计**。4 帧反色、粗条纹——都是因为下游是 VAE。**给任何有损通道设计中间表示时，"它会不会被压没"必须先算，不能事后调**；
- **第三条（对你直接可用）**：**机制预算与表现预算要分开记。** 一个技能贵，可能是"判定窗长、事件多"，也可能是"粒子多、overdraw 高"。**混在一张表里，永远说不清该砍哪一头。**

**三层消融（Table 4）——"各管一件事"的干净证据**

| 去掉什么 | 反应 | 血量误差 | 联合保真 |
|---|---|---|---|
| 满模型 | **99.79** | **0.15** | **98.48** |
| 命令条纹 | 97.93 | 0.28 | 85.26（**Att 86.42 / Skill 87.87**） |
| 受击事件线索 | **80.42** | 0.27 | 78.38 |
| 血条 | 98.31 | **2.18** | **57.24** |
| 技能事件触发 | 98.07 | 0.26 | 78.81（**Skill 79.28**） |

**横着读**：去掉"受击线索"只砸反应（99.79→80.42），血量几乎不动（0.15→0.27）；去掉"血条"只砸血量（0.15→2.18），反应几乎不动（99.79→98.31）。**两条通道互不替代——这就是"必须分开编码"的实证。**
