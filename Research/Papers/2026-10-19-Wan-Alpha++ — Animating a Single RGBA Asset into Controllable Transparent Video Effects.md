# Wan-Alpha++ — Animating a Single RGBA Asset into Controllable Transparent Video Effects

## TL;DR

**把 alpha 当一等公民的视频生成**——给定一张 RGBA 素材（游戏里就是一张带透明通道的技能图标/贴图），生成一段**首尾全透明、中间出现又消失**的特效视频，且 RGB 与 alpha 都干净。三件事值得记：

1. **不改主干的 RGBA 潜空间**：RGB 与 alpha 分别编码后融进**同一组潜变量维度**（不扩维），DiT 一行不用改——保住预训练 RGB 先验；
2. **透明度感知双向扩散（TABD）**：给不透明区 +1、非不透明区 −1 的**符号掩码**乘到 rectified-flow 损失上——正向保住"不透明处的 RGB 似然"，反向把"非不透明表示"推离 RGB 分布。**用梯度符号表达"哪里不该是内容"**；
3. **换时间原点，让旧机制可用**：出现–消失特效是"零–正–零"（首尾帧全透明），预训练模型的首帧条件机制直接失效。本文把时间轴**循环平移**成"正–零–正"，让首/尾帧条件重新有效，生成完再做**逆变换**还原——**不发明新机制，只重排输入**。

数字：文生 RGBA 文本对齐 4.00（最强基线 3.45）、透明度正确性用户排名 1.23（越低越好）；图生特效 DINO-I 0.9227 vs 两阶段基线 0.6679。

![[Research/Files/Pictures/Dong 2026 — 图1 RGBA VAE 与透明度感知双向扩散.png]]
**读图**：左 = 硬渲染/软渲染两个函数（用随机背景色把 RGB 与 alpha 解耦）；中 = RGB 与 alpha 各自过**冻结编码器**，经一个可训练融合块（M）合成共享潜变量 $Z$——**维度不变**，所以后面的 DiT 不用改；右 = 两条 LoRA 解码分支。中间绿框是 TABD：不透明区 $O$ 给 $M=+1$、半透明/全透明区 $S\cup T$ 给 $M=-1$，乘到 rectified-flow 损失上。（图 1，Dong et al. 2026）

## Problem

游戏与影视都需要**可合成的透明素材**（序列帧 / flipbook / 叠加层），但现有路线都有硬伤：

- **先生成 RGB 再抠像（matting）**：两段误差累积——生成模型不知道"最终要透明"，抠像模型又看不到运动上下文；发丝、烟、薄纱这类**半透明边界**必崩；
- **文生 RGBA 模型**（LayerDiffuse / TransPixeler 一类）：RGB 与 alpha 分布纠缠，alpha 边界毛糙、背景残留；
- **首帧/首尾帧条件失效**：技能特效的标准形态是"出现 → 展开 → 消失"，**首尾帧都是全透明的**——而预训练视频模型的图生条件机制要求首帧有内容，直接喂全透明帧会得到"整段都空"或"边界帧被当成噪声"。

## Historical Context

```text
2023  LayerDiffuse：把 alpha 塞进潜扩散（图像级），透明 PNG 生成
2024-2025  视频侧跟进：TransPixeler / RGBA 视频扩散——alpha 与 RGB 仍纠缠
2026       Wan-Alpha（会议版）：文生 RGBA，首次把"透明"做成共享潜空间的一等分量
★ 2026-10  Wan-Alpha++（本篇）：加图生条件 + **出现-消失**这一特有时序形态
```

**它解决的不是"生成得更好看"，而是"生成的时间结构对不对"**——首尾透明这个约束，是一条**结构性**约束，不是画质问题。

## Core Idea

三个"不动模型、只动数据与采样"的技巧，是本篇最可迁移的部分：

| 技巧 | 做法 | 一句话本质 |
|---|---|---|
| **TABD** | 符号掩码 $M\in\{+1,-1\}$ 乘到扩散损失：不透明区保似然、非不透明区推离 | **用梯度符号表达"这里不该是内容"** |
| **透明引导均值采样** | 由 alpha 通道算协方差椭圆 $G$，把初始噪声均值平移成 $\mathcal{N}(G\cdot\mu,I)$（默认 $\mu=0.05$） | **把 alpha 先验搬到采样起点**——零额外网络、零额外显存 |
| **时间相位重参数化** | 循环平移时间原点 $k$：$0\to+\to0$ 变成 $+\to0\to+$，生成后逆变换 | **换个时间原点，让旧的条件机制重新可用** |

## Technical Approach

### 1) RGBA 潜空间（不改主干）

- **硬渲染 / 软渲染**：$R_h=V_{rgb}\odot\mathbb{I}(V_\alpha>0)+c\,[1-\mathbb{I}(V_\alpha>0)]$，$R_s=V_{rgb}\odot V_\alpha+c(1-V_\alpha)$，背景色 $c$ 从 8 种纯色里随机取——**逼模型学会"背景是任意的、alpha 才是真的"**；
- 冻结编码器分别编 RGB 视频与"三通道复制的 alpha 视频"，经**因果 3D 卷积 + 5 个（因果残差 + 注意力）子模块**融合成共享 $Z$；解码走 RGB LoRA / Alpha LoRA 两条分支；
- 重建目标 = 像素 L1 + 感知损失 + **Sobel 边缘一致性**；渲染目标同时监督 alpha、软渲染、硬渲染。

### 2) TABD：把 DiT 拉进 VAE 的训练回路

只靠潜特征的统计距离，DiT 分不清"这是 RGB 还是 alpha"。所以本文把**冻结的 DiT 放进 VAE 训练**，从 DiT 的视角优化潜表示：

$$\mathcal{L}_{bidiff}=M\cdot\mathcal{L}_{RF},\qquad M(p)=\begin{cases}+1 & \text{不透明区}\\-1 & \text{半透明/全透明区}\end{cases}$$

**含义**：不透明区的表示要"像 RGB"（保预训练先验），非不透明区的表示要"被推离 RGB 分布"（让 alpha 可分）。这是一个非常便宜的技巧——**不改结构，只改损失的符号**。

### 3) 时间相位重参数化（本文最漂亮的一招）

- 定义每帧的**时间 alpha 质量** $m_i=\frac{1}{HW}\sum V_{\alpha,i}$；可见性集合 $\mathcal{K}=\{j\mid m_j>\tau_m,\ m_{j-1}>\tau_m\}$（$\tau_m=0.5$）；
- 从 $\mathcal{K}$ 里采样切点 $k$，做循环平移 $\tilde V_i=V_{(i+k)\bmod T}$：$0\to+\to0\ \Rightarrow\ +\to0\to+$；
- 此时**首尾都有内容**，预训练模型的"首尾帧条件"直接可用；生成后施加**逆变换** $\mathcal{R}_k^{-1}$ 还原成"出现–消失"；
- **只改时间相位，不改帧内容、运动与透明度演化**——所以模型学到的是"同一段特效的另一种时间排布"，而不是一个新的生成任务。

### 4) 透明态梯度引导

推理时把**同一张 RGBA 参考图同时放在首尾**锚定外观，中间指定一段不可见区间（默认中间 8 帧），用梯度把它推向**全透明目标** $V_\varnothing$：

$$\hat Z_0=Z_n-n\hat v_n\ \Rightarrow\ \mathcal{L}_{tr}=\|\hat V_{\mathcal{I}_{tr}}-V_\varnothing\|^2\ \Rightarrow\ \bar g=g/(\|g\|+\epsilon)\ \Rightarrow\ \hat Z'_0=\hat Z_0-\eta\bar g$$

**关键洞察**（原文明确写出）：让模型"匹配一张复杂 RGB 关键帧"是不可靠的；但**"全透明"是低复杂度状态**（零 alpha 占主导），梯度引导在这里可靠。**把不可验证的目标换成低复杂度目标**——这是可迁移的工程判断。

## Key Contribution

1. **不改主干的 RGBA 表示**：证明"扩维不是唯一解"，融合块 + 双向损失足以让同一组潜变量同时承载 RGB 与 alpha；
2. **时间相位重参数化**：把"首尾透明导致条件失效"这个结构性障碍，转化为一次可逆的时间重排——**零训练成本的机制复用**；
3. **透明态梯度引导**：给出"在低复杂度子空间里做引导"的样板；
4. **数据侧贡献**：77,237 个训练片段（10 个抠图数据集 + 3 个视频抠像集）、429 条文生样本、196 条特效视频——**特效类数据是稀缺项**，这批量本身有价值。

## Why It Works

- **alpha 与 RGB 的可分性来自"背景随机化"**：软/硬渲染用 8 种随机底色，等于告诉模型"你看到的背景是假的"；
- **符号掩码比加权更有效**：+1/−1 是"要么靠近、要么推开"，没有中间地带——对二值语义（是否内容）正合适；
- **时间平移是可逆的、保内容的**：它不改变任何一帧的像素，只改"哪一帧被当作第 0 帧"，所以模型的能力被完整保留；
- **引导目标选得对**：全透明帧的分布极窄（alpha≈0），梯度方向稳定；相比之下"匹配参考图中间帧"是高维、多解的。

## Limitations

- **推理成本**：透明态引导每步要 2–3 次梯度迭代，且只在前 32/40 步做——**比基线贵**（作者列为待优化项）；
- **超参敏感**：$\mu$（均值平移强度）、$\eta_s$（引导步长）、引导步数都要调；$\mu$ 过大出现色偏（0.5 时明显），$\eta_s=75$ 或全程引导会掉细节；
- **只处理单次"出现–消失"**：多阶段透明度事件（闪烁、间断出现）未覆盖；
- **分辨率/时长受限**：基于 Wan2.1 的 VAE 与 DiT，片段长度与分辨率受底座约束（论文未给长视频结果）；
- **无物理/无光照一致性**：生成的是"看起来对的透明视频"，不是可重打光的素材——**不能直接当带光照的 VFX 元素复用**。

## Game Development Relevance

- **它填的是"2D 特效素材生产"这一格**：风格化技能特效、UI 动效、宣传物料大量使用**序列帧 / flipbook / 透明叠加层**，而这条管线最贵的一步一直是"alpha 干净"（发丝、烟、薄纱、光晕）；
- **"出现–消失"正是技能特效的标准生命周期**：起手 → 展开 → 消散。本文把这条时序形态当成**结构约束**来处理，而不是靠提示词碰运气——这对做技能 VFX 的人是有共鸣的；
- **两阶段（生成 + 抠像）的误差累积有了量化对照**：特效类 DINO-I 0.6679 → 0.9227、CLIP-I 0.7969 → 0.9368，且图 13 直观显示两阶段在"首帧初始化"下根本产不出消失过程；
- **必须说清的边界**：这是**离线素材生成**，与运行时粒子系统是两条账。它不会降低 Niagara 的 overdraw，也不会进你的 SABC 预算；它能影响的是**素材制作工时**与**风格化特效的试错速度**；
- **可迁移的两条判据**：① 素材生成要"从第一步就带 alpha"，不要后期抠；② 生成的结构性约束（首尾状态、朝向、锚点）应尽量用**可逆的输入变换**去满足，而不是让模型重新学。

## Unreal Engine Relevance

- 产出可直接作为 **Flipbook / SubUV 贴图**或**带 alpha 的视频纹理**（UE 的 Media Texture）导入；
- 若要用于 Niagara 的 sprite 渲染器：需转成序列帧图集（本文不提供该工具链）；
- **不建议**把它当"UE 内实时特效"——它是 DCC 侧的素材生成器，位置在内容生产管线，不在运行时。

## Learning Value

- **立即可用的判断**：下次看到"AI 生成特效"的宣传，先问三件事——① alpha 是端到端出的还是后抠的？② 首尾状态怎么保证？③ 生成的东西能不能重打光？本文对前两问给了正面答案，第三问没有；

## Notes

- **为什么是 B+ 不是 A**：方法层面三招都干净且可迁移，但**底座是别人的**（Wan2.1）、**数据是拼的**（公开抠像集）、**任务面窄**（单次出现–消失）；它是"把一个具体痛点解决得很好"，不是"提出新范式"；
- **与库内 VFX 线的位置**：[[Particle Systems]] / [[Real-Time VFX Performance Budgeting]] 讲的是"运行时怎么省"，本篇讲"素材怎么来"——两条账本互不影响，但都属于"技能特效"这条业务线的上下游；
- **一处需注意**：本文的"特效"数据只有 196 条（含薄纱/烟/水/光晕/发丝边界），**样本量很小**；它在"风格化/卡通素材"上的表现（图 13 的熊与城堡）比写实特效更有说服力，引用时不要外推。
