# Patch-Based Generalized Neural Texture Upscaling（Fujieda & Harada 2026）

## TL;DR

**把"纹理分辨率"这个决定从资产挪到采样点。** 一个**通用的**小 MLP（不是每张纹理一个），训练好之后**直接替换纹理采样器**：取 3×3 低分辨率 texel，出 2×2 高分辨率 texel。

```text
传统：资产里存 2K → 显存里驻留 2K → 采样时双线性
离线超分：离线把 1K 升成 2K → 存 2K（磁盘/显存一点没省）
NTC：每套纹理拟合一个小网络 → 省磁盘也省显存，但【每资产要训练】+【多套并发采样会发散】
本文：资产里存 1K → 采样时 3×3 texel 过一次共享 MLP → 显存/磁盘都按 1K 算
```

**一句话评价**：**它赢的不是画质（PFT 全面更好），赢的是"接口"——一个所有纹理共用的权重，意味着零资产改动、零管线改动、零 warp 发散。** 而它的代价，全文**没有一个数字**。

## Problem

分辨率在涨，纹理是显存与包体的主要成本：

- 磁盘：直接等于游戏下载体积；
- 显存：直接抬高最低硬件要求。

已有四条路，各有各的不可行处：

| 路线 | 省磁盘 | 省显存 | 每资产要处理 | 运行时可行 |
|---|---|---|---|---|
| 离线神经超分（SRCNN / SwinIR / **PFT**） | ✅ | ❌（升完还得存 2K） | ❌ 不需要 | ❌ 计算量大、**无随机访问** |
| **NTC**（神经纹理压缩） | ✅ | ✅ | ✅ **每套要拟合** | ✅ 但**多套并发 = 发散** |
| **NTBC**（神经块压缩） | ✅ | ✅ | ✅ 每资产要处理 | ✅（硬件解码，但质量被 BC 约束封顶） |
| 解析上采样（双线性/双三次/Lanczos） | ✅ | ✅ | ❌ | ✅ 但**补不出缺失的高频** |

本文瞄准的空白很明确：**要一个"不需要每资产处理、又能在采样时跑、又不会发散"的方法。**

## Historical Context

```text
2014  SRCNN：CNN 做图像超分（离线，无随机访问）
  ↓
2021  SwinIR：Transformer 超分（同上）
  ↓
2023  NTC（Vaidyanathan 等，NVIDIA）：每套纹理拟合一个小 MLP + 潜网格，
        采样时解码 ⇒ 第一次同时省磁盘与显存
        · 代价：每资产训练；每套一个网络 ⇒ 并发采样发散
  ↓
2024  NTBC（Fujieda & Harada）：网络只负责"产出 BC 块"，解码交给硬件
        · 绕开运行时推理，但质量被 BC 格式封顶；仍要每资产处理
  ↓
2025  PFT（Long 等，CVPR）：当前最强离线超分，作为本文的"上界参照"
  ↓
2026 ★ 本文：一个【通用】MLP，塞进采样器里，2× 上采样
        · 零资产改动、零发散；质量介于解析法与 PFT 之间
```

**这条线的分水岭是 2023：NTC 把"解码"搬进了采样器，但把"模型"绑在了资产上。** 本文的全部贡献就是把那个绑定解开——**用通用性换压缩率**。

## Previous Work

作者自己把前驱分成三类，分类方式比结论更有用：

1. **通用离线超分**（PFT / SwinIR / SRCNN）：模型通用、质量高，但**不能随机访问**——你得先有整张图。所以只能当预处理，省不了显存。
2. **每资产拟合**（NTC / NTBC / MATUP / PBR-SR）：质量或压缩率高，但**每套纹理一次训练**，进不了"直接套在已有游戏上"的场景。
3. **解析上采样**（双线性/双三次/Lanczos）：免费、可随机访问，但**原理上补不出低分辨率里不存在的高频**。

本文的位置：**第 1 类的通用性 + 第 3 类的可随机访问 + 第 2 类的省显存**，代价是压缩率不如第 2 类。

## Core Idea

### ① 局部性：一次只升一个 patch，不是一整张图

输入 $(n+2m)\times(n+2m)\times c$，输出 $2n\times 2n\times c$；实验取 $n=1,\ m=1,\ c=3$，即 **3×3 → 2×2**。

- $n=1$ 的理由：**每次采样取的 texel 数最少**；
- $m=1$ 的理由：**不带 context 的 patch 在边界会出现块状接缝**（模型看不到 patch 外的图案），所以每边扩 1 texel 当 context，输出时丢掉；
- 边界处没有 padding texel 就**镜像**（假设纹理在边界平滑）。

### ② 残差接解析上采样，而不是从零学

$$\text{out}=2\times2\ \text{的输出} = \underbrace{\text{bilinear}(3\times3)}_{\text{低频，已够好}} + \underbrace{\text{MLP}(27\text{ 维})}_{\text{只学高频残差}}$$

结构：线性投影到 $d$ → $L$ 个残差块（两个 Linear + ReLU + skip + ReLU，**skip 后 clamp 到 1**）→ 输出层投到 $2n\times2n\times c$。实验配置 $d=256$、$L=4$。

**这一步是全文最实用的一处设计**：低频让解析法免费给，网络只负责它擅长的那个残差。消融也支持——去掉残差连接 LPIPS 0.0796 → **0.0755**；去掉残差块 0.0767 → 0.0755（**小但稳定**）。

### ③ 通用性 = 无发散（全文最重要的一句工程论证）

> **"因为所有纹理共享同一套权重，GPU 执行无论同时有多少套纹理活跃都不会发散。"**

这句话值得展开，因为它是本文与 NTC 的**唯一本质区别**：

- NTC 每套纹理一个网络 ⇒ 一个 warp 里的 32 个线程可能在跑 32 个不同的网络 ⇒ **矩阵核心（matrix core）是按组工作的，不是 SIMT** ⇒ 需要**排序**才能高效执行（原文引 Belcour & Benyoub 2025）；
- 本文只有一套权重 ⇒ **warp 内所有线程跑同一个网络** ⇒ 矩阵核心可以直接吃。

**代价写得很诚实**：压缩率比不过 NTC。原文 Table 4.4 直接说：本文与 PFT "都无法匹配 NTC (512×512×3)"，本文大致相当于 **NTC (256×256×3)**，在困难样本上更差。

### ④ 一个"因为接口形状"才存在的能力（作者的附注，值得单列）

> "我们还没探索，但**完全可以跳过 MLP 直接采样低分辨率纹理**——比如漫反射之后的顶点，不需要高质量的地方。"

**为什么 NTC 做不到**：它的潜网格必须先解码才能用，跳过解码就没有 texel。**本文的输入是 texel 本身**，所以"升不升"是每次采样自己的事。

**这是"决定权在消费点"的最纯粹形态**：连"要不要用神经网络"都是每个采样点决定的。

## Technical Approach

| 项 | 设定 |
|---|---|
| 输入 / 输出 | 3×3×3 → 2×2×3（**2× 上采样**） |
| 隐藏维 / 残差块 | $d=256$，$L=4$ |
| 损失 / 优化器 | L1（作者称比 MSE 更锐）、Adam，lr $10^{-3}$（可选 cosine 退火到 $10^{-6}$） |
| 训练集 | Poly Haven（Diffuse 565 / Normal 565 / ARM 563 张）；**三类混训一个模型** |
| 测试场景 | Hangar（45/44/45）、Victorian（37/36/36）、Museum（56/29/30） |
| 纹理尺寸 | 统一降采样到 ≤2048×2048 |
| 主机端 | HIP 写的渲染器（AMD） |

**三类混训的依据**（Fig. 3）：同类训练的模型在同类上最好，但**混训在三个类上总体最平衡**；单用 normal 训 normal 反而不好（作者的推测未展开）。

## Results

### ① 画质：**全面输给 PFT，全面赢过解析法**（LPIPS，越低越好）

| 数据集 / 类别 | 本文 | 双线性 | 双三次 | Lanczos3 | **PFT** |
|---|---|---|---|---|---|
| Poly Haven / Diffuse | 0.239 | 0.396 | 0.369 | 0.383 | **0.224** |
| Hangar / Diffuse | 0.075 | 0.193 | 0.156 | 0.157 | **0.043** |
| Hangar / Normal | 0.023 | 0.088 | 0.067 | 0.065 | **0.014** |
| Hangar / ARM | 0.041 | 0.094 | 0.068 | 0.065 | **0.024** |
| Victorian / Diffuse | 0.103 | 0.225 | 0.190 | 0.192 | **0.091** |
| Museum / Diffuse | 0.052 | 0.142 | 0.107 | 0.107 | **0.048** |

> **PFT 在每一行都更好**，而且模型复杂度差好几个数量级。作者把 PFT 定位成"上界参照"（best-case performance），这个自我定位比很多论文诚实。

**PSNR 的用法值得记**：作者明确说"**模糊的纹理常常 PSNR 更高**"，所以主指标用 LPIPS。Table 2 里 Hangar Diffuse：本文 PSNR 36.86 高于双三次 35.42，但 LPIPS 0.075 好于 0.156——**两个指标方向一致；而在 Museum Normal 上 PSNR 38.44 反而低于双线性 38.61，LPIPS 却 0.020 好于 0.064**。这就是"逐像素指标不适合评上采样"的具体形态。

### ② 端到端渲染误差（FLIP，越低越好）

| 相机 | 本文 | 双三次 | 双线性 |
|---|---|---|---|
| Hangar Cam 1 | **0.0519** | 0.0573 | 0.0626 |
| Hangar Cam 2 | **0.0415** | 0.0441 | 0.0473 |
| Hangar Cam 3 | **0.0441** | 0.0470 | 0.0495 |

**收益很小（约 5–10%）**，但方向一致。作者点出差异主要出现在**高光反射**与近距离视角——**这正是 mip 层级最吃紧的地方**。

### ③ 泛化 vs 过拟合（Table 4）：省下的那点质量值不值一次管线工序

| 数据集 | 通用模型 | 每资产过拟合 |
|---|---|---|
| Hangar Diffuse | 0.076 | **0.059** |
| Hangar ARM | 0.041 | **0.031** |
| Victorian Diffuse | 0.103 | **0.091** |
| Museum Normal | **0.020** | 0.021（**反而更差**） |

**过拟合平均能再降 20% 左右的 LPIPS，但要给每个资产加一道工序。** 而且它不总是赢（Museum Normal）。作者的结论很务实：**"取决于开发情况，让开发者自己选。"**

### ④ 消融（Hangar Diffuse，LPIPS）

| 变量 | 值 | LPIPS |
|---|---|---|
| 隐藏维 | 512 / 256 / **128** / 64 / 32 / 16 / 8 | 0.075 / 0.075 / 0.078 / 0.083 / 0.090 / 0.086 / 0.079 |
| patch 大小 $n$ | **1** / 2 / 4 | 0.0755 / 0.0767 / 0.0899 |
| padding $m$ | **0** / 1 / 2 | 0.0871 / 0.0755 / 0.0791（PSNR：33.79 / 36.87 / **37.21**） |
| 残差连接 | off / **on** | 0.0796 / 0.0755 |

**两条反直觉的**：

- **$m=0$ 崩得厉害（PSNR 33.79）**：拿 1 个 texel 去生成 4 个，是**病态问题**。所以"上下文"不是可选的优化，是这个方法的**成立条件**；
- **$d=8$ 仍好过所有解析法（0.079 vs 双线性 0.193）**：说明收益的大头来自"学到了 PBR 纹理的高频统计"，不是来自容量。**这条对"要不要上大模型"是个有用的下限证据。**

## Key Contribution

1. **把"每资产拟合"换成"一次训练、处处可用"**，于是纹理上采样第一次变成**可插进已有游戏的替换件**（原文："simply by swapping the sampling step"）。
2. **给出"无发散"这个 GPU 侧判据**：多套纹理并发采样时，**权重的数量**决定要不要排序。这是 NTC 类方法的隐性税，本文把它显式化了。
3. **指出了一个只属于"输入是 texel"的优化**：不需要质量的地方可以完全不跑网络。
4. **诚实的天花板**：全文明确说补不出"低于像素尺度、源纹理里不存在"的细节——**这是所有上采样方法的共同边界，不是本文的**。

## Why It Works

**因为它把"通用性"当成接口属性来设计，而不是当成精度损失来接受。**

通常的取舍是"通用模型精度低"，但本文的通用性买到的是三件**工程上不可替代**的东西：

1. **零资产改动**（不用重跑任何离线工序）；
2. **零管线改动**（替换采样器即可）；
3. **零 warp 发散**（一套权重）。

第 3 条最容易被低估：在 PBR 渲染里，**一次 GBuffer 填充可能同时命中几十套材质**（原文引 AMD/NVIDIA 的非主材质执行），每套一个网络意味着要么排序、要么低效。**这不是"精度换速度"，是"可行性"问题。**

## Limitations

1. **🔴 全文没有任何运行时性能数据**。标题里的三个形容词（lightweight / generalized / patch-based），**"lightweight" 是唯一一个没有数字支撑的**——没有参数量、没有 FLOPs、没有每次采样的延迟、没有带宽分析、没有帧率影响。作者把它列为"最重要的未解决方向"：*"a systematic runtime performance evaluation ... would be essential for practical deployment."*
   > 这是本文最刺眼的一处：**它的全部卖点是"能在采样时跑"，而"采样时跑多快"一个字没提。**
2. **只有 2×**。更高倍率未探索；2× 意味着面积 1/4，但**4× 以上的收益才是显存真正吃紧的地方**。
3. **画质上限由低分辨率输入决定**：PFT 与 NTC(512) 都更好，NTC(256) 大致打平。**它没有创造信息，只是更聪明地插值。**
4. **不做 mip 链**。全文没有讨论"上采样与 mip 层级如何共存"——而采样时一旦进入更粗的 mip，输入本身就已经是降采样过的，**误差会叠**。这是工程落地时的第一个坑。
5. **不处理三平面/UV 拉伸/各向异性**：采样器替换只考虑了规则 2D 采样。
6. **三类混训的"平衡"是经验选择**，作者没有给出"什么时候该分开训"的判据。

## Game Development Relevance

**5/5 —— 这是"纹理显存预算"这条线上第一个"零管线改动"的方案，值得当成一个接口范式记住。**

1. **它把"贴图尺寸"这一维的预算单位换了**：从"存多少 texel"变成"每次采样算多少"。见 [[Budget Units]] 的 ⑦。
2. **"通用 + 共享权重"是进管线的硬门槛**：任何"每资产一次工序"的方案（NTC / NTBC / MATUP / PBR-SR）在已有项目里都要重跑整条资产管线。**评估新方法时先问"要不要重跑离线"，这一问比精度差 0.02 重要。**
3. **它给了一个可以直接抄的优化**：**不需要质量的地方跳过网络**。在 VFX 里这对应"远处粒子/次级材质用低分辨率原样采样"，不需要任何额外开关——**因为输入是 texel，跳过是免费的**。
4. **对移动端要谨慎**：TBDR 架构下，每个采样点一次 MLP 前向意味着**寄存器压力与 ALU 占用**，而移动端最紧的是带宽不是 ALU——这个交换在移动端可能是**反的**。原文只做了 PC（HIP）。

## Unreal Engine Relevance

- **落点很直接**：`Texture2D` 采样路径 → 自定义 `MaterialExpression` / 采样节点；或更彻底地，走 **Virtual Texture** 的采样层替换。
- **但 UE 的材质图不允许"每采样一次前向"这种自由度**——实际落地要么写成自定义 shader 节点，要么走 Substrate 的自定义 BSDF 路径。**这是它与引擎结合的真正障碍，不是性能。**
- **与 mip 的冲突在 UE 里尤其明显**：纹理流送按 mip 层级决定驻留，如果只存半分辨率、靠采样时升，那么**流送系统的"层级"概念要重写**——这一点原文完全没碰。
- **可迁移的一条到 Niagara**：粒子贴图的采样同样可以走"低分辨率 + 采样时升"，且粒子对高频细节更不敏感——**这是比纹理更宽容的场景**。

> **这条线的形状不是"越来越准"，是"约束越来越多"**：从"离线整图"到"采样时局部"到"采样时局部 + 单一权重"。每一次都牺牲精度上限，换取"能不能真的装进引擎"。**而 PFT/NTC(512) 一直在这条线的上方——它们是"如果不管约束能做到多好"。**

## Relationships

### Based On

- **NTC（Vaidyanathan 等 2023）**：把解码搬进采样器的第一例；本文继承其"局部前向 + 随机访问"的架构，**放弃其"每资产拟合"**。
- **NTBC（Fujieda & Harada 2024，同组前作）**：本文作者自己的上一代，证明了"神经 + 硬件解码"这条路可行。

### Improves

- **解析上采样（双线性/双三次/Lanczos）**：同样可随机访问，但补不出高频。本文是"解析法的直接替换件"。

### Contrasts

- **PFT（Long 等 2025）**：同一任务、同一指标，**PFT 在每一行都赢**。差别不在精度，在"能不能在采样时跑"。
- **NTC**：省得更多，但需要每资产训练且会发散。**两者是"压缩率 vs 可部署性"的正面冲突。**

### Related

- **[[Level of Detail]]**（今日新建）：这是 LOD 的"第四种单位"——不是物体、顶点、簇，而是**单次采样**。
- **[[Streaming]]**：省显存 = 减轻流送压力；但 mip 与上采样的冲突未解。
- **[[Neural Rendering]]**：把神经网络放在"采样器"而不是"渲染器"里，是神经渲染最保守也最容易落地的一种位置。

### Followed By

- （尚无）通用模型 + 每资产轻量适配；以及**任何一篇补上运行时测量的后续工作**。

- **Normal**。为什么不是 Easy：机制（MLP + 采样器替换）不难，但**"为什么通用性比精度更重要"这一步**需要工程判断——它涉及 warp 发散、资产管线、离线工序三件事，是这一篇真正的内容。
- **Hard 部分（不必读）**：NTC 的潜网格 + PEPS 编码细节、BC 格式的块结构。**只需要知道"它们是每资产拟合、因而会发散"这一句。**

## Learning Value

1. **"接口成本 > 精度成本"**：PFT 全面更好，但没人能把它放进采样器。**评估任何新方法，先看它的接口形状。**
2. **"发散"是一个可以事先算出来的判据**：**网络权重的份数**决定要不要排序。这条可以直接用来筛"能不能上 GPU"。
3. **残差接解析基线，是让"小模型够用"的通用手法**：低频免费，网络只学残差。消融里 0.0796 → 0.0755。
4. **"通用"会隐藏一部分信息，但也会暴露一个能力**：跳过前向（因为输入是 texel）。**约束与能力常常是同一个设计决定的副产品。**

## Notes

- 作者单位：AMD（Shin Fujieda，东京；Takahiro Harada，Santa Clara）。**这是一篇产业侧论文**，与同批次的学术预印本不同——它的评价标准应该是"能不能进管线"，不是"刷不刷 SOTA"，本文自己也是这么写的。
- **未报的数字**（按重要性排）：① 每次采样的延迟/周期；② 帧率影响；③ 参数量；④ 显存带宽影响；⑤ 与 mip 共存时的误差。**这五项全空，所以"lightweight"目前是一个设计意图，不是测量结果。**
- **一处可交叉验证的口径**：作者说本文"大致相当于 NTC (256×256×3)"，而 NTC 那一档的潜网格是 $256^2\times3$——**与"2× 上采样、存半分辨率"在存储量级上确实可比**，这个对比是自洽的。
- **同日参照**：本批次另一篇前沿（[[2026-11-05-de Clermont Gallerande — REACT Real-Time Completion of Skeletal Motion Signals|REACT]]）把"决定权搬到消费点"做到了另一头（逐关节逐帧），但**它报了延迟（22–24 ms）**——两篇放在一起看，"报不报成本"本身就是可比的维度。
