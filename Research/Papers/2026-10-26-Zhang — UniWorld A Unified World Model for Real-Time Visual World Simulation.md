# UniWorld: A Unified World Model for Real-Time Visual World Simulation

## TL;DR

**它要解决的不是画质，是"接得上"**：一个上游世界源（驾驶录像 / 人体活动 / 物理模拟器 / 合成场景）不断吐几何，一个生成器不断把它画成照片。难点在**窗口接缝**——上一段生成的东西必须**逐比特不变**地进入下一段，而它依赖的深度条件也必须跟着一起保鲜。

两条机制：

1. **noise-aligned overlapping continuation**：把已生成的历史放在下一窗口的前缀里，并**在每个 flow 时间点把它对齐到当前采样噪声水平**（投影 $P_{i,t}$），每步数值更新后把前缀换回规定轨迹，只提交新后缀。投影是**幂等**的（$P_{i,t}(P_{i,t}(z))=P_{i,t}(z)$），所以历史**精确保持**；
2. **rolling depth latent state**：深度条件只读一次每个位置（`retain overlap` + `read new suffix`），活跃深度状态**上界与轨迹长度无关**——$M_{depth}\le 4L_{max}S\times96$ 字节，默认配置下 **19.050 MiB @ 960×544 / 9.413 MiB @ 672×384**。

实测：**14.472 FPS @ 960×544、21.361 FPS @ 672×384**（8×H100，FSDP/Ulysses，8 次采样评估），对 14 FPS 目标达标；缓存路径与在线路径**逐比特一致**（24/24 状态检查 + 3 组 PyBullet 分支）。

> 一句话对读者：**这篇的贡献几乎不体现在 PSNR 上——它的消融区间全部跨零。它买的不是画质，是"可验证"与"有界"。** 这个区分对你的预算工作比数字本身重要。

## Problem

连续视觉世界模拟要同时维持**两份历史**：生成出来的画面，和产生这些画面的几何条件。已有的长视频方法（StreamingT2V / FramePack / Diffusion Forcing / Self Forcing / LongVie）只处理第一份——它们没有"深度条件也必须与已提交画面严格对应"这个约束。

于是出现三类接缝病：

1. **历史被重写**：重叠窗口重新生成时，已提交的帧被"轻微改动"——单看不出来，连起来看是闪烁；
2. **噪声水平错配**：把干净历史直接塞进含噪状态，等于告诉模型"这段是干净的、那段是噪的"，模型会把接缝当成内容去解释；
3. **条件漂移**：深度按窗口重新读取时若相位/归一化不一致，几何与画面对不上，越走越偏。

```text
2025  LongVie / LongVie 2：统一噪声初始化 + 全局控制归一化
2026  Matrix-Game 4.0：把规则搬出模型（层次 2 的完成形态）
2026  UniWorld：把"历史"写成一份**可验证的状态契约**——不是更好的记忆，是**不会变的历史**
```

它的位置很特殊：**不与"更强的视频模型"竞争，而是给任何上游世界源提供一个"渲染半边"的规范接口**。

## Previous Work

- **长视频生成**：StreamingT2V（短/长时外观记忆）、FramePack（帧上下文压缩）、Diffusion Forcing（逐 token 噪声等级）、Self Forcing（训练-推理历史分布对齐）、RePaint（已知区域替换含噪观测）、LongVie / LongVie 2（统一噪声初始化 + 全局控制归一化）；
- **可控视频生成**：ControlNet / SparseCtrl / CameraCtrl、VideoX-Fun Union 控制分支；
- **世界模型**：Ha & Schmidhuber 2018、Genie、Astra（自回归去噪 + 噪声历史 + 动作适配器）。

**相对 LongVie 的增量**：LongVie 做的是"统一噪声初始化"（让所有窗口从同一个噪声场出发），UniWorld 做的是"**把历史当作每个 flow 时间点的边界条件**"——不只是初始化对齐，是**整条采样轨迹上都被钉住**。

## Core Idea

**历史不是"喂给模型的上下文"，是"采样过程的边界条件"。**

$$\mathcal{P}_{i,t}(z)=M_i\odot\big[tH_i+(1-t)\epsilon_i\big]+(1-M_i)\odot z$$

- $M_i$ 遮住前 $h_i$ 个潜位置（继承历史）；
- $H_i$ 是历史潜变量，$\epsilon_i$ 是**同一份全局噪声**在该窗口的切片（重叠位置用同一个噪声实现）；
- 于是历史前缀**跟着当前样本一起走同一条 noise→data 轨迹**，而不是以"干净值"的身份插进含噪状态。

**这带来三条可证性质**（附录 A）：

| 性质 | 内容 | 工程含义 |
|---|---|---|
| 幂等 | $P_{i,t}(P_{i,t}(z))=P_{i,t}(z)$ | 投影可反复施加，**不增加模型评估次数**（逐元素替换） |
| 终态还原 | $t=1$ 时前缀**精确等于** $H_i$ | 已提交历史逐比特不变 |
| 有界状态 | 深度活跃行 $\le 4L_{max}S\times96$ 字节 | **与轨迹长度无关**（19.05 MiB 恒定，30 s 与 120 s 一样） |

## Technical Approach

### 1) 统一接口：一切都变成"图像对齐的深度"

设源 $m$ 的状态 $\xi^{(m)}$ 与相机/对齐信息 $\kappa^{(m)}$，适配器 $A_m$ 产出可见深度，$N_m$ 标准化：$\bar D^{(m)}=N_m(A_m(\xi^{(m)},\kappa^{(m)}))$，再灰度复制到 RGB、VAE 后验众数 + FP32 归一化、$(1,2,2)$ patchify。

**为什么是深度而不是网格/白模**：深度是**所有世界源都能产出的最薄公共量**——录像能估、模拟器原生有、按需引擎能算。代价是丢掉了几何的拓扑与材质 id（对比 [[2026-10-21-Zhang — Matrix-Game 4.0 Harnessing Video Models for Real-Time Playable Game Worlds|Matrix-Game 4.0]] 的 low-poly 代理，那是"更厚"的接口：带物体 id、不带外观）。

### 2) 窗口几何：一串具体数字

| 层面 | 数值 |
|---|---|
| 像素窗口 / 重叠 / 步长 | $(W,O,\Delta)=(345,\,39,\,306)$ 帧 |
| 潜空间（VAE：$N=17n+5$ 像素帧 ↔ $F=5n+2$ 潜帧） | $(L_{max},h,\Delta)=(102,\,12,\,90)$ |
| 30 s 请求 | 内部补齐到 736 像素帧 / 217 潜帧，输出裁到 720 帧 |
| 三个窗口 | $[0,102),[90,192),[180,217)$ |
| 采样 | 8 次 flow 评估（DMD 蒸馏的 VDN-H3），shift 12/3，guidance 1 |

**注意"提交边界"与"交付边界"不是一回事**：潜空间提交在 345 / 651 帧，而增量 RGB 交付还要多留 **5 帧混合尾巴**（`[0,340),[340,646),[646,720)`）。这类"两套边界"是流式系统里最容易被忽略的一处账。

### 3) 滚动深度状态：每个位置只读一次

$$C_i=\text{concat}\big(C_{i-1}[a_i-a_{i-1}:L_{i-1}],\ \text{ReadDepth}(b_{i-1},b_i)\big)$$

并且**在每个窗口的 8 次评估中深度条件保持不变**（$C_i^{(0)}=\cdots=C_i^{(K-1)}=C_i$）——与视频历史不同，**深度不跟噪声水平走**，它始终是干净的 FP32 结构条件。

读取量对照：30/60/120 s 分别读 **217 / 427 / 852** 个位置，直接切片法要 **241 / 475 / 960**。省得不多（约 10–11%），**真正的收益是"每个全局深度位置只进入滚动状态一次"这条不变量**，以及由此得到的**上界证明**。

### 4) 训练的取舍

**没有联合训练**：直接用发布的 MiniMax-H3 ControlNet-Union（Union 分支接 50 个 H3 block 中的 5 个）+ DMD 蒸馏的 VDN-H3 8 步模型，只改"条件输入与生成历史如何跨窗口保留"。这在方法论上很重要——**它把"机制"与"模型能力"解耦了**，所以消融的净效应才能被单独测出来（也正因为如此，净效应很小）。

## Key Contribution

1. **把"历史保持"从工程 trick 提升为可证契约**：幂等投影 + 终态还原 + 有界状态，三条都能验；
2. **噪声对齐**：历史不是"干净地插进去"，而是"跟着当前噪声水平一起走"——这是接缝不闪的关键，也是最容易被抄错的一步；
3. **一份接口接四种源**：估计深度 / 原生模拟器深度 / 按需引擎深度，同一个 checkpoint；
4. **逐比特一致性**：缓存路径与在线路径输出完全相同（24/24 状态检查 + 3 组分支实验），使"重放"成为可用的调试手段。

## Why It Works

- **幂等投影 = 把"约束"变成"不变量"**：不需要损失项去惩罚历史漂移，历史在结构上就不可能漂；
- **深度只读一次 = 把"重复计算"变成"状态机"**：滚动状态不是缓存优化，是**语义定义**（每个位置在全局时间轴上只被引入一次）；
- **活跃状态与时长解耦**：所有随长度增长的东西都被挡在"已提交输出"之外，工作集只与窗口长度有关。

## Limitations

**论文自陈（也是全文最诚实的地方）**：

1. **消融几乎全是零效应**：固定窗口对照（表 3）里，`boundary RGB only` 与 `endpoint only` 的 PSNR 差 $+0.00637$ dB、区间 $[-0.0147,+0.0259]$ **跨零**；`direct global slice` 与 `aligned re-encoding` 精确为 **0.000**（恒等）；只有 seam LPIPS 有 $0.00195$ 的改善（区间 $[0.00033,0.00362]$ 不含零）。**换句话说：这套机制买不到可测的画质，它买的是"历史不变"这个性质本身。**
2. **绝对画质很低**：PSNR **13.3973 dB**（100 段 30 s），这是生成模型的正常量级，但不能当"重建质量"读；
3. **"实时"的计价单位是 8 张 H100**：14.472 FPS @ 960×544、21.361 @ 672×384，含 FSDP/Ulysses 通信；对游戏团队这就是**云渲染/离线档**，不是端侧；
4. 深度状态 19.05 MiB 只是**活跃深度行**，不含临时副本、融合后的条件特征、模型激活与上游几何源自己的存储。

**我补的两条**：

5. **它没有"玩法"**：与 MG4.0 / LiveAct 不同，这里没有动作接口、没有规则、没有可玩性——它是**渲染半边**，不是世界模型全部。把它归到 [[World Models for Games]] 的"层次 2"时要说清：**它拆的是"呈现"，不是"推演"**；
6. **驾驶/人体/模拟/合成四类的 PSNR 差异极大**（14.99 / 12.40 / 12.76 / 13.44），Simulation 类最差且 NMAE 最高（0.2524 vs 0.05–0.09）——**结构化场景（镜面、规则几何）是这类渲染器的弱项**，恰好是游戏场景的常见形态。

## Game Development Relevance

- **接口范式可直接搬**：如果你的引擎已经能出深度（延迟渲染的深度缓冲），那么"引擎出几何 + 模型出画面"这条路的**最小接口就是深度**，不必先做 low-poly 代理。代价是丢掉物体 id/材质（MG4.0 的代理能给，深度给不了）；
- **状态契约是可复用的工程模板**：`每个位置只读一次` + `提交边界与交付边界分离` + `缓存路径与在线路径逐比特一致`，这三条与渲染无关，**任何"分块流式"系统（地形分块、动画分块、粒子预算分帧）都适用**；
- **诚实边界对你的判断有用**：一套机制如果消融跨零，那它在项目里就**不该按"画质提升"立项**，只能按"可验证性/可调试性"立项。这条判据能挡掉很多"论文很好但我们用不上"的误判。

## Unreal Engine Relevance

- **不能进运行时**（8×H100）。可行落点是**离线预览 / 概念视频生成**：给一个相机轨迹 + 场景深度序列，生成"看起来像最终品质"的过场；
- **可借的是"两套边界"的工程思想**：UE 的 World Partition / 关卡流送同样有"提交粒度 ≠ 交付粒度"的问题（streaming cell 提交 vs 渲染可见），UniWorld 把这件事写成了显式契约；
- **与 MegaLights / Lumen 无关**：它不参与光照求解，是"整帧生成"。
