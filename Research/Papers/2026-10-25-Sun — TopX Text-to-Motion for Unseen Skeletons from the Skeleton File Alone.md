# TopX —— 骨架文件就是接口

> University of Southampton × Nanjing University × MOGO AI，`2610.34321`（v1 10-25 / v2 10-28），18 页。
> **一句话**：一个新角色到手时，**你只有它的骨架文件**——没有动作片段、没有模板、没时间重定向、更不会为它微调。TopX 把"骨架文件"本身当成模型接口：树、静止姿态、关节名进去，关节旋转 + 根轨迹出来，**4 到 117 个关节共用一个 73M 的模型**。

## TL;DR

- **它要解决的不是"生成得好不好"，是"这套模型能不能对一个从未见过的骨架工作"**——而之前的做法（重定向 / 模板 / 逐骨架统计归一化）都要求"先有目标骨架的动作"，这在逻辑上先有鸡还是先有蛋；
- **三个设计决定各对应一个"任意性"**：**归一化**用静止姿态与骨架尺寸（治"没有动作统计"）、**世界系描述子**用骨骼的世界方向与相对根的位置（治"每个关节的 rest frame 朝哪是作者随便定的"）、**HK-RoPE**（治"关节顺序与拉普拉斯特征基也是随便定的"）；
- **HK-RoPE 的核心是一句线性代数**：热核签名 $h_j(\tau)=\sum_{k\ge1}e^{-\tau\lambda_k}v_{kj}^2$ 里的 $v_{kj}^2$ 在特征空间里求和后 = **投影算子对角元**，与基的选取、符号、重根都无关。**所以它不需要 SignNet，也不需要担心"截断把重根劈开"**；
- **这条不是理论洁癖**：作者统计 **5,127 个训练骨架里有 3,210 个（63%）在前 8 个非平凡模态内出现重根**——重根不是边角情况，是常态；
- **成绩要分开读**：held-out 游戏物种上 KIDdesc **0.127 vs 真值自身的 0.124**（几乎重合），文本检索 R@1 **0.953 vs 真动作 0.929**；但 **OOD-tree 1.78 vs 真值 0.142**、**OOD-new-species 91.5 vs 104（速度只有真值的 0.19）**——**"同科不同种"它能过，"全新体型"它还没过**；
- **最值得记的一处**：UniMate 的两把尺子（FIDkin / FIDdesc）**各有各的最优 guidance（7 / 3）**，而 TopX **两把尺子的最优点是同一个（2）**。**调参不再是一个取舍——这本身就是"表示找对了"的信号。**

## Problem

游戏、影视、虚拟制片里，"角色"是一个**大阵容**：每个角色有自己的一套骨架——**关节数不同、关节顺序不同、rest pose 朝向不同、命名习惯不同**。而文本到动作的模型几乎全部假设**一个骨架**：关节数、顺序、rest pose 都焊在模型里。

想让它对新手工作，常见的四条路各缺一块：

| 做法 | 缺的那块 |
|---|---|
| **重定向**（retargeting） | 需要**源动作**，而新角色没有任何动作 |
| **模板模型**（SMAL / 统一 30 关节 / 共享拓扑） | 超出模板的骨架**表示不了** |
| **逐骨架统计归一化**（AnyTop 一系） | 需要**目标骨架自己的动作统计**——又回到"先有动作" |
| **微调** | 每个新角色都要训一遍，产线上不可能 |

**所以真正的约束是：模型只能看"骨架文件"本身**——树、rest pose、关节名。这三样东西的性质决定了难点：

1. **尺度**：没有动作 ⇒ 不知道这个角色的动作幅度、每个通道的分布 ⇒ **不能用逐骨架统计做归一化**；
2. **约定**：关节的**排列顺序**、**命名**、**每个关节 rest frame 的朝向**都是绑定师的自由选择 ⇒ **输出不该依赖它们**；
3. **形状**：树本身可能就在训练分布之外（新拓扑、更多关节、陌生体型）。

## Historical Context

动画线在库里已经从"检索"走到"生成"，但**"骨架"一直是那个被默认的东西**：

```text

2025  CAST / PriMoRetarget       骨架 = 要**适配**的对象（拓扑感知、优先级重定向）
2026  UniMate                    骨架 = 要**泛化到**的对象（谱编码 + 零样本）
2026  ★ TopX                     骨架 = **接口**（树 + rest pose + 名字，直接吃）
        ↓
      "从'适配骨架'到'骨架即接口'——变的不只是方法，是问题的提法"
```

[[Skeletal Animation]] 这个概念页一直缺一个"骨架作为数据结构"的锚点，TopX 正好补上：**它把骨架的三件任意性（顺序 / 朝向 / 命名）逐条消掉，剩下的才是可迁移的结构**。

## Previous Work

- **人体 text-to-motion**：MDM / MLD / T2M-GPT / MotionDiffuse 一系，全部固定骨架；
- **动物 / 多物种**：SMAL 模板、共享拓扑、统一 30 关节——**换个物种就出界**；
- **任意骨架**：**AnyTop**（无文本条件、用自身动作统计归一化）、**UniMate**（谱编码 + SignNet + rest-pose rebasing，零样本）——TopX 的直接对手；
- **图上的位置编码**：拉普拉斯特征向量（符号与重根基不唯一，需要 SignNet 消歧）、随机游走签名、热核签名（**本文用的这个**）、WIRE（把谱坐标当旋转角）。

## Core Idea

> **别把骨架"翻译"成模型认识的形状；把模型改成能直接吃骨架的形状。**

具体到三处：

| 任意性 | 常规做法 | TopX 的做法 |
|---|---|---|
| 尺度（没有动作统计） | 用该骨架动作的均值/方差归一化 | 用**rest pose 中心 + 骨架尺寸**归一化（$s$ = rest pose 包围盒对角线） |
| rest frame 朝向 | 用父坐标系下的偏移（**依赖作者的朝向选择**） | 用**世界系描述子**（骨骼的世界方向 + 相对根的地面点的位置，按平均骨长归一化并 log 压缩） |
| 关节顺序 / 特征基 | 学习式位置表，或谱编码 + SignNet | **HK-RoPE**：热核签名 → MLP → 旋转角，**与顺序、符号、基、重根全无关** |

## Technical Approach

### 1. 表示：每帧每关节 17 个通道，全部"rest pose 下为零"

一个所有骨架共用的表示必须满足两条：**能从树 + rest pose + 动作算出来**（不需要模板/重定向/IK）；**每个通道在每个骨架上含义相同**。于是每个关节每帧 = 17 通道：位置（水平坐标相对平滑地面轨迹、高度绝对）、**相对 rest 朝向的全局旋转（6D 连续表示，rest 时为单位阵）**、世界速度（只作监督）、二值接触标志；根节点再加地面轨迹与朝向。

$$\tilde x_{fjc}=\frac{x_{fjc}-x^{\text{rest}}_{jc}}{\sigma_c},\qquad \sigma_c=s/g_c$$

**这个归一化的漂亮处**：rest pose 在 17 个通道里**恒为零**（rest 位置、单位旋转、零速度、零接触）——于是模型学的永远是**"相对自己 rest pose 的位移"**，而不是某个绝对坐标系里的量。

### 2. 每关节三个特征，各治一种"任意"

1. **一句文本描述**（"left thigh joint"），用冻结的 **LLM2Vec** 编码。"front left upper leg" 在马和蜥蜴身上指同一个概念，而 `L_Femur_02` / `b_hindleg_l_1` 不是；
2. **结构向量**：相对父节点的 rest 偏移（父坐标系下）、骨长、深度、到根的路径长、子节点数、是否叶子——过一个零初始化 MLP；
3. **世界系 rest 描述子**：骨骼在**世界系**里的方向 + 相对根地面点的位置（按平均骨长归一、log 压缩）。

**注意 (2) 与 (3) 的分工**：父坐标系偏移依赖"作者怎么摆这个关节的 rest frame"，世界系描述子不依赖。**作者原话是：把 rest pose 传给网络的，是 (3) 不是 (2)。**

### 3. HK-RoPE：把"树上的位置"变成"旋转角"

$$\mathcal L=I-D^{-1/2}AD^{-1/2},\quad (\lambda_k,v_k)$$
$$h_j(\tau)=\sum_{k=1}^{J-1}e^{-\tau\lambda_k}v_{kj}^2,\qquad \tilde h_j(\tau)=\frac{h_j(\tau)}{\frac1J\sum_i h_i(\tau)},\qquad \tau_i=2^{i-2},i=0..7$$
$$\ell_{ij}=\frac{q_i^\top R(\theta_j-\theta_i)k_j}{\sqrt{d_h}}+b_{ij},\qquad b_{ij}=-\min(g_{ij},8)+u_{a_{ij}}+d_{s_{ij}}$$

三个性质逐条对上三个要求：

- **每个树都有定义** ⇒ 任意拓扑可用；
- **8 个值，与关节数无关** ⇒ 一个模型吃 4–117 个关节（**所有 $J-1$ 个非平凡模态都参与求和，不需要截断或补齐**）；
- **与特征基无关** ⇒ 因为 $v_{kj}^2$ 在一个特征空间上求和 = **该空间投影算子的对角元**，换基、换符号都不变；重根被"截断劈开"也不影响（和是跨整个空间算的）。

**这条不是小事**：UniMate 用谱编码 + SignNet 处理符号歧义，但**重根内部的基选取歧义**与**截断劈开特征空间带来的歧义**它没有覆盖。作者统计：**3,210 / 5,127（63%）的训练骨架在前 8 个非平凡模态内（或第 8 与第 9 之间）出现重根**。

### 4. 双轴分解注意力 + 帧轴 RoPE

一个动作是"关节 × 帧"的网格，但两个轴性质不同（关节是树、帧是序列）：每个 block 先**跨帧** attention（同一关节），再**跨关节** attention（同一帧），再 MLP。帧轴用标准 RoPE（$\theta_f=f\omega$，$\omega_m=700^{-2m/d_h}$），关节轴用 HK-RoPE。**两个轴都没有学习式绝对位置表**。

### 5. SkelShift：把"泛化"拆成五条可测的轴

四个动作语料统一成一个 codec：**143,334 条带字幕片段、骨架 4–142 关节、每个关节都有文字描述**。测试按**五种骨架偏移**分桶：拓扑（ID-tree / OOD-tree）、关节数（OOD-J>60，如 Mixamo 65）、体型（OOD-plan）、物种（OOD-species / OOD-new-species）、绑定来源（OOD-rig）。**每个测试树到训练树的距离都要报告**——这是"泛化"能被讨论的前提。

**而且它不用学习式评估器打分**：作者的理由很硬——学习式 text-motion 评估器一出土著分布就掉分，用它给"分布外的动作"打分等于让裁判也出界。**改用无评估器的统计量（KID / FID 在运动学描述子上）。**

## Key Contribution

1. **一个"只吃骨架文件"的 text-to-motion 模型**：73.3M 参数、10 block、flow matching，覆盖 4–117 关节、最长 240 帧；
2. **HK-RoPE**：一个对任意树有定义、对关节重标号不变、对特征基不变、维度固定的图上位置编码；
3. **SkelShift**：把"未见骨架"拆成五条轴，并且**报告每个测试树的距离**；
4. **一次诚实的对比**：与 UniMate 同数据同预算训练，把"两把尺子各有最优 guidance"这件事摆到台面上。

## Why It Works

**因为它把"泛化"从"模型容量问题"改写成了"接口设计问题"。**

一个 73M 的模型不可能"记住"上千种骨架。它能做的只有一件事：**把不同骨架映射到同一个坐标系里**，让"抬左前腿"在蜥蜴、马、蜘蛛上是同一个操作。三处设计都在做这个映射：

- rest-pose 归一化 ⇒ **尺度**被消掉；
- 世界系描述子 ⇒ **朝向约定**被消掉；
- HK-RoPE ⇒ **顺序与基**被消掉。

**剩下的就是"结构"本身**——而结构正是可以从骨架文件里读出来的东西。

## Limitations

作者自述 + 我补：

1. **真正的新体型仍然不行**：OOD-new-species 的 KIDdesc **91.5**（真值 104），**速度只有真值的 0.19**——动作**偏慢偏小**，说明它把"没见过的体型该动多快"估错了；
2. **OOD-tree 仍远离真值**：1.78 vs 0.142；
3. **消融的幅度小，要小心解读**：满模型 1.78，换成学习式帧表 1.88、学习式关节表 1.87、特征向量 + SignNet 1.83、去掉增广 1.95。**也就是说"换掉 HK-RoPE"只贵 0.05——而离真值还差 1.64。** 真正的贡献是"**整个接口设计**"，不是某一个编码；
4. **（补）held-out 物种那一栏只有 6 个 rig**（原文用 ∗ 标注"少于 20 rig"）。**0.127 vs 0.124 这句话的说服力，受这一栏的样本量限制**；
5. **（补）没有风格、没有速度、没有地面约束的显式控制**——它是"文本 → 动作"，不是"文本 + 参数 → 动作"。

## Game Development Relevance

- **直接对上"新角色到手"的场景**：外包交来的角色通常只有 rig，没有动画；现在的流程是"找相似角色 → 重定向 → 手修"。**TopX 的承诺是"把这一步换成一次前向"**——哪怕只用来出**初稿**，也能把绑定师的起点从零帧挪到 60%；
- **它把"骨架"从资产变成了接口**：这对**批量 NPC**（几十个不同体型的杂兵）、**怪物变体**（同科不同种）最有用。**反过来说：真正全新的 Boss 体型，现在还不能指望它**；
- **SkelShift 的评估思路可以搬到项目里**：不要只报"平均质量"，要按**偏移类型分桶**（新拓扑 / 新关节数 / 新体型 / 新绑定来源）分别报。**否则一个"同科"的好成绩会掩盖"跨科"的崩**；
- **对 VFX 的间接意义**：技能动作如果能按骨架生成，那么"每个新角色的技能起手/收招"就不再是逐角色手工对齐——**但现在只到"能动的初稿"，没到"能进战斗的时序"**。

## Unreal Engine Relevance

- **Control Rig / IK Retargeter**：TopX 的输出是**关节旋转 + 根轨迹**，正好是 Control Rig 的输入格式——**它替代的是 Retargeter 的上游（"没有源动作"那一步），不是 Retargeter 本身**；
- **骨骼命名**：它用 LLM2Vec 编码"关节描述"来跨骨架对齐语义，这对 UE 的 **Retarget Chain 命名约定**是一个可借鉴的思路——**别要求项目统一命名，而是把命名当特征**；
- **Anim Blueprint**：输出是逐帧的（不积分速度、无漂移），可以直接进 Montage；**但 240 帧上限与没有 root motion 曲线编辑，意味着它现在只能当"草稿层"**。

## Learning Value

- **一条可迁移的判据**：*判断一个"泛化"方案行不行，先问它消掉的是"约定"还是"结构"。* 顺序、命名、坐标朝向是约定，可以消；关节数、树形、骨长比例是结构，消不掉也不该消；
- **一条更值钱的判据（今天新得）**：**"一个旋钮需不需要为两个指标各调一次"，是表示有没有找对的信号。** UniMate 的 guidance 在 FIDkin 下最优 7、在 FIDdesc 下最优 3——**它必须在"像"和"自然"之间选**；TopX 两个指标的最优点都是 2。**当表示对了，调参就不再是取舍。** 这条可以直接拿去审任何"两难旋钮"。

**读图**：左上 ❶ 是全部输入——**一棵树、一个 rest pose、一串关节名，没有动作片段**（"No motion clips" 那几个字是全文的立场声明）。中间是 transformer：**十层，每层先做 temporal attention（$\theta_f=f\omega$）再做 spatial attention（$\theta_j$，来自 HK-RoPE）**，文本与 flow time 走 AdaLN。左下 ❷ 是今天最该看的一张图：**同一套配色（core → ends）在剑龙（40 关节）、人（22）、蜘蛛（61）三副骨架上给出相同的结构位置**——颜色是热核签名第一主成分的 log 值。**注意三副骨架的关节数完全不同，但颜色分布是同构的**：这就是"8 个标量概括一棵树"的字面样子。右侧是同一个文本在剑龙上生成的 0.0 / 1.8 / 3.6 s 三帧。（图 1，Sun et al. 2026）

## Notes

**关键数字对照（都是同数据同预算）**

| 指标 | TopX | UniMate | 真值参照 |
|---|---|---|---|
| FIDdesc（↓） | **4.83** | 6.06（按 FIDkin 调）/ 4.32（按 FIDdesc 调） | 0.48（真-真） |
| FIDkin（↓） | **2.00** | 2.05 / 2.52 | — |
| 穿透帧占比（↓） | **0.24** | 0.33 / 0.28 | 0（真值） |
| 已发布权重：两个 held-out 物种 FIDdesc | **1.19** | 3.32 | AnyTop 24.63 |

**"两把尺子"那张表要横着读**：UniMate 一列在 FIDkin 下调到 2.05，代价是 FIDdesc 6.06；换成按 FIDdesc 调，FIDdesc 降到 4.32，FIDkin 涨到 2.52。**它的两个指标是此消彼长的**。TopX 两列都是 4.83 / 2.00——**同一个点**。

**一处必须记住的诚实**：held-out 游戏物种的 KIDdesc **0.127 vs 真-真 0.124** 这句话很漂亮，但那一栏只有 **6 个 rig / 635 条片段**。**样本量决定了这句话的边界**——它说明"同科不同种"能过，不说明"任意新物种"能过（OOD-new-species 那栏 91.5 就是反例）。
