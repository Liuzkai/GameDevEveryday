# Honeycomb-Surfels: Compact Hexagonal Primitives for Efficient Scene Rendering and Reconstruction

## TL;DR

**"一个原语能代表多少东西"是可以被设计的，而不只是被优化的。**

3DGS 家族的原语是**一个视角相关颜色 + 一个各向异性高斯支撑域**，于是"空间上的颜色变化"只能靠**很多个原语叠出来**——叠出来的东西就是 overdraw。另一条路（BBSplat 的逐原语纹理、NeST/Nexels 的共享神经外观场）把容量加进去了，但**把复杂度搬到了纹理、网格或解码器上**。

Hexels 的选择是：**把容量加在原语自己身上**，两个改动——

1. **支撑域换成六边形**（带柔边的平面片，$K=\sigma(-\beta\, d(u,v))$）；
2. **颜色场升到一阶**（$c^{sp}(u,v)=c_0+u\,g_u+v\,g_v$，每个原语 20 个可学参数）。

在**同模型内存**下（作者的主战场），对 2DGS 提升 **+4.53 / +6.99 / +7.38 dB**（Tanks and Temples / Mip-NeRF360 / DTU），同时训练显存最多省 **3.6×**、渲染快 **1.54–1.87×**。

但今天真正值得记的是那张 **2×2 消融**（形状 × 颜色场），因为它把两笔账拆开了：

| 平滑着色目标（256 原语） | 常数色 | 一阶色场 | 增益 |
|---|---|---|---|
| **高斯支撑** | 31.33 dB | 35.13 dB | **+3.80**（颜色场买的） |
| **六边形支撑** | 35.62 dB | **37.07 dB** | **+1.45** |
| 增益 | **+4.29**（形状买的） | +1.94 | — |

**两个改动不是相加的**：$31.33+3.80+4.29=39.42 \ne 37.07$——**它们各自都在提高"单个原语能表达多少"，所以互相替代**。而 **overdraw 那条线是纯形状效应**：高斯 9.82/10.47 → 六边形 2.80/2.48 blends/px，**掉了 3.5–4.2 倍，与颜色场几乎无关**。

> 一句话对读者：**颜色场买"表达量"，六边形买"覆盖次数"。** 这是两个不同的预算，别指望一个改动同时解决。

## Problem

表面原生（surface-aligned）原语这条线，从 2DGS 到 Triangle Splatting 到 MeshSplatting，几何形式各不相同，但**面对同一个问题**：

> "一个原语能代表场景的多少，代价是多少？"

原文把这句话直接写在引言里。而当时的答案分两类：

- **每原语一个视角相关颜色**（3DGS / 2DGS / triangle splat）：空间变化靠**多原语重叠**产生 ⇒ **overdraw 大**；
- **每原语带纹理 / 神经外观场**（BBSplat / NeST / Nexels）：单原语容量大 ⇒ 但复杂度搬进了**纹理图、特征网格或解码器**。

Hexels 的目标是第三条：**在原语内部解决，不引入任何外部结构**。这与"自然场景大片区是局部平面 + 平滑渐变"这个先验直接对应——**该用一个大的原语去覆盖它，而不是用一百个小的去拟合它**。

## Historical Context

```text
2000  Pfister 等《Surfels》——点不再是点，是"带形状、带法向、带颜色的面元"
2001  ★ Zwicker 等《Surface Splatting》——**EWA 滤波的屏幕空间形式**，splat 的支撑域由此有了严格定义
2002  Zwicker 等《EWA Splatting》——把重建与带限统一成一个椭圆核（[[Zwicker — Surface Splatting (2001)]] 的直接后继）
2007  QSplat / 点云渲染成熟：LOD + 层次结构，但"每个点是常数色"
2023  3DGS：各向异性高斯 + 视角相关 SH —— **可微、可实时，但支撑域是椭圆**
2024  2DGS：把高斯压成面元（surfel），改善几何 —— **支撑域仍是椭圆/圆**
2025  Triangle Splatting / MeshSplatting：换成三角形 —— **支撑域变成多边形，但每片仍是常数色或顶点插值**
2026  ★ Hexels：**六边形支撑 + 一阶颜色场** —— 支撑域形状第一次成为被设计的一等公民
```

**它的历史位置**：2001 年 EWA 回答了"**滤波器该长什么样**"（由投影几何**推导**出椭圆），2026 年 Hexels 回答了"**支撑域该长什么样**"（由铺砌经济学**设计**出六边形）。**前者是导出的，后者是选的**——这个区别很关键：椭圆是圆核投影的必然结果，六边形不是任何东西的投影，它是"同周长下面积最大"这个优化问题的解。

## Core Idea

**先问"什么样的形状能最少次数地覆盖一块区域"，再问"一个原语内部能有多少变化"。**

为什么是六边形，原文给了两句话、一条定理、一个命题：

- **蜂窝定理（Hales 2001）**：正六边形无缝铺满平面，且在等面积下**周长最小**（比正三角形和正方形都小）；
- **命题 G.2（本文附录）**：在局部一阶近似模型下，一个合适朝向、各向异性缩放的六边形，在**同样的颜色误差上界**内，能覆盖比对应正方形**多约 30%** 的面积、比对应三角形**多一倍**的面积。

**"周长最小"为什么重要？** 因为 splat 的代价不在"面积"上，在**边界**上——每一片柔边都要在边界附近做混合，边界越长、混合的像素越多、overdraw 越高。**六边形是"用最少的边围住最多的面"的解。**

## Technical Approach

### 1) 原语定义

一个 Hexel 是**平面上的六边形片**，参数（V1 共 20 个可学量）：

| 参数 | 含义 |
|---|---|
| $\mathbf p$ | 中心 |
| $\mathbf t_u,\mathbf t_v$ + 尺度 $s_u,s_v$ | 切平面上的两个方向与各向异性缩放 |
| $\mathbf n$ | 法向 |
| $\mathbf c_0$ | 基色（RGB） |
| $\mathbf g_u,\mathbf g_v$ | 沿两个局部坐标的**颜色梯度**（RGB 各一组） |
| $\beta$ | **边界锐度** |

空间权重：$K(u,v)=\sigma\!\left(-\beta\cdot d(u,v)\right)$，$d$ 是六边形距离（到六条边的**最大值**，而不是欧氏距离——这是"六边形"真正进入数学的地方）。$\beta$ 大则边界硬、小则软边。

颜色场：$\mathbf c^{sp}(u,v)=\mathbf c_0+u\,\mathbf g_u+v\,\mathbf g_v$。

**注意 $\beta$ 是每原语可学的**：这意味着模型可以自己决定"这一片该硬边（贴边界/贴细节）还是软边（大平面）"。**这是支撑域形状之外的第二个自由度，原文没在摘要里强调，但它是"大原语覆盖大平面"能成立的前提**——一块 2 米见方的片如果边界是硬的，接缝会非常明显。

### 2) 渲染

**透视正确的射线—平面求交 + 深度序混合**。没有 tile-based 光栅化之外的技巧，也没有解码器。

### 3) 与 EWA 的关系（本库读法）

把 [[Zwicker — Surface Splatting (2001)]] 的屏幕空间 EWA 核拿过来对照：

$$\rho_k(\mathbf x)=\frac{1}{|J|}\,G_{\,J V_k J^\top + I}\!\left(\mathbf x-m(\mathbf u_k)\right)$$

Hexels 的核是 $\sigma(-\beta d)$——**不是高斯的，是六边形距离上的 sigmoid**。两者在做同一件事（"一个原语在屏幕上覆盖多大、边缘怎么衰减"），但：

| | EWA（2001） | Hexels（2026） |
|---|---|---|
| 支撑形状 | **椭圆**（圆核投影的必然结果） | **六边形**（铺砌优化问题的解） |
| 形状从哪来 | **推导**（雅可比 $J$） | **选择**（等周长下面积最大） |
| 边缘衰减 | 高斯（无界，靠 cutoff 截断） | sigmoid（**有界**，$\beta$ 控锐度） |
| 原语内部变化 | 常数（变化靠纹理或重叠） | **一阶线性**（$c_0+ug_u+vg_v$） |
| 带限怎么来 | 核里那个 $+I$（显式低通） | **没有显式带限**——靠 $\beta$ 与最小尺度隐式控制 |

最后一行是它的**理论欠账**：EWA 的 $+I$ 是对"像素是有限面积"这件事的严格补偿；Hexels 没有对应项，**它靠"训练时学到合适的 $\beta$ 与尺度"来避免走样**。这在离线重建里可行（训练目标会惩罚走样），但在**任意视角、任意分辨率**下没有保证——**这也是它没解决 minification 的理论问题的证据之一**（原文只报了训练视角附近的指标）。

## Key Contribution

1. **把"支撑域形状"变成一等设计变量**，并给出一个可判定的选择理由（蜂窝定理 + 命题 G.2）；
2. **一阶颜色场**：用 6 个额外参数（两组 RGB 梯度）换掉"多原语重叠"；
3. **一组干净的 2×2 消融**，把"形状"与"表达"两笔账拆开；
4. **同内存设置下对 2DGS 的 4.53–7.38 dB 提升**，并给出"原语自身携带全部信息、无外部结构"的完整实现。

## Why It Works

**因为它同时压低了两个不同的量，而这两个量恰好是同一个几何事实的两面。**

- **overdraw ↓**：按面积/周长比，六边形用更短的边界围住同样的面积 ⇒ 边界附近的混合像素变少 ⇒ blends/pixel 从 10.47 掉到 2.48；
- **每原语表达量 ↑**：一阶色场让"平面上的线性渐变"由**一个**原语承担，而不是由"两个常数色原语 + 混合"承担。

**而这两件事在数学上是耦合的**——这也解释了为什么消融不是相加的：**你少叠的那一层，本来也在提供渐变**。一旦原语自己能提供渐变，就少需要一层；反过来，一旦原语覆盖面积大了，渐变的跨度也变大了。

## Limitations

- **高频/无纹理表达不了**。一阶场只能表达线性变化；高频纹理要么切小原语、要么换更富的颜色模型（V2/V3 就是往这个方向走的），**而一旦切小，"少而大"的优势就消失了**。
- **优势高度依赖"同内存"这个比较基准**。放开约束后（Table 4）：
  - Mip-NeRF360 上只**领先 2DGS 0.30 dB 以内**；
  - DTU 与 T&T 上 +0.90 dB；
  - **BBSplat 在 DTU 上仍高 0.50 dB**，**3D Convex Splatting 在 T&T 上高 0.27 dB**；
  - **T&T 的部署内存反而更差**（198.84 MB vs 2DGS 177.56 MB）。
  **换句话说：这是一篇"效率论文"，它的优势在效率受限时才显形。**
- **2DGS 作为主对手偏弱**。Mip-NeRF360 是无界场景，2DGS 在那里本来就吃亏（同内存下 17.82 dB，比 3DGS 的 20.46 低 2.64 dB）。**"对 2DGS +7.38 dB"里有相当一部分是"2DGS 不适合这个数据集"。**
- **纯静态、纯离线**。没有动态场景、没有时序一致性、没有引擎集成；训练时长在 8–24 分钟（Table 2 "min" 列）。
- **理论与实验之间有一处缝**：命题 G.2 是"局部一阶近似下、同样颜色误差上界内"的结论，而实测是端到端 PSNR——**这两者之间的桥是作者假设的，不是证明的**。

## Game Development Relevance

- **它是"LOD 该按什么降"的一个新答案**。传统 LOD 降的是**三角形数**；Hexels 提示可以降**原语数**同时**升每原语表达量**——即"少而聪明"，而不是"少而粗糙"。这对**远景/大场景**（UE 的 Nanite 之外那条路）有直接参考价值。
- **overdraw 那个 3.5–4.2× 是可用的数字**。如果你的场景里半透明片（植被、粒子、特效）很多，那么"把圆片换成六边形片"在**同样的覆盖面积**下能少掉约四分之三的混合次数——这个结论对 **Niagara 的 sprite 渲染**同样成立（sprite 是四边形，四边形的面积/周长比还不如六边形）。
- **不要把它当成"GS 的替代品"**：它没有动态、没有引擎集成、没有 minification 保证。**它是一个"原语设计"的方法论样本。**

## Unreal Engine Relevance

- **Niagara sprite / mesh particle**：sprite 目前是四边形（两张三角形）。**四边形在同面积下周长比六边形长 ~7%**（正方形 4√A vs 六边形 ≈3.72√A）。这个差距不大，但它指向一个可试的方向：**用六边形/圆形的软边 mask 代替方形 sprite，在同样覆盖率下减少 overdraw**。
- **Nanite / Virtual Geometry**：Nanite 的 cluster 是三角形簇；Hexels 的"少而大"思路在**极远景**（cluster 已经很小的尺度）上等价于"用更少的 cluster 覆盖更大的面"——**但 Nanite 的约束是几何精度，不是外观表达**，所以这条迁移不直接。
- **不适用**：本文没有时序、没有蒙皮、没有 LOD 切换策略。

## Technology Evolution

```text
"原语是什么"
2000  Surfels：点 + 形状 + 法向 + 颜色（Pfister）
2001  Surface Splatting：**支撑域由投影几何导出**（EWA 椭圆，含带限项 +I）
2002  EWA Splatting：重建与带限统一，抗锯齿成为核的性质而非后处理
2023  3DGS：可微 + 实时，支撑域仍是椭圆，容量仍在"每原语一个色"
2024  2DGS：压成面元，几何变好，容量不变
2025  Triangle Splatting / MeshSplatting：换成多边形，**容量仍不变**
2026  ★ Hexels：**支撑域形状 + 原语内颜色场同时设计** —— 容量第一次进到原语里
        ↑ 代价：没有 EWA 那个 +I，minification 的理论保证丢了
```

**这条线的方向**：从"**原语是一个采样点**"到"**原语是一小块曲面片**"。3DGS 把点变成了高斯团，2DGS 把高斯团压成片，Hexels 把片变成"有内部结构的片"。**每一步都在问同一个问题：一个原语到底该承担多少？**

## Learning Value

- **对 TA**：`blends/pixel` 这个指标可以直接借。你现在的 overdraw 判据是 $\sum A_i/A_{screen}$（面积比），**它假设每个片只贡献一次**；Hexels 报的是**每个像素实际被混合多少次**，这才是填充率的真成本。
- **对架构**：这是一篇"**把容量放对地方**"的论文——它没有让原语变多，也没有让网络变大，只让**每个原语多承担一点**。
- **对评审**：任何"同 X 对比我们高 N dB"的说法，都要先问 **X 是什么**。同内存、同原语数、同训练时间、同推理 FPS——**四个基准给出四张不同的排名表**。

## Notes

- **证据形态**：一手 PDF（arXiv 2610.37668v1，35 页含 15 页附录），**未经同行评审**；代码与项目页均已公开。
- **一组"必须两个方向读"的数字**（本库整理，非原文表述）：同一批方法在两张表里的名次不同——

  | 数据集（Mip-NeRF360） | 同内存 | 同原语数 |
  |---|---|---|
  | 3DGS | 20.46 | **23.38** |
  | 2DGS | 17.82 | 21.65 |
  | Triangle Splatting | 22.36 | **24.73** |
  | Hexels | **24.82** | （V3 优于全部） |

  2DGS 与 3DGS 的差距从 **−2.64 dB** 缩到 **−1.73 dB**——**不是方法变了，是分母变了**。**任何"同预算对比"都必须先声明预算是什么。**
- **"4.53–7.38 dB"这个区间的来源**：T&T +4.53、Mip-NeRF360 +6.99、DTU +7.38。三个数据集差异很大，而 **T&T 是最接近"游戏资产"的那个，也恰好是最低的那个**——引用时别只引上限。
- **一处未展开的疑点**：原文说 "Hexels V1/V2 provide compact alternatives, while V3 uses a richer appearance model with a larger per-primitive memory cost"，但 Table 2 只报了 V1、Table 3/4 才出现 V3。**V1 与 V3 的差别（颜色模型阶数？参数个数？）在正文里没有一处完整定义**——这是复现时会卡住的地方。
