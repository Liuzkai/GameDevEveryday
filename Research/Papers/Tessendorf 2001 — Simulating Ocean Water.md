# Tessendorf — Simulating Ocean Water (2001)

## TL;DR

**海面不需要"解"出来，它可以被"抽样"出来。** 这篇 2001 年的 SIGGRAPH 课程笔记给了游戏与影视工业**唯一被普遍采用的水面算法**：

1. 把海面看成**一堆不同波长、不同方向的 sinusoid 的叠加**，每个波的频率由**色散关系** $\omega=\sqrt{gk}$ 决定（深水）；
2. 不去解 Navier-Stokes，而是**按实测的海浪功率谱（Phillips 谱）随机的给出每个波分量的复数振幅**，于是整个高度场在**频域**被"造"出来；
3. 每一帧的演化只是**给每个分量乘一个相位** $e^{i\omega t}$，再用**一次 2D IFFT** 变回空间域——$O(N^2\log N)$；
4. 想要"尖"的波，就在水平方向加一个**位移** $x\to x+\lambda D(x,t)$（Creamer 变换），顶点被挤向波峰 → 波峰变尖、波谷变平；
5. 位移过度会**自交**，而**Jacobian $J<0$ 就是"这里折叠了"的判据**——顺手变成**泡沫/浪花**的遮罩。

> 一句话对读者：**这条路线把"物理正确"换成了"统计正确 + 可控成本"**——海面看起来对，但每一帧的成本只与**网格分辨率**有关，与"海里有多少物体、水面有多复杂"无关。

## Problem

1990 年代末，CG 水面有三条路，各有硬边界：

| 路线 | 框架 | 强项 | 死穴 |
|---|---|---|---|
| **CFD**（Stam 1999、Foster-Metaxas） | Eulerian（网格） | 物理正确、可做浅滩破浪 | **网格点数爆炸**：算得了一个海湾，就算不了浪花尺度的细节 |
| **SPH** | Lagrangian（粒子） | 飞溅、破碎、爆炸 | 表面重建贵；大范围平静海面很浪费 |
| **本文：表面现象学** | 只算**水面** | 极大范围 + 极多细节 + 便宜 | 丢掉拓扑变化（破碎、飞溅）——**它不模拟水体，只模拟"水面的样子"** |

作者自己把定位说得很清楚：**这是"互补"而非"竞争"**——三种方法各在不同运动区间最好。本文选择放弃"水体内部与拓扑变化"，换取"从风暴潮到毛细波的全尺度 + 实时可算"。

## Previous Work

- **Gerstner 波**（Fournier & Reeves 1986；Peachey 1986）：单个波就能给出"尖峰圆谷"，但**没有谱**——波的数量、方向、相位全靠人调；
- **统计海洋学**：Pierson-Moskowitz / Phillips 等**半经验谱**，由风速决定能量分布；AROSS 等实测数据给出 3D 功率谱的形状；
- **CFD/SPH**：见上表。

**本文的增量**：把"谱"与"FFT"接起来——**用实测谱生成随机的频域系数，用 FFT 一次性变回空间域**，于是"物理统计上的合理"和"计算上的便宜"第一次同时成立。

## Core Idea

**四步，一页纸就能实现：**

```text
① 谱：P_h(k) = A·exp(-1/(kL)²)/k⁴ · |k̂·ŵ|²      （L = V²/g，V 风速，ŵ 风向）
② 造初值：h̃₀(k) = (1/√2)(ξr + iξi)·√P_h(k)      （ξ 为标准高斯随机数）
③ 演化：  h̃(k,t) = h̃₀(k)e^{iω(k)t} + h̃₀*(-k)e^{-iω(k)t},  ω = √(gk)
④ 出图：  h(x,t) = Σ_k h̃(k,t)e^{ik·x}            ← 一次 2D IFFT
```

三个设计选择的理由：

- **在频域造初值**（而不是在空间域生成后做 FFT）：省一次变换，且天然保证"谱正确"；
- **两个共轭项**：保证 $h$ 是实函数（波"向左"和"向右"各传一半）；
- **$h$ 只依赖 $t$，不依赖 $h(t-\Delta t)$**：**任意时刻可以直接算，不需要积分历史**——这是它比 CFD 便宜一个数量级的根本原因，也是"循环/跳帧/回放"在工程上完全自由的原因。

## Technical Approach

### 1) 色散关系与"循环"的代价

一个波分量的**相速度** $c=\omega/k=\sqrt{g/k}$：**长波跑得快，短波跑得慢**——所以海浪会"散开"，这是海面看起来活的原因。

但 FFT 要求**空间周期性**：波场在 $L_x\times L_z$ 的 patch 上必须首尾相接，于是**每个分量的周期必须能整除整个循环周期**——实际做法是**把 $\omega$ 量化**（取最近的"整数个周期"的频率）。

![[Research/Files/Pictures/Tessendorf 2001 — 图8 色散关系量化与循环周期.png]]
**读图**：实线是连续色散关系 $\omega=\sqrt{gk}$，两条虚线是量化后的阶梯（循环周期 100 s 与 20 s）。**周期越短，阶梯越粗**；而**量化误差在低波数（长波）端最大**——偏偏长波是海面"形状"的主要来源。这解释了游戏里一个常见现象：**FFT 海面循环得越短，涌浪越假**；补救办法是"多级 patch 各自循环"（cascade）而不是一个 patch 装下所有尺度。（图 8，Tessendorf 2001/2004）

### 2) 尖锐波：位移而不是改谱

FFT 出来的波**峰圆谷圆**，像"好天气"。要做出"尖峰"，不改谱，而是**在水平方向位移顶点**：

$$\mathbf{x}'=\mathbf{x}+\lambda\,\mathbf{D}(\mathbf{x},t),\qquad \mathbf{D}=\sum_k -i\frac{\mathbf{k}}{k}\tilde h(\mathbf{k},t)e^{i\mathbf{k}\cdot\mathbf{x}}$$

位移把顶点**挤向波峰**（波峰处水平位移汇聚），于是波峰变尖、波谷变平——这正是 Gerstner 波的思路，但这里**由谱驱动、自动对所有分量生效**。

![[Research/Files/Pictures/Tessendorf 2001 — 图16 尖锐位移与折叠判据.png]]
**读图**：实线是未位移的波面，虚线是加了位移后的尖锐波面——**峰更尖、谷更平**；点线是 **Jacobian（折叠图）**：它在波峰处下探、**穿零变负**的区域就是"水面自交"的位置，作者直接拿它当**泡沫/浪花遮罩**。一个量同时解决"形状"与"该在哪儿起白沫"。（图 16，Tessendorf 2001/2004）

### 3) 渲染：看得见的不是高度，是斜率

- **法线**：$\epsilon=\nabla h$ 可以直接在频域算（乘 $i\mathbf{k}$ 再一次 IFFT），**不必对高度场做差分**——精度更高、成本一样；
- **反射/折射**：Fresnel 反射率随入射角变化，海面"远处发白、近处透"就是它；
- **水体颜色**：Beer-Lambert 式衰减 + 单次散射反照率 → 为什么海水是蓝绿的；
- **焦散/光柱**：光穿过起伏表面后在水中聚焦，作者给了基于光强 PDF 的做法（这是水下效果最早的一批工程配方）。

### 4) 它做不到什么：一句话

> "**You either get the whole surface, or you don't compute it.**"

FFT 是**全域**运算——**不能只算屏幕上那一块**，也不能"局部加密"。于是：

- 想让船体扰动水面 → 得换方法（iWave：显式波动方程 + 卷积核，13×13 核支持**变水深**）；
- 想要"近处细、远处粗" → 只能**多级 patch**（每级自己的尺寸与循环周期），或改用顶点数可控的 Gerstner 叠加。

## Key Contribution

1. **把海面从"求解"变成"采样"**：随机相位 + 实测谱 + FFT，物理统计上站得住，成本可控；
2. **色散关系作为"演化"的唯一驱动**：所有分量只乘相位，帧与帧之间无状态；
3. **尖锐位移 + Jacobian 折叠判据**：一个变换同时给出"尖峰"与"泡沫位置"；
4. **一份完整的工程配方**：从谱参数（风速 $V$、截断 $\ell$、patch 尺寸）到渲染（Fresnel/衰减/焦散）到参数取值（$N$、$dx$、2 cm 下限），全部写死给读者。

## Why It Works

- **统计正确 > 逐点正确**：观众判断"像不像海"靠的是**波长的分布与方向性**，而不是某一点的流体解；
- **相位可叠加、可并行**：每个波分量独立，天然适合 GPU（FFT 是现代 GPU 的强项）；
- **"无状态"是最大的工程红利**：任意 $t$ 直接算 → 可循环、可回放、可跳帧、可多机同步；
- **位移把"形状"与"谱"解耦**：谱管"有哪些波"，位移管"波长什么样"——两个旋钮各管一件事，调参直观。

## Limitations

- **全域成本，不可剔除**：屏幕里只有 10% 是水，也要算满整个 patch；这是它与"光栅化按可见性付费"最根本的差别；
- **无拓扑变化**：破碎、飞溅、白浪水体、船尾迹都不在模型内（泡沫只是"贴"上去的遮罩）；
- **循环的量化误差**打在最显眼的长波上（图 8）；
- **2 cm 下限**：作者明说 $dx,dz$ 不必低于约 2 cm——再小进入表面张力/非线性区，模型失效；这也意味着**"无限细节"是假的**，远处必须靠法线贴图或 LOD；
- **风向单一**：Phillips 谱的 $|\hat k\cdot\hat w|^2$ 只允许一个主风向（可用多谱叠加绕过，但原文没做）；
- **没有"物体↔水"的耦合**：船、漂浮物、角色入水都不在框架里。

## Game Development Relevance

**这是本库"水的第二条路"的源头，也是"预算"这件事最干净的一个反例/正例混合体：**

1. **成本模型**：每帧 ≈ $O(N^2\log N)$，**只与网格分辨率有关**——与"水面上有什么""镜头看到多少"完全无关。对照你的 VFX 预算语言：**它是"固定成本"型（像后处理），不是"按元素计费"型（像粒子）**；
2. **档位旋钮只有一个**：$N$（面片尺寸）。10 cm / 5 cm / 2.5 cm 就是三档，**画质与成本严格成正比**——比"低中高"三档命名清楚得多；
3. **"不可剔除"的代价**：这正是为什么游戏里最终流行的是**Gerstner 叠加**（顶点数可控、可剔除、可只算近处）+ **法线贴图**（远处细节），而 FFT 海面多用于**近景/过场/影视**；
4. **与 2026 的对照**：[[2026-10-09-Make It Flow — Animating Water in 3D Gaussian Splatting Scenes|Make It Flow]] 连谱都不采了（光流注入）——**"感知优先"这条线从 1999 的 Stam、2001 的本文，一路走到 2026 的"不模拟"**；
5. **对技能 VFX 的直接用处**：水面/水花类技能（冲击波、踏浪、水龙）里，**"用谱造形状 + 用位移造尖峰 + 用 Jacobian 起白沫"** 这三件套可以直接搬到 Niagara 的网格/材质实现里——尤其 **Jacobian→泡沫遮罩**这一招，比手绘 flow map 便宜且自洽。

## Unreal Engine Relevance

- **UE 的 Water 系统走的是 Gerstner 路线**（Water Waves 资产 = 一组 Gerstner 波参数），不是 FFT——原因正是上面第 3 条：**可剔除、顶点数可控、可只覆盖水体区域**；
- **但"谱"的思想仍在**：Water Waves 的"波长/振幅/方向/陡度"四参数，本质是**手调的离散谱**；本文的贡献是告诉你**这组参数该服从什么分布**（Phillips 谱的 $k^{-4}$ 衰减 + 风向余弦）；
- **Niagara**：本文的"频域造初值 + 相位演化"可以做成 **GPU 端的 IFFT 水花**（小网格、局部区域），用于技能里的水面涟漪——比全场景水面便宜得多；
- **材质侧**：$\epsilon=\nabla h$ 在频域算的思路，对应 UE 里"用高度图导数算法线"（`DDX/DDY` 或预烘焙法线），本文提醒的是**别用差分近似代替解析导数**。

## Technology Evolution

```text
"水怎么来"的四代：
1986  Gerstner 波        手调几个波                → 便宜、可控、假
1999  CFD（Stable Fluids）解 NS                     → 真、贵、网格受限
★2001 谱 + FFT           采样统计 + 一次 IFFT      → 统计真、成本固定、不可剔除
2026  光流注入           连统计都不采              → 只为"看起来在动"
```

**四代不是替代关系，而是四个成本档**：手调波（最便宜，引擎默认）→ FFT 谱（中，近景/过场）→ CFD（贵，影视/预渲染）→ 光流注入（最便宜但只对"已有画面"有效）。

## Learning Value

1. **一份"固定成本 vs 按元素成本"的教科书对照**：粒子按个数计费，FFT 水面按分辨率计费——**同一张预算表里，这两类项的增长方式完全不同**；
2. **"档位旋钮只有一个"的干净样本**：$N$ 决定一切，画质与成本线性——比五维预算表简单，但正好说明"**维度越少，档位越好解释**"；
3. **一个可直接用的技巧**：**Jacobian 判据 → 泡沫遮罩**（不用手绘、不用模拟，$J<0$ 就是白沫）；
4. **一条历史判断**：游戏最终选 Gerstner 而影视选 FFT，**不是质量之争，是可剔除性之争**——这与"生成式渲染能不能进运行时"是同一类问题。
