# A Hidden-Surface Algorithm with Anti-Aliasing

## TL;DR

**把像素当成一块面积，而不是一个点——为此必须在每一个像素里跑一次隐藏面。**

一句话结构：**先滤波再采样**，而最容易实现的滤波器就是「把像素覆盖面积内的可见强度积分起来」（$\mathrm{box}$ 滤波，即面积采样）。这在数学上要求每个像素独立解一次可见性：把该像素的深度有序多边形表按「最前面那个多边形的第一条未裁边」递归切成两半，直到最前面的多边形把整块盖住——此时它的贡献就是**面积 × 颜色**；把各支的面积加权色相加，就是这一像素的平均强度。

三件真正留下来的东西：

1. **「点采样 → 面积采样」是定性差别，而「面积采样 → 更好的滤波器」是定量差别**（原文 §Anti-Aliasing）。这是他给出的、此后四十八年一直沿用的验收标准。
2. **面积权重可以在二维上递归求**：因为 z 序已经在列表里，像素内不需要任何 z 计算——三维隐藏面退化成二维裁剪。
3. **代价：完全抗锯齿比不做慢约 3 倍**（原文 §Implementation，作者原话 *approximately three times faster* 指关掉积分器的情形）。

> 它回答的不是"怎么把锯齿磨平"，而是"一个像素值到底应该等于什么"。答案一旦写成积分，后面所有方法——MSAA、A-buffer、Duff 的精确卷积、乃至 2026 年的 [[2026-11-19-Zoomers — ATS Anti-Aliased Triangle Splatting with Exact Per-Primitive Integrals|ATS]]——都只是在回答"这个积分怎么算得起"。

## Problem

1978 年的图形学把 aliasing 当成"边缘不够光滑"的美术问题，用 ad hoc 手段修边。Catmull 开篇就把它抬成正确性问题，列了四条症状（原文 §ANTI-ALIASING）：

| # | 症状 | 今天叫什么 |
|---|---|---|
| 1 | 边缘阶梯（jagged edges） | 几何 aliasing |
| 2 | 小物体在相邻帧之间忽现忽隐 | **时间 aliasing / popping**（游戏里最刺眼的一种） |
| 3 | 周期性图案出现摩尔纹 | moiré |
| 4 | 细节碎裂（fine detail breaking up） | 高频混叠 |

他引用 Crow 1977 的三条结论作为出发点，其中第二条是全篇的支点：

> **Point sampling of an unfiltered object is never correct at any resolution.**（点采样一个未滤波的物体，在任何分辨率下都不正确。）

常见的反驳是"分辨率够高就看不见了"。Catmull 的回答是：**分辨率提高时，场景的高频内容也跟着提高**（围栏的栏杆更密、纹理更细），所以采样率与信号带宽是同步增长的，比值不变。这不是"再等等硬件"能解决的问题。

而一旦承认要滤波，代价立刻出现：**正确的 box 滤波要求每个像素内部解一次可见性**——原文那句 *A correct solution for this filter requires a hidden-surface algorithm at each pixel*，就是整篇论文的动机。像素里可能有四个多边形、三个可见（见图 6），任何"按中心点取一个颜色"的做法都会错。

**这条线上有一个反复出现的分岔**：**"把积分算出来"（Catmull 1978 / Duff 1989 / ATS 2026）vs "用样本逼近积分"（MSAA / TAA / 超采样）**。两者不是精度之争，是**代价形状**之争——前者的代价与"每个像素要算几个被积函数"成正比、与分辨率无关；后者的代价与样本数成正比、**与分辨率成正比**（像素越多，总样本越多）。1978 年 Catmull 选了前者，2026 年 ATS 在同一原语上又选了一次前者，而代价倍率几乎没变（见 §Notes）。

## Previous Work（为什么"未发表"是个问题）

Catmull 有一段少见的方法论批评（原文 §ANTI-ALIASING）：

> 有若干种缓解方案，但**大多未发表**——因为它们或者附属于别的算法，或者属于专有实现。

这句话值得单独记：**一个效果如果只以"某个商业系统里的实现"存在，它就无法被比较、被证伪、被累积**。他随后用 Crow 1977 的三条把"经验修边"翻译成"滤波问题"，这一步是把技法变成学科的动作。

技术上前人给了两件工具，本篇都直接用：

- **Sutherland–Hodgman 裁剪**（[6]）：把多边形按一条直线切成两块。本篇的积分器就是反复调用它。
- **Sutherland et al. 的十算法表征**（[7]）：给出"排序 / 相干性 / 裁剪"这套词汇，本篇用它自陈算法位置（按 y 排序、x 桶排序、z 表搜索、不用扫描线间相干但用点间相干）。

## Core Idea

**面积采样 = 用 box 滤波把图像带限，再在像素中心取值。**

$$I_{pixel}=\frac{1}{A_{pixel}}\iint_{A_{pixel}} I_{visible}(x,y)\,dx\,dy$$

这一步把"抗锯齿"从**采样密度**问题改写成**积分**问题。而积分一旦写出来，可见性就成为被积函数的一部分——**被遮挡的部分积分为 0**，所以积分器必须先知道"在这个像素里，谁在前、谁可见、各占多少面积"。

于是核心装置是：**一个只处理二维、且不需要任何 z 计算的递归积分器**。它能成立全靠一个前提（本篇真正的隐含假设）：

> **每个多边形内部颜色是常数。** 因此"这一块可见面积"乘上"这个颜色"就是它的全部贡献。

**这条前提就是 1978 与 2026 的分界线**：Triangle Splatting 的窗口在三角形内部是 $u^\sigma$（$u$ 是到最近边的归一化距离），颜色/不透明度**不是常数**，面积乘颜色立刻失效——必须真的把 $\iint u^\sigma\,dA$ 算出来。ATS 2026 干的就是这件事，而它用的工具（把区域切开、把面积分变成边界积分）恰好是本篇 §The Pixel Integrator 的同一条思路的推广。

## Technical Approach

### ① 两级裁剪：从扫描线到像素

```text
y 排序 → 活动多边形表
   ↓ 每个扫描线（一条有宽度的带）
 裁掉"带"以下的部分，只留落在带内的窄横条
   ↓ 每个像素
 在像素右边界再裁一次 → 得到像素内的多边形表
```

**一个纯工程但很关键的优化**（原文 §FINDING VISIBLE SURFACES）：大多数横条的**中段**会完整覆盖一串像素，逐像素裁剪是浪费。于是把横条切成三段——**左不规则段 / 中段 solid run / 右不规则段**——中段只需数它覆盖了几个像素，只有两端进入积分器。这是"固体段 + 两个不规则端"的原型，后来所有扫描线光栅化器都有这一层。

### ② z-list 与 pixel polygon list

进入一个像素后重建一份"像素多边形表"：

1. 按 z 序把多边形搬进列表，**遇到第一个"完整覆盖像素"的多边形就停**（它遮住后面所有东西）；
2. 如果没有这样的多边形，**补一个虚拟的"固体多边形"，颜色 = 背景**——保证列表总是被一个固体封底；
3. 所有多边形裁到像素边界；**贴着像素边界的边标记为 `clipflag`（已裁）**。

`clipflag` 是这篇论文里最不起眼、但决定复杂度的一个数据结构：它记录"这条边是不是已经被裁过"，从而让递归知道**还剩哪些边可能暴露后面的东西**。

### ③ 积分器：按"最前面那条未裁边"二分

```text
integrate(list):
  取 list[0]（最近的多边形）
  找它的第一条未裁边 e
  若没有未裁边，或 list 只有一个多边形:
      return  面积(list[0]) × 颜色(list[0])      ← 唯一的"求值"出口
  否则:
     用 e 把 list 里所有多边形裁成两侧 → listA, listB
     把沿 e 的那些边标记为已裁
     return integrate(listA) + integrate(listB)   ← 纯组合，无 z 运算
```

三条性质让它成立：

- **z 序是列表给的，不是算出来的**——所以 e 被当作**二维直线**而不是三维平面。原文明确说：*there is no need for any z calculations*。
- **递归必然终止**：每切一次，至少有一条边被标记为已裁；边数有限。
- **求和即正确**：两块区域互不相交且并集等于原区域，面积加权色自然相加。

### ④ 什么时候可以不做积分

原文给了两级降级，都在用户控制下：

| 情形 | 处理 | 代价 |
|---|---|---|
| 中段完全覆盖像素 | 直接计数，不裁剪 | 无 |
| 用户要求"锯齿边" | 关掉积分器 | **快约 3 倍**（原文 §Implementation） |
| 前多边形无未裁边 | 面积 × 颜色，不再递归 | 无 |

## Key Contribution

1. **把 aliasing 定义为"滤波问题"而非"采样密度问题"**，并给出 box 滤波的解析实现——这使得"正确"成为一个可以讨论的谓词。
2. **定性 / 定量的划分**（见下节），这是全文最耐用的一句话。
3. **面积权重递归**：一个纯组合、无 z 运算、必然终止的每像素积分器。
4. **solid run 优化**：把"逐像素"降到"逐段 + 两个端"。

## Why It Works

**为什么定性 / 定量的划分是对的？** 原文的论证是一个可检验的不变量：

- **点采样**：把一根比像素细的线平移，落在采样点上的样本数会跳变——**全部强度的和随平移而变**（原文的栅栏例子：一张全白、下一张全黑）。
- **面积采样**：积分对平移不变（只要不跨出边界），**强度的和恒定**。
- **更好的滤波器**：也积分，只是权重不同；因此与面积采样的差别**随分辨率提高而收敛**。

所以三种方案里只有第一种"错在类别上"，另两种"错在量上"。这条判据今天仍然好用：**评价一个抗锯齿方案，先问它有没有破坏"平移下的强度和不变"**——破坏了的（点采样、某些只做后处理的锐化式 AA），再多分辨率也救不回来。

**为什么递归不会爆炸？** 因为每个像素的多边形数很少（原文实测的卡通动画场景里，多数像素只有 2~4 个多边形），而每次递归至少消耗一条边。复杂度是"像素内多边形数 × 边数"的乘积级，不是场景级。

## Limitations

原文没有专门的 Limitations 节（1978 年的写法），但边界是清楚的：

1. **被积函数必须是常数**——颜色恒定是"面积 × 颜色"成立的全部理由。原语内部一旦有分布（窗口函数、纹理、着色渐变），这个方法给不出积分，只能给近似。**这是 2026 年 ATS 必须重做一遍的根本原因。**
2. **只处理多边形**：曲线、点、体积都不在内；且要求多边形按"左右顶点表"的特定形式输入（为多边数多边形优化的表示）。
3. **递归的最坏情况没有界**：原文没有给复杂度分析，只有"实际场景里很快"的经验陈述。
4. **代价约 3 倍**，且作者把它当成可开关的选项（*Full anti-aliasing is only required for quality recording*）——这句话等于承认：**在 1978 年的算力下，正确的像素是奢侈品**。
5. **512×512、8 bit/通道**的验证规模（图 8–10），没有时间维度上的定量评估——症状 2（popping）只以"电影里没看到"这种定性方式被报告。
6. **没有和"更好的滤波器"比较**：box 是最容易解析的滤波器，不是最好的（原文自己承认 *While there are better filters, this one is easy to understand*）。这个空白由 Duff 1989 补上（任意多项式滤波器的精确卷积）。

## Game Development Relevance

- **今天每个 GPU 光栅化器的覆盖率（coverage）语义就是这一篇的 box 滤波**：MSAA 的 4/8 个子样本是对这个积分的**蒙特卡洛式近似**（等权子样本 = 用 $N$ 点近似面积）。
- **症状 2（popping）在游戏里是最贵的一种 aliasing**，因为它动起来才出现；这也是 TAA 成为默认选项的真正原因——不是因为它更准，而是因为它把误差变成**时间上相关的**，而人眼对相关噪声的容忍度高于对闪烁的容忍度（这条判断的严格版本见 Dippé & Wold 1985，本库尚未入库，列为待补）。
- **"面积 × 常数色"这条假设在今天的引擎里几乎处处失效**：软粒子（像素内 alpha 变化）、体积雾（像素内有介质）、splat 类表示（像素内有窗口）——凡是像素内值有分布的地方，本篇的积分器都只能做近似。
- **一个可以直接搬进评审的问题**：这个像素值，是"某点的采样"还是"某块面积的积分"？如果是前者，那么分辨率变化时它一定会以某种方式坏掉——只是坏在几何边缘还是坏在细节上。

## Unreal Engine Relevance

UE 的默认路径（TAA/TSR + 后处理 AA）属于"用样本逼近积分"，而不是本篇的"把积分算出来"。因此本篇在 UE 里的对应物不是一个开关，而是三处隐式约定：

- **光栅化的覆盖率**（MSAA 的 `SampleCount`，以及 forward 路径下 `r.MSAACount`）；
- **材质里的 `PixelDepth`/`DDX/DDY` 类导数**——它们度量的是"这个像素覆盖了多大的屏幕面积"，正是 box 滤波的足迹；
- **Nanite 的软件光栅化**在三角形小于像素时退化为"簇级"处理，本质是在回答"亚像素三角形怎么办"，而这个问题的原始形态就是本篇的图 6。

真正的接入点不在渲染器，而在**表示层**：只要原语在像素内是常数（平涂/不透明），本篇的方法就是精确的；一旦原语的贡献在像素内变化（半透明 splat），就必须换 ATS 那一类解析积分。

- **Hard**：递归积分器的**最坏情况**与"什么时候该降级"缺少直觉——本篇没给复杂度分析，需要自己构造病态例子（例如一个像素里叠 50 层细长多边形）才能建立"这方法在哪里会崩"的感觉。

## Learning Value

1. **一个判据**："定性 vs 定量"的划分可以直接用来评价任何新的 AA 方案（包括 TAA、DLSS、以及各种后处理锐化）。
2. **一个反例**：本篇的方法在"原语内部非常数"时立刻失效——这条边界正好解释了为什么 2026 年还需要一篇新论文。
3. **一个可迁移的工程模式**：`clipflag` + "按第一条未裁边二分" 是一种"把高维问题降到二维"的通用技巧（z 序已给 ⇒ 平面变直线）。

## Visualization

![[Research/Files/Pictures/Catmull 1978 — 图6 一个像素里的多个多边形.png]]

**读图**（Figure 6，Catmull 1978）：一个像素方格里压着四个多边形、其中三个可见；细长的多边形 C 横跨 A/B 的边界。**这张图就是"为什么必须每像素做一次隐藏面"的最小证明**——中心点落在 C 上，会得到"C 的颜色"，而正确答案是 A、B、C 三块面积按比例混合。任何按点取值的做法都会在这一格上错，且错误随物体平移而跳变（症状 2）。出处：Catmull, *A Hidden-Surface Algorithm with Anti-Aliasing*, SIGGRAPH '78, Figure 6。

## Notes

- **版本与出处**：SIGGRAPH '78 会议论文集（*Computer Graphics* 12(3)），页码 6–11；本库 PDF 为 UCL VLF 项目镜像的扫描件（6 页，含 OCR 文本层，图 1 在该扫描件中缺失，图 6 完整）。
- **规模**：验证图为 **512×512、每通道 8 bit**（原文 §Implementation）；工作场景是**平涂多边形的卡通动画**，因此"一个像素里 2~4 个多边形"是常态。
- **那个 3×**：原文 *the user can request jagged edges with the result that the program runs approximately three times faster for complicated pictures*。**这个数字在四十八年后几乎原样重现**——ATS 2026 的实测是 202→81 FPS（2.49×）、1/8 分辨率下 69→27 FPS（2.56×）。两套硬件、两套算法（软件扫描线 + 平涂多边形 vs GPU splatting + 半透明三角形）、同一个倍率。**冷水**：基线不同、场景不同，倍率相同可能只是巧合；它至多说明"每像素多算一次积分"这件工作的**相对**价格没有随硬件改变——因为它付的是"被积函数"的钱，不是"像素"的钱。
- **不要混淆**：本篇与 [[Catmull-Clark — Recursively Generated B-Spline Surfaces (1978)|Catmull–Clark 细分曲面]] 是 1978 年的两篇不同论文；本库两篇都有。
