# ParaBMG — 解一个系统的代价，可以跟未知数成线性

## TL;DR

**几何处理管线里最贵的一步，是"再解一次那个几乎没变的稀疏系统"。** ParaBMG 的答案不是"把迭代做得更快"，而是**让同一份网格划分同时充当两样东西**：粗化用的层级、和块 Jacobi 平滑用的块划分。矩阵按块存（对角块稠密、跨块稀疏），于是平滑、残差、粗层更新三个操作跑在同一份存储上，层级构造一次、复用上万次。

**最该记的一组数**（Armadillo 弹性系统，$10^{-6}$，Table 5）：

| 方法 | 平均 PCG 迭代 | GPU 更新时间 + 求解（ms） |
|---|---|---|
| MAS | 318.9 | 86.7 |
| **ParaBMG** | **50.4** | **27.1** |
| AMGX（1 V-cycle） | 71.6 | 449.2 |
| AMGX（10 V-cycles） | **21.9** | **1317.8** |

**迭代数最少的那个，慢了 48 倍。** 21.9 比 50.4 少一半还多，但 1317.8 ms 对 27.1 ms——因为它的每次迭代都在重建层级。**这就是全文的中心：在演化系统里，"收敛率"和"速度"是两个不同的量，而它们的分母不同。**

## Problem

几何处理的一整类管线——网格编辑、蒙皮权重、参数化、特征保持滤波、曲率流反演——都是**反复解同一个稀疏对称正定（SPD）系统**：

$$
A^{(\nu)} x = b^{(\nu)},\qquad A^{(\nu)} \text{ 的稀疏结构固定，系数随 } \nu \text{ 变}
$$

$\nu$ 是外层非线性优化或时间步的编号。**结构不变、数值在变**。分辨率一涨，这一步就吞掉整个交互预算；而 $\nu$ 可以是几万（本文基准里一条序列最多 397 个系统）。

于是问题的正确提法不是"哪个求解器最快"，而是：**"在一个要解四万次、每次只变一点系数的序列上，总时间最短的是什么？"**

## Historical Context

这条线的三次转折，每次都换了一个"被优化的对象"：

| 年代 | 代表 | 被优化的对象 | 欠下的 |
|---|---|---|---|
| 1962–1977 | Fedorenko；Brandt | **收敛率**：让迭代数与网格尺寸无关 | 层级要建，且要建得好 |
| 1980s–2000s | 代数多重网格（AMG） | **通用性**：只看矩阵，不看几何 | 不利用网格结构；系数一变就得重建 |
| 2010s– | 并行 / GPU 多重网格 | **每次迭代的墙钟** | 层级构造与数值更新成了新的大头 |
| 2022–2026 | 多重网格加法 Schwarz（MAS） | **每次迭代的便宜**（无重叠块 + 就地块求逆） | Poisson 型问题上迭代数爆炸 |
| 2026 | **ParaBMG** | **重复求解的总账**：构造 + 迭代 | 只覆盖 SPD / Poisson 型 |

**这不是一条"越来越快"的线，是一条"贵的那一项在搬家"的线。** 每一次进步都把成本从前一项挪到后一项；ParaBMG 的贡献是承认这件事，然后同时压两头。

## Previous Work

四族，各自的欠账单写清楚（这也是本文最实用的一段文献地图）：

- **稀疏直接法**（PARDISO / cuDSS）：稳健、无收敛问题；欠的是 fill-in（内存随分辨率超线性）与**重复数值分解**——演化系统正好每步都要重分解。
- **通用 AMG**（AmgX / BoomerAMG / AMGCL）：GPU 实现成熟；欠的是**不利用网格几何**，且系数演化时要做 coarsening 与 setup 更新。
- **几何多重网格**（Surface Multigrid / GravoMG / GravoTet）：利用网格、粗化便宜；欠的是**强并行平滑器**与面向"演化"的数值更新路径。
- **MAS**（多重网格加法 Schwarz，弹性仿真 SOTA）：每次迭代极便宜（非重叠块、就地块求逆）；欠的是**迭代数**——它的界是加法的，Poisson 型问题上比乘法的 MG 松。

> **一句话分工**：MAS 赢在"每次便宜"，MG 赢在"次数少"，而**谁的总账更小取决于耦合能传多远**（见下）。

## Core Idea

**用同一份网格划分，同时喂两个机制。**

```
        网格 V_l
            │
   ┌────────┴────────┐
   │                 │
 粗化（层级）      块划分（平滑器）
   │                 │
 V_{l+1}           B_v = {u : f_l(u) = v}
   │                 │
 插值 P_l          块 Jacobi：就地 3×3 / q×q 求逆
   │                 │
   └────────┬────────┘
            │
     同一份块结构存储
     （对角块稠密 + 跨块稀疏）
```

三个机制互补：

1. **平滑器杀高频**。块 Jacobi：每个块内联合修正 $q$ 个强耦合未知量，块间并行。块越大，高频消得越狠，但每次迭代越贵。
2. **粗网格杀低频**。残差限制到粗层，粗层上解一个"同一问题的缩小版"，再插值回来修正。低频误差在粗层上变成高频，于是**同一把刀（平滑器）在粗层又能用**。
3. **乘法优于加法**（Xu 1992 的界）：MAS 把各层校正**相加**（可以并行），MG 把校正**逐层作用在残差上**（层间串行）——后者界更锐，代价是串行。

> **这两句话是整个多重网格的全部**：平滑器不管低频，粗网格不管高频；**任何一层单独用，收敛率都随 $n$ 退化**。

## Technical Approach

### ① 层级构造（全并行，图 3）

一级粗化四步，都在 GPU 上：

1. **选粗点**：PMIS（并行最大独立集）风格的贪心选点。
2. **块划分**：每个细点归到最近的粗点，$f_l: V_l \to V_{l+1}$，块 $B_v=\{u: f_l(u)=v\}$。最近点用**并行多源最短路**（标签 $(d_{l,u}, f_l(u))$ + 原子替换，式 8），顺便把"块"定义成"测地邻近的一簇"——这是几何信息的进入点。
3. **块容量上限**：块超过 $m_{\text{agg}}$ 就分裂，插入额外粗点（$m_{\text{agg}}=32$）。
4. **边投影**：$E_{l+1}=\{(f_l(u),f_l(w)) : (u,w)\in E_l,\ f_l(u)\neq f_l(w)\}$。

### ② 块结构存储

对角块**稠密**、跨块**稀疏**。好处是一份数据三用：平滑（块内稠密求解）、残差（稀疏块乘）、粗矩阵更新（Galerkin 积 $A_{l+1}=P_l^\top A_l P_l$ 的块化）。

### ③ 面向"演化"的三项省法

- **层级复用**：稀疏结构与划分不随系数变 ⇒ 建一次，一直用。
- **就地块求逆**：块是 $3\times3$ 或 $q\times q$，直接在寄存器/shared 里解，不落全局内存。
- **预备粗解 + 自适应谱估计**：最粗层的解与 Chebyshev/谱估计的参数预先算好，每步只更新。

### ④ 基准（这本身是贡献）

四套 CUDA 管线：**LDSE**（局部网格变形）、**QHW**（准调和权重 = 蒙皮权重）、**DSTV**（方向形状全变差 = 特征保持滤波）、**IMCF**（平均曲率流反演 = 网格膨胀）。规模：**40 条序列 / 40,987 个线性系统 / 20 个网格 / 177K–6.6M 顶点**。

## Key Contribution

1. **一个"块多重网格"框架**：块划分既是粗化产物又是平滑器单位——把两个原本独立的设计耦合起来。
2. **一份统一的 GPU 求解器基准**：4 万多个真实几何处理系统，公开可比。**在此之前，这个领域的"哪个求解器快"基本靠各说各话。**
3. **数字**（对最强 GPU 基线，40 条序列平均）：**3.7×–7.7×**；分基线：**3.7×–10.7×** 对 AMGX、**4.5×–8.5×** 对 BoomerAMG、**6×–105×** 对 GravoMG/GravoTet 的 GPU 移植、**6×–96×** 对 SOTA MAS。
4. **三个交互应用**：网格编辑、带边界约束变化的参数化（QHM）、准调和聚类——端到端加速 **14.1× / 3.9× / 3.7× / 39.7× / 4.4×**（Table 3），最大处理到 **10.2M 顶点**且可交互。

## Why It Works

**因为误差不是一种东西，而是一个频谱，且不同频段的"消除成本"随 $n$ 反向变化。**

- 高频误差：局部，几次加权平均就没了。平滑器 $O(n)$ 一次。
- 低频误差：全局，局部操作每次只能削掉 $O(1/n)$。**在细网格上迭代，等于用一把只能切薄片的刀去砍一整块。**

多重网格的洞察是：**换到粗网格上，同一个低频就变成了高频**。于是同一把刀在每一层都有效，而每一层的工作量是上一层的一半——总工作量 $\sum_l n_l \approx 2n$。

> **这就是 $O(n)$ 的来源：不是每次迭代更快，而是"层数 × 每层工作量"这个乘积里，每层都在指数变小。**

而 MAS 是加法版：各层校正独立、可全并行，但**误差只能在"一次循环"里被削减一次**，不能像乘法那样把"上一层没削干净的残差"继续往下传。耦合短程时无所谓（局部校正已经够了），耦合长程时差距就出来了。

## 屏蔽强度：什么时候乘法赢（图 11，本篇最该读的一张）

物理上，弹性隐式时间步解的是

$$
\left(K + \Delta t^{-2} M\right) x = b
$$

$M$ 是质量矩阵，$\Delta t^{-2}$ 充当**屏蔽项**（screening）——**这正是 screened Poisson 方程**。$\alpha \equiv \Delta t^{-2}$ 越大，远距离的影响被质量项"屏蔽"得越狠，耦合越短程。

作者固定 Armadillo 的刚度与约束，只扫 $\alpha$（$10^{10} \to 0$，实际时间步是 3600 s⁻²）：

| $\alpha$ | 物理含义 | 谁赢 |
|---|---|---|
| $10^{10}$ | 极短时间步，几乎纯惯性 | 局部校正够用；MAS 的便宜占上风，AMGX 也不差 |
| $3600$（真实步长） | 常规仿真 | ParaBMG 已经领先 |
| $10^{5}$ | 慢动作 | MAS 迭代数开始指数上升 |
| $0$ | 静态极限，**完全无屏蔽** | MAS ≈ 1300 次迭代，ParaBMG ≈ 120 次——**差一个数量级** |

> **判据：看耦合能传多远，而不是看问题属于哪个领域。**
> 同一个 Armadillo、同一套约束、同一个右端项，只改一个 $\alpha$，最优求解器就换人。**所以"仿真的求解器搬去几何处理"这件事，从原理上就不该成立**（原文原话：*Solver design for geometry processing therefore cannot simply be inherited from simulation*）。

**一句冷水（作者自己泼的）**：在这个弹性族里，**MAS 的时间始终优于 AMGX**，即使到静态极限也没有翻转。也就是说"加法输给乘法"不是纯数学结论，还掺着实现质量——**换到 Poisson 型基准上差距才真正拉开**。这条被作者写在正文里，很诚实。

## Limitations

1. **只覆盖 SPD / Poisson 型**。$3N\times3N$ 的耦合系统（三自由度/顶点）、多右端项、非 SPD，全部未处理。
2. **超参不自动**。$m_{\text{agg}}$、层数、平滑次数都是手调的；系数分布极端时"要不要重建"没有自动判据。
3. **块大小是笔交易**（图 9）：$q$ 从 1 加到 32，迭代数只降 **17.1%**（35→29），时间从 **255.9 → 420.2 ms**（在固定 AMGX 层级上测）。所以"更大的块"并不自动更好——**这正是它必须在块求解上做工程优化的原因**。
4. **构造仍是串行瓶颈的一环**：图 5 里一个典型 Pulley/LDSE 系统，update 16.38 ms vs solve 63.34 ms——**"更新系数"占了 20.5%**，而这一项在纯求解器论文里通常不计。
5. **基准是作者自己实现的四条管线**；与被测 CPU 实现的对比"工作量匹配"由作者声明，不是第三方复现。

## Game Development Relevance

**四个落点，从"最直接"到"最间接"：**

1. **蒙皮权重（QHW）**：这是角色管线里最讨厌的一步——自动权重需要解一个带约束的椭圆 PDE，网格一密就卡死。本文把它做到 10.2M 顶点可交互。**对 TA 的含义：自动权重可以做成"拖一下手柄就看到结果"的交互工具，而不是"点一下等十分钟"的批处理。**
2. **布料 / 软体 / 断裂**：IPC 家族的每一步都是"解一个 $K+\Delta t^{-2}M$"。本文的 $\alpha$ 扫描等于告诉你：**你的时间步越长，越需要多重网格；步长越短，块 Jacobi 类的便宜方法反而够用。** 这条判据可以直接用来决定"要不要上 MG"。
3. **网格编辑 / DCC 工具**：局部变形（LDSE）就是建模器里的"拖点"。交互性取决于解一次要多久。
4. **参数化 / UV（QHM）**：边界控制点一动就要重解；本文演示的是"拖边界点，UV 实时跟"。

**反过来的教训也很硬**：如果你在游戏里做的是"每帧解一个 $n$ 只有几千的系统"，那这一切都不适用——**层级构造的固定开销会吃掉全部收益**。$O(n)$ 的优势只在 $n$ 大、且要解很多次时才显形。

## Unreal Engine Relevance

- **Chaos Flesh / Chaos Cloth**：都是"每步解一个稀疏 SPD"的结构。MG 在这里的障碍不是算法而是**拓扑会变**（布料撕裂、破碎）——层级必须能增量重建，这正是本文"复用 + 预备更新"那套机制针对的场景。
- **Geometry Script / 骨骼权重工具**：QHW 的交互化直接对应"自动权重预览"。
- **不适用**：Lumen / Nanite 这类不需要解全局稀疏系统的管线。**别硬套。**

## Learning Value

**这是一篇"把成本结构讲清楚"的论文**，比它给出的加速比更值钱。三个可迁移的动作：

1. **看任何求解器论文，先问"setup 算不算在时间里"**。算了的和没算的，不能比。
2. **看任何"我们的方法更快"，先问"在什么耦合长度上更快"**。$\alpha$ 扫描那张图就是模板。
3. **看任何"$O(n)$"，先问"常数项里有什么"**。层级构造就是那个常数项。

**读图**：四个色块 = 四种时间尺度。左上 **Setup（一次，$\nu=0$）**：建层级、分配 $D_l/E_l$、预备表；左下 **Update（每次 $\nu>0$）**：只重算 $A_l^{(\nu)}=I+\alpha M_l^{(\nu)}$ 并就地求逆；右下 **Apply（每次 PCG 迭代）**：pre-smooth → restrict → 粗解 → prolongate → post-smooth。**关键在"Update 不等 Setup"**——这就是"演化系统"这三个字的全部含义。（图 2，Lyu et al. 2026）

![[Research/Files/Pictures/Lyu 2026 — 图9 局部解尺寸的权衡.png]]

**读图**：同一个 AMGX 层级，只改局部解尺寸 $q$。上图残差曲线几乎重合（迭代数 35→29，**17.1%**），下图时间从 420 ms 涨到 800 ms（含 upload+setup），**代价涨得比收益快**。**这是"块越大越好"的反例**，也是本文必须自己做块求解优化的理由。（图 9，Lyu et al. 2026）

![[Research/Files/Pictures/Lyu 2026 — 图8 MAS补上多重网格粗校正.png]]

**读图**：三条曲线，同一系统。MAS 单独用要 ~250 次迭代 / ~520 ms；**给 MAS 补上多重网格粗校正（MAS+MG）** 后降到 ~140 次 / ~180 ms；ParaBMG 约 15 次 / ~55 ms。**中段那条线是全篇最漂亮的一个实验**：它证明两个机制是**可叠加的**，不是二选一——"加法"缺的那一半恰好是"乘法"多的那一半。（图 8，Lyu et al. 2026）

![[Research/Files/Pictures/Lyu 2026 — 图11 屏蔽强度扫描.png]]

**读图**：横轴 $\alpha$ 从 $10^{10}$（强屏蔽，短时间步）到 $0$（静态极限，无屏蔽），虚线是真实步长 3600 s⁻²。左：PCG 迭代数（对数轴）；右：更新+求解的 GPU 时间。**MAS（深红）在 $\alpha\to0$ 时迭代数冲到 1300，而 ParaBMG 停在 120**；AMGX(10 V-cycles) 迭代数最少但时间最高（1.3 s 级）。**一张图同时否定了两个直觉**："迭代少的更快"和"仿真里最好的搬过来就行"。（图 11，Lyu et al. 2026）
