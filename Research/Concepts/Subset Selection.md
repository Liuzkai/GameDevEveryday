# Subset Selection

## Definition

**给定 $N$ 个元素、预算 $K$、以及一个评价"选得好不好"的损失 $\mathcal{L}(m)$，选一个 $K$ 元子集：**

$$\min_{m\in\{0,1\}^N}\ \mathcal{L}(m)\quad\text{s.t.}\quad \sum_i m_i=K$$

**它是预算问题的另一半。** [[Budget Units]] 回答"**用什么计量**"（十二种计价对象）；本页回答"**预算定了之后，留下哪些**"。两页必须一起看：**计量单位错了，选择再准也没意义；选择错了，计量再准也只是算清了一笔坏账。**

**为什么需要单独一页。** 库内已有 20 多篇论文在解这个式子（LOD 选表示、QEM 删边、GS 剪枝、灯架裁剪、蓄水池重采样、贴图流送），但**没有一页承载"这个式子本身"**：

- [[Level of Detail]] 讲的是"**每帧**选哪一份"，判据是"这一帧它会错多少像素"；
- [[Mesh Simplification]] 讲的是"**离线**把网格变少"，判据是"这份表示比原来差多少";
- 两页都**默认了"逐个判断 + 排序"这个范式**，没有问过它什么时候不成立。

**本页补的就是这一问。**

## Core Principle

**子集选择不是一个算法，是三个独立决定的乘积。** 与 [[Mesh Simplification]] 的"删什么 × 代价怎么算 × 停在哪"同构，但换成"选择"的语言后，第三个轴变成**时间**：

```text
① 元素之间能不能互相替代？   —— 决定"独立打分"是否合法
  ×
② 代价住在哪个空间？         —— 决定"打分"值不值
  ×
③ 决策什么时候提交？         —— 决定"能不能反悔"
```

### ① 可替代性：这一轴决定"打分"能不能用

**"逐个打分再取 top-K" 隐含一个假设：一个元素的价值与"还有谁在"无关。**

这个假设在**只有一阶量**的世界里成立得不错（删一个时，交叉项严格为零），但在**高压缩比**下必然失效——因为那时你删的不是"一个"，是"一片互相兜底的"。

| 情形 | 元素之间 | 独立打分 |
|---|---|---|
| 稀疏、彼此远离 | 几乎无交互 | ✅ 精确（[[LeCun 1990 — Optimal Brain Damage\|OBD]] 的对角近似在"只删一个"时是恒等式） |
| 密集、同一片区域互相兜底 | **可替代（substitutes）** | ❌ 系统性低估——"单独看都冗余，一起删是个洞" |
| 互补（complements，缺一不可） | 同上一族 | ❌ 同样低估 |

**三个域的同一个现象，三个独立测量：**

| 域 | 现象 | 量化 |
|---|---|---|
| 网络权重（1990） | 删到 ~30% 后，预测与实际分离 | **作者自陈失效点** |
| 3D 高斯（2026） | 同一 LOO 分数的两个高斯，剪后在重要性上差 **3.0×（90% 删率）/ 5.0–6.8×（99%）**；LMnOP 保留的那些在 **88–94%** 的对里更重要 | [[2026-11-25-Jeong — LMnOP Pruning 3DGS via Leave-Many-Out Importance\|LMnOP]] Table 2 |
| 网格顶点（2026） | 后处理简化的误差无人补偿；接上梯度后交付口径差 **34%**，且增益随预算收紧从 0.05 涨到 1.34 | [[2026-11-25-Oh — DiffSimp Differentiable Mesh Simplification\|DiffSimp]] Table 2/5 |

> **一句话判据：预算越紧，独立打分越错。** 这不是经验，是"交互项在删除集合变大时按二阶增长"的直接后果。

### ② 代价空间：这一轴决定"打分"值不值

同一个"删多少"，住在不同空间里给出的排序可以完全不同：

| 代价住在 | 代表 | 优点 | 硬伤 |
|---|---|---|---|
| **元素自身的参数**（幅值 / 不透明度 / 激活） | 幅值法、`Opacity` 基线 | 免费 | 只是代理量；**没有单位，不能跨模块相加** |
| **几何空间**（到平面的距离平方和） | QEM 1997 | 可加 ⇒ 可进堆 ⇒ 可随时停 | 与"看起来"无关；属性的汇率只能拍 |
| **图像空间**（渲染后比像素） | Image-Driven 2000 | 与验收口径一致 | **不可加** ⇒ 不能进堆，只能边简化边渲染 |
| **任务损失**（下游目标） | [[2026-11-25-Oh — DiffSimp Differentiable Mesh Simplification\|DiffSimp]] 2026 | 能穿梯度，上游可补偿 | 需要可微前端；且"哪个损失"本身是个选择 |

**最锋利的一条**：DiffSimp 的 Table 5 证明**"优化稠密的那份"与"优化交付的那份"可以反向**（raw −3.4% 而 deployed +1.2%）。**所以"代价住在哪个空间"不是精度问题，是方向问题。**

### ③ 提交时机：这一轴决定"能不能反悔"

离散决策有个讨厌的性质：**一动，全局的价值表就变。** 于是所有工程解法都在回答同一个问题——**什么时候把它定下来？**

| 家族 | 做法 | 例子 | 代价 |
|---|---|---|---|
| **A. 一次打分 + 一次提交** | 算一个分，取 top-K，不再回头 | OBD、QEM、`Opacity`、LightGaussian | 最快；高压缩比下系统性出错 |
| **B. 迭代重打分（每轮真删）** | 删一批、在剩下的上重打分、再删 | GaussianPOP 的 8 阶段；多级 LOD 链 | **不可反悔**（前一轮删错的救不回来）；每轮重算 |
| **C. 联合期望（不真删，只搜概率）** | 把"其他也会被删"积进重要性；**搜索期一个都不删**，最后提交一次 | [[2026-11-25-Jeong — LMnOP Pruning 3DGS via Leave-Many-Out Importance\|LMnOP]]（µ-σ rendering，$R=8$） | 贵（每次要全模型评估）；但**无路径依赖** |
| **D. 固定结构求导** | 离散决策照常做，但把这一次的实现冻住，只对"决策之后的连续映射"求导 | [[2026-11-25-Oh — DiffSimp Differentiable Mesh Simplification\|DiffSimp]]（固定塌陷历史 $\sigma$） | 梯度有偏（只对这一次实现负责）；需可微前端 |
| **E. 在线重采样** | 预算固定，流式到达，按权重概率替换 | [[Reservoir Sampling]] / [[ReSTIR]] | 只能处理"可流式"的元素；有偏（需无偏估计器） |

> **B 与 C 的关系值得单记**：LMnOP 的消融里，"8 阶段重打分 + LOO" 与 "单阶段 + 联合期望" **效果基本打平**（23.08 vs 23.00 dB），**但前者 10.7 分钟、后者 19.5 分钟**。打平的时候要比**时间花在哪**：8 阶段法的时间花在"重复删 + 重算"（**可并行、可增量**），LMnOP 的时间花在"8 次全模型渲染"（**不可增量**）。

## 三个"预算对象"必须先分清

同一个"删 90%"，说的是三种不同的东西：

| 说法 | 分母 | 谁在意 |
|---|---|---|
| **元素数** | $K/N$ | 论文（最好写） |
| **字节数** | 存储 / 带宽 | 平台方（装机包、显存） |
| **时间** | 每帧 ms | 玩家（帧率） |

**它们不成比例。** [[2026-11-25-Jeong — LMnOP Pruning 3DGS via Leave-Many-Out Importance|LMnOP]] 里"同样 10% 的高斯，选法不同，PSNR 差 1.15 dB"——**说明元素数是一个可以用不同方式花掉的预算**；而 [[Budget Units]] 的十二种计价对象说明**换个分母，同一个 −74% 可以读成 −23%**。**选择问题永远要先问"分母是什么"。**

## Historical Evolution

```text
1990  OBD：定义"重要性 = 删除引起的损失增量" + 对角近似 + 自陈 30% 失效点
  ↓
1992  OBS：H⁻¹ 补偿"其余会被重新优化" —— 二次型世界里的闭式联合重要性
  ↓
1997  QEM：把代价做成可加的二次型 ⇒ 可进堆、可随时停 ⇒ 工业默认（后处理）
  ↓
2000  Image-Driven：把代价搬进图像空间 ⇒ 对"看起来"诚实，但不可加
  ↓
2004  Lightcuts：把"选灯"做成层次切（cut）+ 2% 相对误差界 ⇒ 第一次带"界"的选择
  ↓
2023  ReSTIR / Reservoir：预算 = 1 个样本，在线替换 ⇒ 选择变成"流式"
  ↓
2024–25  GS 剪枝：LOO 重要性搬到高斯（PUP / GaussianPOP / RAP / Coreset）
  ↓
2026  LMnOP：联合期望（µ-σ）+ 概率搜索、一次提交
2026  DiffSimp：固定离散解、对连续映射求导
  ↓
（下一步）"选子集"与"调剩下的"联合优化（现在几乎都是分开做的）
```

**这条线的方向：从"假设独立"走向"承认交互"，而每走一步，代价都从"一次反传"涨到"多次全模型评估"。**

## Related Concepts

- **[[Budget Units]]** —— 上游：**怎么计量**。本页是下游：**选了谁**。**单位不清，选择无意义。**
- **[[Level of Detail]]** —— 同一式子的"每帧"特化；本页关心的是"这个式子本身在什么条件下可解"。
- **[[Mesh Simplification]]** —— 同一式子在"网格"上的离线特化；它的"三条实现路线"其实就是本页家族 A/B/D 的历史形态。
- **[[Reservoir Sampling]]** —— 家族 E：**预算固定、元素流式到达**时的选择。与 A–D 的关键差别是"元素能不能等"。
- **[[Many-Light Rendering]]** —— 灯的选择（剔除 / 层次近似 / 重采样 / 改写内容）；**唯一带"误差界"的一支**。
- **[[Gaussian Splatting]]** —— 当下最大的应用场：高斯数从百万压到十万。
- **[[Differentiable Rendering]]** —— 家族 D 的技术基础；本页的第三轴（提交时机）在那一页有更细的讨论（Learning Gap 第 3 条）。
- **[[Scalability and Quality Tiers]]** —— "档位 = 误差容限"，与本页的"预算 = 容差"是同一件事的两种说法。

## Game Applications

1. **LOD 链**：家族 A（离线 QEM 生成 + 运行时按屏占选）。**注意它是"两次选择"**：离线选表示、运行时选哪份。
2. **灯光预算**：家族 A + 界（Lightcuts 类）。**必须带界**——灯光是美术的意图，不能只给"排了个序"。
3. **粒子 / VFX 上限**：家族 A（按屏幕贡献）+ 家族 E（流式预算）。见 [[Real-Time VFX Performance Budgeting]]。
4. **贴图流送**：家族 E（mip 层级 + 驻留窗口），分母是**带宽**不是个数。
5. **3DGS 资产落地**：家族 A→C/D 迁移的当下现场（2024–26）。
6. **可破坏物 / 破碎预处理**：家族 A，但**预算极紧**（碎块面数爆炸）⇒ 按本页判据，最容易踩"独立打分"的坑。

## Personal Knowledge

- **Easy**：top-K 这个动作、按分数排序、多阶段删。
- **Normal（本页要建立的）**：**三轴分解**（可替代性 / 代价空间 / 提交时机），以及"A–E 五个家族各自的硬伤"。
- **尚未建立**：**"选择"与"调整"的联合**——今天所有方法都假设"选完之后剩下的原样不动"（除了 DiffSimp 让上游去补偿）。**这是本页最大的空缺。**

## Learning Gap

- **"最优子集"的理论地板只在一个特例上有**（网格：$F_{\min}$ 的四项分解 + $4n_{\text{sig}}$ 悬崖）。**高斯、灯光、粒子都没有对应的下界**——所以那些领域的"预算表"至今没有"这样压是不可能的"这句话。
- **交互的度量没有统一语言。** OBD 用 $h_{ij}$、OBS 用 $H^{-1}$、LMnOP 用方差 $\sigma^2$、Shapley 用边际贡献的平均——**四套语言，没有换算。**
- **"提交时机"缺少代价模型。** 家族 B 与 C 打平时，我们只能说"时间花在哪不同"，**没有公式告诉你什么时候该选哪个**。
- **多预算同时约束**（显存 + 带宽 + 每帧 ms + 画质）下的选择，库内一篇都没有。

## Next Step

1. **拿一个自己熟悉的预算问题**（LOD 链 / 粒子上限 / 灯光上限），把它的"重要性函数"写下来，标出它属于**代理量**还是**损失增量**。
2. 若属代理量，问：**在最紧的那一档预算下，它还能排序吗？** 不能，就至少换成家族 B（多阶段），成本最低。
3. 读 [[2026-11-25-Jeong — LMnOP Pruning 3DGS via Leave-Many-Out Importance|LMnOP]] 的 §5.3（那组配对实验）——**它是"如何证明前提成立"的模板**，比主表更值得学。
4. 若要碰可微前端，读 [[2026-11-25-Oh — DiffSimp Differentiable Mesh Simplification|DiffSimp]] 的 §4.2–4.3：**"固定离散、求导连续"这条路的具体代价**。

## Notes

- **建页依据**：库内 20+ 篇论文在解同一个式子，**0 页承载它**；`Budget Units` 只讲计量、`Level of Detail` 只讲每帧、`Mesh Simplification` 只讲网格。**三页都默认"逐个打分"合法，而 1990 年那篇经典自己就标注了它不合法。**
- **与 [[Level of Detail]] 的边界**：那页的判据是"这一帧它会错多少像素"，决定频率是**每帧**；本页的判据是"选得好不好"，决定频率是**一次**（或少数几次）。**合并会让"决定频率"消失**，故不合并。
- **为什么用 "Subset Selection" 这个名字**：它是统计学/机器学习里的既有术语（best subset selection），且不绑定任何单一域（"pruning" 只适合网络与高斯，"decimation" 只适合网格）。**别名里保留 Pruning 与剪枝，方便检索。**
