# Automated Content Evaluation

## Definition

**把"这个东西好不好"变成"可执行、可复现、可指认"的检查的那一层。**

它产出三样东西，**经常被混为一谈，但用途完全不同**：

| 产出 | 是什么 | 能用来做什么 | 不能做什么 |
|---|---|---|---|
| **判决**（verdict） | 一条一条的"过 / 不过 / 看不清" | 定位、审计、追责 | 排序（太细） |
| **分数**（score） | 把 N 条判决压成一个数 | **排序、选型、做表** | **修改**（信息已被压掉） |
| **报告**（report） | 点名到对象 + 理由 + 证据 | **修改** | 排序（太啰嗦） |

**这一页的核心判断：分数是压缩，报告是索引。** 压缩必然丢信息，问题不在"压得不好"，在**下游只能拿到压缩结果**。

## Core Principle

### ① 三层阶梯 = 修复优先级，不是分类

自动评测最常被写成"多维度打分"，但维度之间**不是并列的**：

```text
A 物理合法（碰撞 / 出界 / 支撑）
  ↓ 不合法时，下面两层的判断本身不成立
B 视觉协调（比例 / 风格 / 搭配）
  ↓ 协调但没法用
C 人类可用（摆放是否合理 / 功能是否成立）
```

**穿模的桌子，"桌面高度是否合适"这个检查没有意义。** 所以三层递进的真正作用是：**当报告里同时有十项缺陷时，告诉你先修哪一个。** 这是几乎所有自动评测都缺、但所有使用者都立刻需要的东西。

### ② 反馈的粒度决定它能被用来做什么

[[2026-11-04-Cao — GREP Grounding Generated Room Evaluation in Principles|GREP 2026]] 给了一组罕见干净的对照（三轮修订 / 五个场景 / 同一初始分 0.585）：

| 反馈形式 | 结果 | 布局实际改动 |
|---|---|---|
| **诊断报告** | 0.585 → **0.676** | **15/15** |
| 只给分数 | 0.585 → **0.543**（比不给还差） | 5/15 |
| 不给反馈 | 0.543 | 6/15 |

**"只给分数"会让结果变差**，因为收到"0.54 分"的模型唯一能做的是随机重排。**这是 reward hacking 的一个具体形态，而且可测**：被优化的会是分数，不是内容。

**判据：如果你的自动反馈只有分数，那它只能用来选，不能用来改。**

### ③ 必须能说"不知道"

硬规则和固定视角的评测器有一个共同的**结构性缺陷**：**没有"证据不足"这个状态**。看不见的地方，它们默认判"没问题"。

GREP 的做法是把 `insufficient` 做成一等输出：先问"证据够不够"，不够就**自己去取**（量距离/角度、调已有视角、渲新视角），取完还要检查"新视角真的补上了缺的那条证据吗"。

**这一条对工程的意义比分数公式大**：自动化工具的假阳性（把"没看见"当成"没问题"）比漏检更难查，因为**它不会报错**。

### ④ 先量重复性，再拿它比东西

任何自动评测在能用来做决策之前，必须先回答"同一份输入跑两次，分差多少"。

GREP 自报：12 场景 × 5 次重复，**单场景标准差中位数 2.9 分**（范围 0.4–7.3），**极差中位数 7.2 分**（最大 17.2），ICC = 0.92 ⇒ **10 个场景取均值时，两个均值差小于约 4 分不算差异。**

**没有这个数的自动评分，任何"版本 A 比版本 B 好 2 分"的结论都是噪声。**

### ⑤ 四类评测器的失效模式（各不相同）

| 评测器 | 强项 | **典型失效** |
|---|---|---|
| **硬几何规则**（碰撞、包围盒、可达性） | 快、确定、可解释 | **分不清"故意接触"与"穿模"**；只查枚举过的关系 |
| **整体指标**（PSNR / LPIPS / FID / IQA） | 无需标注、可大批量 | **与人类判断可能≈随机**（见下）；看不出语义级错误 |
| **整体模型评判**（一个 VLM 看一眼打分） | 泛化好、能读语义 | **只看一张全局图 ⇒"看起来还行"**；**会偏袒自家生成** |
| **结构化检查表**（原子问题 / 固定清单） | 可审计、可复现 | **词表由输入描述或标注决定 ⇒ 描述里没有的查不到** |

**四类的失效点没有重叠**——所以正解通常不是"选一个最好的"，是**分层组合**：几何测量打底（便宜、确定）+ 模型判断语义（贵、模糊）+ Agent 决定"要不要再看一眼"。

## Prerequisites

- **可测量的场景表示**：物体 + 变换 + 尺度 + 边界。**没有几何就没有测量，只剩"看起来"**；
- **一个渲染/取景回路**：能对同一场景换相机重渲。**这是"自适应取证"的前提**，也是 Agent 型评测比纯指标贵的地方；
- **"缺陷"的定义与严重度**：什么算错、错到什么程度扣多少分。**这一步没有客观答案，是设计决定**——GREP 的 $\alpha=0.4$、$\gamma=4$ 就是两个没有消融的设计常数；
- **一个人工参照**：至少几十组二选一。**没有人类判断做锚，"一致率"这个数没有意义**。

## Historical Evolution

```text
1990s-2000s  人工 QA：美术/QA 一条条看
  ↓
2004         PSNR / SSIM：图像质量的"客观指标"时代
  ↓
2017         FID / LPIPS：生成模型的分布级与感知级度量
  ↓        ——共同病：一个标量，说不出哪里错
2022-23      结构化原子问题（DSG）：把"像不像"拆成可判定的子问题
  ↓
2024-25      场景级检查表（SceneEval / LEGO-Eval）：从"图文一致"到"物理合法"
  ↓        引擎侧同源：Data Validation / 碰撞校验 / 命名规范检查
2026-11      ★ Agent 取证（GREP）：三层原则定优先级 + 自主补证据 + 报告
             · 与人类多数一致 86.7%（整体 VLM 62.2% / 纯物理 53.3%）
             · 报告让修订变好（0.585→0.676），分数让它变差（→0.543）
```

**这条线的形状是"从'像不像'到'能不能用'"，而每一步都把'谁的判断'往前提**：指标 → 检查表 → 模型 → **模型 + 证据 + 可以拒绝**。

**一条平行且更早的支线**：动画的"十二条原则"（[[Lasseter — Principles of Traditional Animation Applied to 3D Computer Animation (1987)|Lasseter 1987]]）本质上是**第一份"可验收清单"**——它把"有没有生命力"拆成十二条可指认的项。**自动评测在做的，是把这份清单交给机器执行。**

## Important Papers

- [[2026-11-04-Cao — GREP Grounding Generated Room Evaluation in Principles|GREP 2026]] — **本页主节点**：三层原则 + 八指标 + 自适应取证 + 报告。给出了"报告 vs 分数"的干净对照，也给出了重复性数字
- [[Giroux 2023 — Towards a Perceptual Evaluation Framework for Lighting Estimation|Giroux 2023]] — **反面证据 + 出路**：49 人 2AFC 审计 15 个 IQA 指标，**高光/无参照任务上一致率≈随机（0.5）**；但用几十组二选一可以**训练出项目专用指标**（SVR 0.786–0.889，holdout 成立）
- [[2026-10-29-Wang — TalkFlow Structured Latent Flow Matching for Speech Driven Holistic Motion Generation|TalkFlow 2026]] — **指标失效的第二例**：真值的 BCS 只有 6.86，**低于表里每一个方法**；FGD 最好的方法在用户研究里真实感排名反而更差。**"一个指标同时判好坏，就会被两边打脸"**
- [[Baran 2007 — Automatic Rigging and Animation of 3D Characters|Baran 2007]] — **指标分工的教科书**：CD-J2J / J2B / B2B 三个距离各管一类错误（"J2B 低 + J2J 高 = 骨架位置对、但关节沿骨错位"）——**这是"拆开才有诊断力"的最早样本之一**

## Technologies

- **Data Validation / 硬规则校验**（引擎侧）：最快、最确定的一层。**要先接受它分不清"故意"与"错误"**，把这条写进规则设计；
- **VLM judge**：泛化好，但**会偏袒自家生成**（GREP 的 judge 本身就是被测模型之一，作者自己点名了这个风险）；
- **2AFC 人工二选一 + 学习组合**：Giroux 那条路——**几十组偏好对训练一个项目专用指标**，这是目前唯一"既便宜又与人对齐"的工程解；
- **Agent + 取景回路**：贵，但能回答"这一项我看不清，再看一眼"。**成本计价对象从"多少张图"变成"渲几个视角"**。

## Game Applications

- **关卡/室内生成的自动 QC**：三层阶梯是一份现成清单，报告粒度（点名到 actor）正好能点进 `FMessageLog`；
- **资产入库门禁**：命名、缩放、碰撞、材质槽——硬规则够用；"这个模型像不像它该有的样子"才需要模型判断；
- **生成资产的验收**：AI 生成的道具/贴图/动画进管线前，**必须要有一份"哪里不对"的报告**，否则美术只能重做或全收；
- **动画评审**：评审意见的结构化——哪个片段、哪一条原则、证据是什么。**"看起来怪"不是一条可执行的反馈**；
- **反向用途（最值钱的一条）**：**把评测器当成生成器的选择压力时，务必只喂报告、别只喂分数**——否则被优化的是分数。

## Personal Knowledge

Current Level: **Normal**

- **Easy**：为什么要自动评测、硬规则能查什么、PSNR/LPIPS 是什么；
- **Normal**：分数与报告为什么不能互相替代、三层为什么是递进（= 修复优先级）、`insufficient` 为什么是一等公民、重复性数字怎么用（差值 < 4 分不算差异）；
- **Hard**：Agent 的取景策略与预算控制、VLM 的自偏好如何量化——**要用再读**。

## Learning Gap

**缺的不是"知道有自动评测"，是三样具体的东西：**

1. **没有一次"自己的重复性测量"**：手上任何自动评分（哪怕是 VFX 预算表里的估算、或资产的自动检查脚本），**跑五遍看分差多少**——这个数从来没量过；
2. **"报告 vs 分数"没有在自己的流程里被验证过**：给美术/给上级的反馈，现在是分数型还是报告型？**GREP 的证据说这两种的后果相反**；
3. **缺一条"故意 vs 错误"的判据**：碰撞检测在游戏里天天跑，但它分不清"角色踩在地上"和"角色陷进地里"——**这是所有硬规则的共同缺口，不是实现问题**。

## Next Step

**一个 30 分钟的动作，不需要任何新工具：**

1. 挑一个你手上**已经有自动检查**的环节（资产导入校验、VFX 预算估算、关卡碰撞检查都行）；
2. **把同一份输入跑五遍**（或换五次随机种子/五次人工重算），记录分数的极差；
3. 如果极差 > 你平时用来做决策的差值 ⇒ **这个评分的所有"细微改进"结论都作废**；
4. 再把最近一次"用分数做的决策"翻出来，问一句：**当时如果给的是报告（点名 + 理由 + 证据），结论会不一样吗？**

**做完这一步，你就把"自动评测"从"一个数"变成了"一把知道自己精度的尺子"。**
