实时毛发三刀 — Scheuermann 2004

Practical Real-Time Hair Rendering and Shading · ACM SIGGRAPH 2004 Sketches · ATI Research · 用于实时动画《Ruby: The Double Cross》

它要解决的问题：2003 年的 Marschner 物理模型（R / TT / TRT 三叶散射）很美，但三样东西都"太贵"—— 发丝几何太贵半透明排序太贵物理求值太贵

它的解法：三刀，把物理观察的结论（而不是方程）参数化，塞进 2004 年的实时硬件。 全文只有两篇参考文献——继承 Kajiya-Kay 1989（经验侧），逼近 Marschner 2003（物理侧）。 这篇就是两端之间的工程桥。

1模型刀：连续发丝 → 分层 2D 发片

发片层叠 = 用最少的几何近似最多头发的视觉密度

为什么选发片（原文三条理由）

  • 顶点负载低：比线渲染（每根头发一条曲线）便宜得多；
  • 排序简化：片数远少于三角形/发丝数——为刀 ③ 铺路；
  • 贴美术管线：多边形片 + 贴图，是美术的日常工具。

代价：自阴影不做真的——每顶点 AO（预处理算好）顶替。近看会穿帮（2026 年发丝化的动机之一）。

2着色刀：两个高光，一根"被掰弯"的切线

s 的大小从贴图里查（一张"切线偏移图"，相当于毛发的 normal map）；s 的正负号决定高光移向发梢还是发根

两个高光 = Marschner 观察的"参数化翻拍"

组件做法
漫反射max(0, 0.75×N·L + 0.25)
缩放+偏置 → 背光侧不死黑
主高光（≈R）白、尖、向发梢移位
次高光（≈TRT）受发色调制、宽、向发根移位，乘噪声贴图 → 闪烁感

不是仿真物理，而是把"物理观察到的视觉结论"直接写成两个移位高光项——这条"近似观察而非近似方程"的路子，此后被用了几十年。

3排序刀：取消运行时排序（静态索引缓冲 + 四趟渲染）

半透明发片要正确混合，需要 back-to-front。本文的做法：把排序从"运行时每帧"搬进"预处理一次"—— 按距头距离排好发片（连通分量，不是逐三角形），顺序固化进静态索引缓冲；运行时用四趟固定流程逼近。

趟Z 写Z 测剔除内容
① prime-Z✓（只写深度）—关背面剔除；alpha-test 掩掉透明区；不写颜色给不透明区先铺深度
② 不透明着色—equal—完整毛发 shader，只给与①相同的像素
③ 背面透明关less正面剔除所有背面透明区
④ 正面透明✓less背面剔除所有正面透明区
最值得记的一处：第①趟存在的理由不是"铺深度"，而是"避免后续趟使用 alpha-test"——因为 alpha-test 会禁用 early-Z。
原文："the extra rendering pass is more than offset by the gains of early-Z culling in the following three passes."
→ 通用判据：看到任何"加一步前置工作"的方案，先问它解锁了什么。这里多渲染一趟，解锁了随后三趟的 early-Z。
前提假设（原文明说）："we assume that the hair model only undergoes very moderate animation that doesn't move the hair patches much relative to each other." —— 静态排序成立的条件是发片间相对运动足够小；不成立时，回退到它刚省掉的 CPU 排序。 任何"预计算方案"的规格里，都应该有一行"它在什么条件下失效"。

跨越 22 年的回声：「取消式优化」

年份工作取消了什么用什么替代
2004Scheuermann（本文）运行时 CPU 空间排序静态索引缓冲 + 四趟固定流程
2026Stochastic GS Denoising高斯的显式排序固定光栅化顺序 + 神经去噪
2026CuACDkernel 边界与 host 同步全 GPU 常驻 + 设备端分配器

共同句式：「这个中间环节能不能不存在？」 —— 先问"能不能不存在"，再问"能不能更便宜"。
