程序化建筑 · CGA shape 与 ProxyBuild 对照图解

源头：Müller et al. 2006《Procedural Modeling of Buildings》（SIGGRAPH 2006）　×　前沿：ProxyBuild 2026（arXiv 2609.23386）

① 两阶段推导 —— 2006 年 CGA shape 的核心骨架

宏观 · 自由
质量模型（Mass Model）

用立方体 / 柱体 / 屋顶拼出体块。可任意旋转、收分（如 Petronas 塔）。此阶段只关心"体量"。

桥 · 关键一步
Component Split 抽面

把体块的每个面抽成"正确对齐、正确参数化"的二维 scope。表面不再是任意多边形，而是有坐标系的工作面。

微观 · 秩序
立面 / 屋顶规则

在二维 scope 上做 split / repeat：楼层、开窗、门、栏杆、屋面砖。规则永不需要面对"一般多边形"。

为什么必须两阶段？ 原文给出三条理由，最狠的一条："这些表面是算法的输出，而不是产生式规则的输出" —— 直接对可见立面写规则，等于让规则去面对算法的产物（凹口、多顶点、多洞）。规则必须作用在结构化的中间表示上。 这句话在 2026 年评估"生成式资产为什么不可编辑"时依然成立。

② 让"体块"与"细节"对上账的四种机制

Scope（作用域）

位置 P + 三正交轴 + 尺寸 S = 定向包围盒。所有规则的作用对象，L-system 龟形记号的演化。

规则形式 id : 前件 : 条件 ; 后件 : 概率

带优先级的推导：低细节先、高细节后，受控推进；形状标记为 inactive 而非删除——推导树可查询。

Occlusion 遮挡查询

返回 none / part / full 三态：能放窗放窗、不能放窗放墙、全遮挡删掉。优雅降级 2006 年就有了。 noparent 排除父形状是必须修正。

Snapping 吸附线

体块所有面 → 全局构建平面 → 楼层线自动跨全部体块对齐（塔楼收分处被强制对齐）。split 遇吸附线只改最近的切分。

③ 2006 → 2026：同一个"两阶段"，换掉了"谁写规则"

2006 · CGA shape（Müller 等） 2026 · ProxyBuild
输入 建筑用地 / GIS 足迹（可续造） 文本 + 已分块但无语义标签的壳（点云重建 / LoD2 数据）
中间表示 二维 scope（对齐+参数化的工作面） MAPP：面-边关联图 + 每个面/边的角色概率分布（含 Null 过滤）
结构从哪来 人写规则（庞贝：190 条手写规则；"rule authoring is laborious"） 网络推断（face-edge bigraph 预测角色）+ LLM 解析文本属性
几何从哪来 规则实例化终端对象 检索复用资产库（Sketchfab + Blender Geometry Nodes）
一致性靠 occlusion + snapping（跨体块对齐） 硬约束适配器（消融：去掉后 NCR 95.7%→73.6%，预测值不变 → 结构预测准 ≠ 摆放正确）
编辑性 改规则 → 全体再生 修正单个面/边的角色、加删组件、替换资产（落在"语义槽位"而非"网格顶点"）
2006 年原文写下的两个未来方向，2026 年被逐条兑现： ① "rule authoring is laborious" → ProxyBuild 用"推断 + 检索"绕开写规则； ② "employ shape grammars for shape understanding"（用形状文法做形状理解）→ ProxyBuild 的 face-edge 语义推断就是这个"理解模块"。

④ 谱系时间线（两篇同日入库，互为两端）

1975

Stiny《Shape Grammars》——建筑学形状文法，人工推导

1991

L-system 植物建模（Prusinkiewicz & Lindenmayer）——"生长"范式的辉煌

2001

Parish & Müller《Procedural Modeling of Cities》——城市级生成（简单体块 + shader）

2006

CGA shape：复杂体块 + 一致立面的两阶段解法 ★

2008

CityEngine 首商用版（Procedural Inc.）→ 2011 Esri 收购 → 行业标准工具

2026

ProxyBuild：LLM 属性解析 + 拓扑角色推断 + 检索组装 ★

两条可带走的判据：
① "规则（或生成）必须作用在结构化的中间表示上" —— 2006 年叫"二维 scope"，2026 年叫"角色概率分布"，本质是同一件事：给生成过程一个可对齐、可查询、可修正的工作面。
② "离线生成量与运行时负载是两本账" —— 2006 年：十亿多边形一天生成，但实时化"需要尚未开发的 LOD 技术，因为我们不优化一致拓扑"；2026 年：ProxyBuild 全是离线资产管线，同样不涉运行时。
