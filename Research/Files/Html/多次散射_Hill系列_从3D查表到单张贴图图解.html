"能量补偿"的工程史，可以用一句话概括：如何把"1 − E(μ)"这一个数，用越来越便宜的硬件形式交给运行时。 Hill 的四篇系列记录的就是中间那一段 —— 从"每个材质查一次 3D 表"，一路压到"所有材质共用一张 4 通道贴图 + 3 条 MAD"。

一、降维链：三次瘦身，每次都靠一个新借口

"降维链"出自 Part 3（①→②）与 Part 4（②→③）；每一步舍弃的误差都由下一步的前提兜底。

形态依赖维度运行时成本被舍弃的东西
3D LUTμo × rough × F0RGB 三次查表—（最准，最贵）
2D LUT（w 系数）μo × rough按阶数求和F0 高阶项（Schlick 线性性接管）
单贴图 + 3 MADμo × rough（4 通道）≈ 0高阶弹射的精确形状（重拟合兜底）
可复用判据：看一个表能不能降维，先看它依赖的材质参数在 BRDF 里是不是线性的。 Schlick 的 F = F0(1−s) + s 在 1994 年只是"便宜的近似"；26 年后它成了把 3D 表压成 2D 表的钥匙。

二、F_ms 修正：一次"重复计数"的账务更正

Imageworks 的多次散射 Fresnel 来自几何级数（每弹射一次乘 F_avg、继续弹射概率 1−E_avg）：

F_ms = F_avg·E_avg + F_avg·E_avg·F_avg(1−E_avg) + … 　→　含第一项（= 单散射）［重复计数］
修正：级数从第 2 项开始 + 归一化 → F_ms = F_avg²·E_avg / (1 − F_avg(1−E_avg))
勘误线索（务必沿用）：该式在课件里曾出错（Hill 自述 misedit），修正后并入 Imageworks slides v2（附 Kulla 的数值拟合）。 同族文献还有 Kulla-Conty 的 F_avg 勘误（Turquin 指出）。这一族公式在"课件 → 引擎"链上反复出错 —— 落 shader 前先找勘误。

三、预计算算法：随机游走 + 能量吞吐向量

把"F0 的各阶系数"直接算出来 —— 每次游走携带一个向量，跟踪"被 F0^i 缩放的能量份额"：

// 每次散射事件（Schlick 因子 s）：
for (int i = N - 1; i > 0; i--)
    e[i] = mix(e[i - 1], e[i], s);   // e[i] = s·e[i] + (1−s)·e[i−1]
e[0] *= s;

// 多次游走后取平均（单散射游走计零）→ w0 … wN−1

四、它在谱系中的位置

五、带走三条

  1. 修正的是账务，不是物理 —— "补能量"最常见的 bug 是把已经算过的份额重复计入（F_avg → F_avg²）。
  2. 降维不是一次完成的 —— 3D→2D 靠 Schlick 线性性；2D→单贴图靠"能量集中在前几阶"。每一刀都需要一个新的数学借口。
  3. "更准 vs 能用"在方案内部继续分家 —— 完全精确要 2–3 张贴图；能用的版本 3 条 MAD。工程的答案永远是"够准 + 免费"。
