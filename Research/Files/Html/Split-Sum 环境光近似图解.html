Split-Sum — 环境光镜面反射怎么变成两次查表

Karis 2013 · 没有新物理，只是把"随视角变化的部分"从积分里剥离出来

要算的东西（每像素对半球积分）：

L_o = ∫ L_i(l) · f(l,v) · cosθ_l dl ≈ (1/N) Σ L_i(l_k) f(l_k,v) cosθ_l / p(l_k,v) ← 重要性采样，原文用 1024 次

拆成两项的乘积（式 7）：

L_o ≈ ( 1/N Σ L_i ) × ( 1/N Σ f·cosθ / p ) └── 只有环境 ──┘ └─── 只有 BRDF ───┘ = PrefilteredColor(R, Roughness) × ( F0·A + B ) 其中 (F0·A + B) 来自把 Schlick 的 F 代入后 F0 可以提出积分（式 8）： ∫ f·cosθ dl = F0·∫ f/F·(1−(1−v·h)⁵)·cosθ dl + ∫ f/F·(1−v·h)⁵·cosθ dl └──────── A（scale）────────┘ └───── B（bias）─────┘

能拆的前提是 F 用 Schlick 的线性形式。 精确 Fresnel（含偏振、复折射率）做不到这一步 —— 这是 Schlick 那个"顺手给的近似"的第二份红利：不只便宜，而且可分解。

运行时：两次查表

核心量级对比：离线 1024 次重要性采样 → 运行时 1 次 cubemap 采样 + 1 次 LUT 采样 + 1 次乘法。 这不是"优化了一点"，这是把 IBL 从"不可能实时"变成"固定开销"。

两个近似：哪个更要紧（Karis 自己排过序）

近似内容视觉后果严重程度
① n = v = r 预滤波时假设"法线 = 视线 = 反射方向"，于是可以脱离视角预存一张 mip 链 掠射角得不到"抻长"的反射；各向异性高光形态丢失 较大（原文原话：compared with the split sum approximation, this is actually the larger source of error）
② split-sum 本身 把一次积分拆成两个独立积分的乘积 环境含高频亮源（太阳、窗、灯带）且表面较粗糙时，能量分布错位 较小（"对常数 L 精确，对常见环境相当准"）
最值钱的一条判据：人们通常担心 split-sum 准不准，而作者说真正的误差在它旁边那一刀。评估任何预计算方案，先看"为了让结果可预存，额外假设了什么" —— 通常那一刀比公式本身的近似更贵。

成本与分档（把它当预算项看）

项性质随什么增长你的分档旋钮
预滤波 cubemap固定开销（1 次采样）与光源数无关，与 lobe 数 成正比分辨率 / mip 数 / 是否实时捕获
EnvBRDF LUT固定开销（1 次采样）同上R16G16 → R8G8；移动端可换解析拟合
多 lobe（Clearcoat / Aniso / Hair）乘法：每个 lobe 一份 IBLlobe 组合数低档砍 lobe，而不是砍精度
  • 和动态灯光预算是此消彼长的：环境光（IBL）能让场景在没有动态光源时也"有光"，这正是 MegaLights / 神经 GI 路线要抢的位置；
  • 它不含间接光：split-sum 只算"环境贴图对表面的镜面反射"，不含场景间反弹 —— 那是 [[Global Illumination]] 的另一条线（Lumen / MegaLights / 神经 GI）；
  • 2026 的新问题：当画面真实感由生成模型补齐（DLSS 5 一类），IBL 的精度还值多少预算？ 这个问题目前没有答案，但它就是你分档表未来可能要重排的地方。
一句话带走：split-sum = 把"随视角变化"的耦合断开，让另一半可以脱离场景预先算死。把它记住的方式是记住那个假设（n=v=r），而不是记住那两行公式。
