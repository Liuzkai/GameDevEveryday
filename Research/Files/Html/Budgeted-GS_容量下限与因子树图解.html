Budgeted-GS — 容量下限与因子树

Real-Time Large-Scale Gaussian Splatting via Factoring LOD · Haipeng Wang（Neusoft）· EG 2027 投稿预印本 · arXiv:2610.03162 · 2026-10-05 入库（未公告先见）

一句话：把 city-scale 3DGS 的"该用多少 primitive"从习惯问题变成可测量、可认证的理论问题—— 误差随预算以 N−1/2 下降（Zador 定律），并据此做出"部署时单参数选 LOD"与"训练时直接长在正确尺寸"两个方法。
答卷：官方城市数据、单张 4080 SUPER、1080p 原生全 SH、71 fps。

一、率-失真曲线 —— 预算到底该定在哪

读法曲线陡降段的花费是"买容量"，平坦段的花费是"买安慰"。预算的正确答案 = 陡降与平坦的拐点（knee）——BCT 直接在 knee 训练，"生来就是正确尺寸"。

组件内容回答
容量下限（Zador 定律）R(N) ≍ C·‖λ‖·N−2/d_ps；表面场景 d_ps=4 → −1/2不可避免的误差是多少
合并许可（Wang–Zahl 2025）Kakeya 三维猜想解决定理的加权重释：局部"过度覆盖"处可合并，损失只有常数级哪些组冗余（"第一次把 Kakeya 理论用于渲染"）

三种基元的速率（论文附加结论）

三角形 N⁻¹ ｜ 点基元 N⁻¹ᐟ²（3DGS 属此族） ｜ 各向同性体素 N⁻¹ᐟ⁴ "最优单元恰是各向异性协方差椭球原子 —— 正是 3DGS 拟合的东西。"

"源受限 vs 目标受限"：自由松弛是目标受限（N^(−2/d_c)）；渲染实例是源受限（N^(−2/d_ps)，d_ps ≥ d_c）——"primitive 必须能渲染、不只是匹配颜色"是速率变慢的原因。

三、Factoring LOD —— 一个模型变一棵树

1训练好的模型：每个 primitive → plank（μ, R, h=3σ, α）——"场景原本就是一堆带透明度的定向盒子"
▼ GPU 八叉树（叶容量 4096）
2叶内按尺度分带：ℓ = ⌊log₂(s/s_base)⌋（s_base = 5% 分位）
▼ 每（叶, 带）→ 批量矩匹配 → ≤256 个等价 plank
3守恒三量：加权体积 W · 质心 c* · 惯性张量 T*（SH 颜色进一阶矩）→ 特征分解得等价 plank（c*, R*, h*, w*）
▼ 内部节点自底向上同样聚合
4构建几秒（单 GPU）；聚合表示比输入小 119×；原始 primitive 保留最细层（Morton 序）

四、渲染：单参数 c 扫过全部档位

像素脚印调度器：对每个（叶,带）算阈值 t = c · d / f，落入三层之一：

raw

成员可分辨（s̄ ≥ t）→ 渲染原始高斯

fine

簇可分辨、成员不可 → 渲染 fine 等价 plank

coarse

亚像素 → 渲染单个聚合 plank

c 是唯一的质量旋钮：c=1 = 可分辨参考档；c 越大越合并；c<1 保留亚像素内容（超分）。选择是分辨率不变的（800² 与 1080p 同预算下物化集合相同）；选择与收集全在 GPU（无 CPU 侧收集、无 host 上传）。
