### ✅ [[2026-10-21-Zhang — Matrix-Game 4.0 Harnessing Video Models for Real-Time Playable Game Worlds|Matrix-Game 4.0]]（2610.27999，A，今日头条）

**为什么重要**：它把"世界模型"从"像素预测得准不准"改写成了**"规则由谁执行"**。三角色硬分工：

| 角色 | 负责 | 明确不负责 |
|---|---|---|
| **agent** | 写规则（结构化 JSON，不是自由文本） | 不写画面 |
| **引擎** | 执行规则、维护 world state、出 low-poly 帧 | 不管画质 |
| **视频模型** | 把 low-poly 帧"重画"成 RGB | 不碰状态、不碰规则 |

**今日最该带走的一条（本库首次出现）**：**规则可执行 ⇒ 标注可零模型推断**。它的 114,334 段训练配对（1,712 小时、1280×720），字幕不是 VLM 事后看图写的，而是**规则模板直接从 world state 渲染**出来的。这让三件事同时成立：标注成本≈0 且零幻觉；配对天然像素对齐（引擎同帧出 low-poly 与 RGB）；**换一条规则就换一个数据分布——数据规模由规则空间决定，不由拍摄预算决定**。

**工程侧**：三阶段因果蒸馏（SFT → 因果一致性蒸馏 → 非对称 DMD，80% 步喂 TAEHV 编码）+ 九项推理优化，**4.5 → 83.4 FPS，1110 → 112 ms**（RTX 5090，480p），并给出 5090 / 5080 / 5070Ti 三档硬件表。三层 KV 结构（3 记忆帧 + 参考帧 + 最近 20 chunk，t=0 重跑写干净 KV）是长时一致性的关键——**"重算一帧换 KV 干净"比"设计更聪明的缓存"便宜**。

**Personal Relevance**：① **这是库内第一个"能出画面、能出标签、能出反事实"三项齐备的样本**——判据已写入 [[World Models for Games]] 第四维度；② 对已有引擎的团队（你），**唯一不必外购视频数据的路径就在这里**：low-poly 白模 + 规则脚本量产配对，代价是要先有可脚本化的规则层；③ **别当渲染方案读**——它的 83.4 FPS 是系统账（砍"每帧必须重算什么"），不是模型账；这套减法清单本身比它的画质更有用。

### ✅ [[2026-10-21-Kim — RLSplat Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting|RLSplat]]（2610.27712，A）

**为什么重要**：标题里的 "Resource-Linear Budget Control" 就是它的全部主张——**预算不是事后裁剪，是生成时的配额**。前馈 GS 先生成一大堆再裁，成本随候选数涨；RLSplat 反着来：GSPO 策略网络学一组高斯配额 $k\sim\mathrm{Mult}(B,p)$（$\sum k_n=B$），再用**资源线性**解码器只用 $O(BK_{gs})$ 的局部 cross-attn 把该有的取出来。

**数字**：2K 预算下 **+0.9 dB**，显存 **9.6× 少**，速度 **4.1×**。三个正则缺一不可：去掉 Voronoi **−2.51 dB**、去掉 offset **−0.53 dB**、去掉投影正则**直接训崩**。

**必须说的一条（诚实点）**：**策略 24.83 dB vs Sobel 边缘启发式 24.76 dB，只差 0.07 dB**。也就是说它学到的**不是"更聪明的先验"，而是"分配这个动作本身"**——换任何合理的空间启发式都能拿到几乎同样的质量。这不是缺点，是**这篇论文最有价值的结论**：在预算分配问题上，**"让分配变成可学习的一步"比"设计更好的重要性度量"更值钱**。你若要在项目里做类似机制，别先优化重要性函数。

**Personal Relevance**：这是 GS 预算线的**成本侧**（此前库内 Budgeted-GS 是容量侧、Confidence-Aware 是生长侧）。对你更直接的启发性在**思维迁移**：技能 VFX 目前的降档是"生成后砍粒子"，如果改成"生成时按档位配额"，砍掉的成本本身就是收益。

### ✅ [[2026-10-21-Beche — KoalaGS Complexity-Aware Continuous Level of Detail for Gaussian Splatting|KoalaGS]]（2610.28615，B+，NeurIPS 2026 Spotlight）

**为什么重要**：它指出排序键（$S=\alpha+\lambda s$，不透明度 × 体积）**缺一个"覆盖面积"因子**——细小但必要的高斯排在后面就被砍了。解法是用**优化前就能算**的图像复杂度（delentropy，2D $\rho\approx-0.60$ / 3D $-0.64$，全库里相关性最强的一个指标）当空间先验：训练时按 $p=\alpha e^{\tilde C}$ 给迁移偏置 + complexity dropout（$\delta=0.2$），渲染时排序键 $S=\alpha+\lambda s/e^{\tilde C}$ + 残差方差正则。

**数字与边界（如实）**：100% → 0.1% **连续全谱**评测（不是几个离散档，这点比多数 LoD 论文扎实）；但对 MGS 只 **+0.12 / +1.23 dB**，主要增益来自与"完全不排序"的 MCMC 对比。**先验有用，但没有它论文标题听起来那么有用。**

**Personal Relevance**：**"先验在训练前就可得"这条最值钱**——复杂度是图像本身的属性，不需要跑一遍优化才知道哪里重要。对你的 VFX 预算：**"这个技能在屏幕上占多大、变化多剧烈"是可以从设计稿/白模阶段估出来的**，不必等实测。

**记名（今日入库 3 篇，其余 6 条只记名，不建页）**：

- **Joints, Camera, Action!**（2610.28632）：任意 rig 的 3D 运动 + 视频**联合生成**，含相机配准——与库内 CAST（拓扑感知动捕）/ PriMoRetarget（优先级重定向）同一目标域，且是"运动与视频互为监督"的形态；动画线候选，**等代码**；

## Classical Research

### [[Tessendorf 2001 — Simulating Ocean Water]]

**Historical Role**：**"水的第二条路"的开篇**——而且它的合法性来源与 Stam 1999 完全相反。

Stam 1999（库内已有）**解方程**：把 Navier-Stokes 一步一步推，无条件稳定。Tessendorf 2001 **不解方程**：它按 Phillips 谱 $P_h(k)=A\frac{e^{-1/(kL)^2}}{k^4}|\hat k\cdot\hat w|^2$ **采随机波的统计分布**，一次 IFFT 出整张海面。于是：

$$h(x,t)=\sum_k \tilde h_0(k)\,e^{i(k\cdot x-\omega t)},\qquad \omega=\sqrt{gk}$$

四步配方：**谱 → 高斯随机相位 $\tilde h_0$ → 色散定相速 → IFFT**。二十年后所有实时海面仍是这四步。

**成本模型是这次阅读最大的收获**：FFT 路线是**固定成本**——一次 $N\log N$，与海面多大、浪多密无关；CFD 路线是**按元素计费**——网格越细越贵。这解释了为什么游戏选 FFT 而不选 CFD：**不是因为它更真，是因为它的价格可预测**。

**但固定成本有结构性代价（必须一起记住）**：

1. **必须可分解**——每条波独立叠加，波与波不相互作用（所以没有破浪、没有白冠的动力学）；
2. **必须可周期**——量化色散 $\omega=\sqrt{gk}$ 到最近的 $2\pi/T$ 才不撕裂，于是海面**有循环周期**（图 8），周期内会看到重复；
3. **不可剔除**——不能"这一道浪打在岩石上溅开"，因为浪不是实体。

**三个可直接用的工具**（这是它比"看起来更真"更值钱的部分）：

- **Creamer 尖锐位移**：把高度场当位移场，尖峰自然变尖（不做这个，海面永远像塑料布）；
- **Jacobian $J<0$ 作泡沫遮罩**（图 16）：泡沫不是另算一套粒子，而是**在位移已经算出来的地方顺手判一次**——"拿已算出来的量免费再用一次"的最干净范例；
- **$\epsilon=\nabla h$ 频域求斜率**：法线不用差分，在频域乘 $ik$ 就有，质量与成本同时更好。

**iWave 一支**（同文后半）：对变水深与物体扰动，解**显式波动方程**而不是谱合成——这是"谱合成 ↔ 波动方程"的第三条路，也是可交互水面（船、浮标）的来源。

**Knowledge Graph Role**：

- **补上 [[Fluid Simulation]] 的"水的两条路"**：Stam 1999（解方程，按元素计费）↔ Tessendorf 2001（采统计，固定成本）——概念页时间线已插 2001 节点，新增小节说明"预算判据"（要可交互可扰动 → CFD/iWave；要无边海面一直循环 → FFT）；
- **与 [[2026-10-09-Make It Flow — Animating Water in 3D Gaussian Splatting Scenes|Make It Flow]]（10-13 入库）构成第三种"水怎么来"**：不模拟也不采样，**从视频里抽光流注入**——三条路的成本结构分别是"按元素 / 固定 / 一次性"，这个三分法比"精度高低"有用；
- 与 [[Particle Systems]] 的接口：**水面历来不是粒子系统问题**——这也是为什么它在库内长期缺位（此前 VFX 视角只看到"溅起来的水花"，看不到"水面本身"）；
- 3 图原图提取（图 8 色散量化 / 图 12 三张渲染海面 / 图 16 Jacobian 泡沫遮罩）——视觉政策第 8 次执行，全程原图、无 HTML。

## Technology Evolution

```text
"水怎么来"的三条路（成本结构决定适用场景）：

1999 解方程    Stam：Navier-Stokes 逐步推进        → 按元素计费
              优：可交互、可加障碍、可扰动        劣：网格越细越贵
2001 采统计    Tessendorf：Phillips 谱 + 一次 IFFT → 固定成本
              优：价格可预测、无边海面            劣：不可剔除、只能循环
2026 注入      Make It Flow：光流 → 3D 欧拉场      → 一次性（离线）
              优：几乎零运行时                      劣：不能响应新交互
```

**同一现象，三种"合法性"**——这不是精度阶梯，是**三种不同的成本契约**。选哪条，取决于"这个水面要不要回应玩家"，而不是"哪条更物理"。

**这条轴可以直接迁移到粒子/特效**：今天的技能 VFX 几乎全在"按元素计费"（每颗粒子都算），而水面的教训是——**凡是"看起来像连续介质、且不需要逐点回应"的视觉，都值得问一句"能不能换成固定成本"**。

## Emerging Trends

- **"预算"一词在库内已分裂成四种计价对象**（今日成型）：**容量**（Budgeted-GS：误差 ∝ N⁻¹ᐟ²）/ **成本**（RLSplat：资源线性 $O(BK)$）/ **精度**（CurveCodec：误差界 0.01–1 cm）/ **时间**（MG4.0：每帧必须重算什么）。**它们对"降档"的定义完全不同**——容量降档是"少画一点"，成本降档是"每个便宜一点"，精度降档是"承诺放宽一点"，时间降档是"把计算挪到帧外"。这是本库目前对"预算"最细的一份分类，已写入 [[Personal Knowledge Model]]；

## Key Takeaways

1. **水面经典给的不是"更真的水"，是一份"成本契约"的范本**：FFT 海面价格固定、CFD 按元素计费、光流注入一次性——**选哪条取决于"要不要回应交互"**。把它搬到你自己的领域：凡是"看起来像连续介质、且不需要逐点回应"的视觉（雾、烟、能量场、地面湿润），都值得问一句**"能不能从按元素计费换成固定成本"**；
2. **"规则可执行 ⇒ 标注零模型推断"是今日最可迁移的一条**（MG4.0）：它把"数据规模"从拍摄预算里解放出来，改由规则空间决定。对已有引擎的团队，这是唯一不必外购视频数据的世界模型路径——**代价是要先有可脚本化的规则层**；
3. **预算有四种计价对象**（容量 / 成本 / 精度 / 时间），**它们对"降档"的定义不同**。你的 SABC 表目前只分配了"容量"那一份；C 档技能真正的痛点常在"时间"（帧内重算什么）与"成本"（多一个敌人同屏时每个元素的代价）——**这两本账值得单独建页**；
4. **RLSplat 的 0.07 dB 比它的 24.83 dB 更值得记**：在"分配"这类问题上，**让分配变成可学习的一步**，比设计更聪明的重要性度量更值钱——别先优化先验；
5. **动作月第 10 日，读的存量在涨、做的存量不动**：这不是意志问题，是设计问题。**把最便宜的一件降级成 3 分钟版本，只为破零**（今日已给出动态灯光复审的 3 分钟版）。
