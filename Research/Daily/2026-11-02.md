### ✅ [[2026-10-29-Choi — L3G-World Real-Time Infinite World Generation with Latent 3D Gaussian Memory|L3G-World]]（A- 前沿）

- **记忆的第三种解法：只写缺口**。此前两条路各死一头——按时间存（$O(TR)$）必然 OOM，按空间存（$O(S)$）慢到 0.10 FPS。L3G 同时改两件事：**只在"渲出来不对"的地方长新高斯**（先渲旧记忆 → 用 opacity 与误差出 spawn mask → **只在 mask 内** K-means 初始化 spawn query），**每个高斯里直接存 VAE latent**。
- **全文最干净的一个数**：把高斯里的 VAE latent 拿掉、改回"渲成 RGB → VAE 重编码"，VAE 空间渲染 **943.6 → 2.97 FPS（318×）**。**这就是接口税的字面价格。**
- 其余收益：相比最省的 3D 记忆基线，图元少 **26.7–38.9×**、重建快 **3.0–3.2×**、VAE 空间渲染快 **349–359×**；端到端 **9.02 FPS @480×832 / 单卡 H100**。
- **两处必须保留的诚实点**：① 9 FPS 是"相对同类（0.10–1.99 FPS）的实时"，不是"相对游戏（60 FPS、1080p）的实时"，**差一个数量级算力**；② 三个质量指标里 **PSNR / LPIPS 赢、SSIM 输**（0.441 vs 0.525），且消融里"去掉 VAE lifting"那版 PSNR 反而更高——**说明它买到的是"不崩"，不是"更像"**。
- **读图**：[[Research/Files/Pictures/Choi 2026 — 图2 L3G-Mem 自适应生成与精修架构.png|图 2]]——左侧两路 token（spawn / refine）在 global self-attn 处交换信息，右侧 latent-lifting 分支按通道拼进 query。**注意那个"先筛再聚类"的顺序**：消融里改成"对全部几何特征聚类"，图元从 41K 涨到 75K（1.8×），**这 1.8× 就是"先筛"省下来的**。

### ✅ [[2026-10-25-Sun — TopX Text-to-Motion for Unseen Skeletons from the Skeleton File Alone|TopX]]（A- 前沿）

- **把"跨骨架"这一维的基准重做了**。以往问的是"能不能迁移到新骨架"，TopX 改问：**骨架文件本身够不够当接口？**——一棵树、一个 rest pose、一串关节名，**不看网格、不看动作数据**（图 1 左上角那几个字 "No motion clips" 是全文的立场声明）。
- **三个设计各治一处"任意性"**：① 归一化用 rest pose 与骨架尺寸（治"没有动作统计"）；② 世界系描述子用骨骼的世界方向与相对根位置（治"每个关节的 rest frame 朝哪是作者随便定的"）；③ **HK-RoPE**（治"关节顺序与拉普拉斯特征基也是随便定的"）。
- **HK-RoPE 靠一句线性代数站住**：热核签名 $h_j(\tau)=\sum_{k\ge1}e^{-\tau\lambda_k}v_{kj}^2$，其中 $v_{kj}^2$ 在特征空间求和 = **投影算子对角元**，与基的选取、符号、重根全部无关——**所以它不需要 SignNet**。这不是洁癖：**5,127 个训练骨架里有 3,210 个（63%）在前 8 个非平凡模态内出现重根**，重根是常态不是边角。
- **一处必须自己泼的冷水**：消融里"换掉 HK-RoPE"只贵 **0.05**（1.78 → 1.83），**而离真值还差 1.64**。**真正的贡献是"整套接口设计"，不是某一个编码**——这条对项目里的技术评审同样成立：**别把"消融差异小"直接读成"组件没用"**，要看它在整条链上的位置。
- **读图**：[[Research/Files/Pictures/Sun 2026 — 图1 TopX 从骨架文件直接生成总览.png|图 1]]——左下那块是今天最该看的：**同一套配色（core → ends）在剑龙（40 关节）、人（22）、蜘蛛（61）三副骨架上给出相同的结构位置**，颜色是热核签名第一主成分的 log 值。**关节数完全不同，颜色分布却是同构的**——这就是"8 个标量概括一棵树"的字面样子。

### ✅ [[2026-10-29-Li — Fight World Model Customizable Combat through Visual Interaction Proxies|Fight World Model]]（A- 前沿）

- **世界模型最尴尬处不是画不出打斗，是改一条规则就要重训**。FWM 把"规则执行"和"画面渲染"彻底分开：可执行引擎算状态与事件 → **确定性编译器**压成一张**交互代理**（框 / 朝向 / 动作窗 / 技能窗 / 受击闪 / 血条）→ 渲染器只吃这张代理。**改伤害、改免伤、改吸血，代理格式不变，渲染器一个参数不动。**
- **代理的分层依据只有一句**：*规则能独立改动的地方，就必须独立编码*。于是"尝试的动作"（动作窗/技能窗）、"瞬时的反应"（受击闪）、"持久的状态"（血条）分成三条通道——因为"被保护的一击"要求"有反应、不掉血"，**一根通道表达不了**。
- **数字最干净的两组**：改规则（吸血）后血量误差 **0.19 vs 10.46**（对照：把规则写成文本）、联合保真度 **99.87 vs 16.83**；身份 slot 绑定把换边后的外观遵循度从 **53.68% 拉到 98.27%**（+45 点）。**换边是最狠的测试**——外观相同、左右互换，如果绑定靠位置，它必然崩。
- **一组必须保留的边界**：规则干预那组实验的"真值"**就是代理本身**，所以它测的是"**渲染器有没有忠实执行代理**"，不是"规则引擎算得对不对"。**这正是它要证的命题，但不能当"游戏逻辑正确性"引用。**
- **Table 2 是全篇最有价值的一张表**：纯空间代理（框 + 朝向）在"移动"上已有 99.19%，但**技能只有 46.58%**——因为空间代理**没有时间**；加文本到 92.43%，加状态 token 到 82.42%（文本更强）；**交互代理把三者同时推到 99% 以上**。**差的从来不是信息量，是信息的形状。**
- **读图**：[[Research/Files/Pictures/Li 2026 — 图2 FWM 从规则执行到交互代理的管线.png|图 2]]——规则引擎与渲染器之间只有一张代理图，两侧互不知道对方的内部；[[Research/Files/Pictures/Li 2026 — 图6 规则改动下的血量状态对比.png|图 6]]——同一段互殴在"普通 / 限次免伤 / 吸血"三条规则下血条走向分岔，而画面风格完全一致。**这张图就是"规则可换、渲染不重训"的证据。**

## 经典线：[[Mildenhall 2020 — NeRF Representing Scenes as Neural Radiance Fields|NeRF: Representing Scenes as Neural Radiance Fields for View Synthesis]]（A 经典·历史重要性 5）

**为什么补这一篇**：本库已有 **30+ 篇 3DGS 变体**，但它们的共同祖先一直缺页——`[[Radiance Fields]]` 是个悬空链接，GS 页只能反复用"NeRF 式的"这种二手措辞。今天把这笔账结清。

- **接口只有两个函数**：$F_\Theta:(\mathbf x,\mathbf d)\to(\mathbf c,\sigma)$。**一个 MLP 就是一个场景**，没有网格、没有体素、没有 kd-tree。
- **成本必须按"查询次数"记**：800×800 的一张图 = 64 万条光线 × **192 次查询/光线**（64 粗 + 128 细）≈ **1.5–2 亿次网络查询**，V100 上 **约 30 秒一帧**。**说"渲染一张图"等于没说，"1.5 亿次查询"才是账。**
- **两条"预算按分布分配"的原始设计**：① 分层采样——粗网络 64 点估出 $\hat\sigma$，归一化成 PDF，**只在有东西的 128 点上跑细网络**；② 位置编码 $\gamma$（$\mathbf x$ 用 $L=10$ → 60 维，$\mathbf d$ 用 $L=4$ → 24 维）——**把 $F_\Theta$ 重写成 $F'_\Theta\circ\gamma$：一个不学的、一个学的**。
- **Table 2 最承重的一行是"去掉视角依赖"−3.35 dB**：颜色不再依赖方向，**镜面反射无处表达**。这条对做 VFX 的人有直接含义——**"视角相关"不是可选的润色，它是一整类物理**。
- **读图**：[[Research/Files/Pictures/Mildenhall 2020 — 图2 NeRF 管线.png|图 2]]——五步管线里第 ④ 步（体渲染积分）就是今天主线的原型：**把 192 个样本翻成一个像素，翻译次数写在结构里**；[[Research/Files/Pictures/Mildenhall 2020 — 图4 视角依赖与位置编码消融.png|图 4]]——第三列履带白高光消失（−3.35 dB），第四列链节结构整体糊掉（−2.24 dB）。**两列的失效方式完全不同：一个是少了某类物理，一个是少了某个频段。**

## 今日主线：接口——真正贵的是翻译，不是数据量

### 四个领域，同一笔账

| | 上游 | 下游 | 接口是什么 | 翻译税（实测） |
|---|---|---|---|---|
| **NeRF 2020** | 场景（一个场） | 渲染器（体渲染积分） | **查询** $(\mathbf x,\mathbf d)\to(\mathbf c,\sigma)$ | 192 次/光线 → 1.5–2 亿次/帧 → **30 s/帧** |
| **L3G 2026** | 记忆（高斯） | 生成器（DiT latent） | **latent** | 若改回 RGB→VAE 重编码：**943.6 → 2.97 FPS（318×）** |
| **TopX 2026** | 骨架文件 | 动作生成器 | **树 + rest pose + 关节名** | 若改回"学习式位置表"：1.78 → 1.88（**但整套接口离真值 1.64**） |
| **FWM 2026** | 规则引擎 | 视频渲染器 | **交互代理**（框/窗/事件/血条） | 纯空间代理技能 **46.58%** → 交互代理 **99%+** |

**四行放在一起，指向同一个结论：接口的贵，不是"数据要搬多远"，而是"两侧的原生表示差多远"。**

### 三种把翻译税降下来的手法

1. **让上游直接产出下游的原生格式**（L3G）。高斯里不放颜色、放 latent——因为下游（DiT）要的就是 latent。**代价是接口绑死在"这一个下游"上**：换一个不用 VAE 的生成器，这 318× 立刻归零。
2. **让接口对上游的"任意选择"不变**（TopX）。关节顺序、特征基符号、rest frame 朝向，全是建模师随手定的——**接口不能依赖这些**。热核签名做到的正是这件事：它不是"更好的编码"，它是**一个对任意性免疫的量**。
3. **让接口的形状按"下游要分辨什么"来设计**（FWM）。下游要分辨"在挥剑"还是"在挨打"，所以接口必须有**时间窗**和**事件位**——把这两样塞进文本，信息一点没少（92.43%），**但形状错了，渲染器读不出来**。

### 一条反过来的判据：翻译被藏起来的时候最贵

L3G 正文里有一句几乎没被强调的话，但它是全篇最锋利的：**世界模型的 3D 记忆路线（GEN3C / Spatia / SPMem / Lyra 2.0 / NeoVerse）"每次做条件都要重编码一遍"，而没人把这笔算进 FPS。**

**这正是接口成本的典型死法——它不出现在任何一个模块的耗时里，它出现在"模块之间"。** 每个人都在优化自己的 kernel，而那条 RGB→latent 的往返被当成了"胶水"，不计量。

同样的结构在 NeRF 里也有一份：**权重只有几 MB**（比任何体素表示都小），**但它一帧要查 1.5 亿次**——**内存与时间在这里彻底解耦**。所以那条判据要改写成：

> **判断一个表示贵不贵，别看它占多少内存，看"查询一次多少钱"×"一帧要查多少次"。**

### 对项目（NGR / 技能 VFX）的直接含义

技能系统 → 粒子/渲染系统之间也有这条缝，而且通常是三步翻译：**策划表（配置）→ 运行时结构（GameplayEffect / Niagara 参数）→ GPU 缓冲（粒子属性）**。

- **按"翻译次数"记预算，而不是按"数据量"**：同屏 3000 颗粒子，如果每颗每帧要做一次 CPU→GPU 的属性查表，成本不是 3000，是 **3000 × 帧数 × 查表次数**——**这正是 NeRF 的 192 次/光线的同构**。
- **第七维（机制预算）其实就是"接口维度"**：11-01 提出的"判定段数 + 窗口长度"，本质是**要求技能配置里带上"时间窗"和"事件位"**——**和 FWM 的交互代理是同一个设计动作**：让下游能分辨"在打"还是"被打"。
- **一条可以马上做的自查**：*我们有没有哪一步是"先算成通用格式、再转回专用格式"？*（L3G 的 318× 就藏在这种往返里。项目里最常见的版本是：**先烘成贴图，再在 shader 里解回数值**。）

## Important Relationships

- **[[Mildenhall 2020 — NeRF Representing Scenes as Neural Radiance Fields|NeRF 2020]] ↔ [[Gaussian Splatting]] 全体**：**祖先与 30 个后代**。GS 的每个设计选择几乎都是对 NeRF 某条成本项的回应——可微光栅化（替代逐光线查询）、逐基元排序（替代 192 次采样）、显式存储（替代 MLP 的隐式）。**读 GS 变体时如果不知道这一层，就会把工程取舍当成方法创新**；
- **[[Mildenhall 2020 — NeRF Representing Scenes as Neural Radiance Fields|NeRF 2020]] ↔ [[2026-10-29-Choi — L3G-World Real-Time Infinite World Generation with Latent 3D Gaussian Memory|L3G]]**：**同一条判据的两端**。NeRF 把"内存与时间解耦"（几 MB 权重 / 1.5 亿次查询），L3G 把"翻译与解码解耦"（高斯里存 latent / 免 318× 重编码）。**两篇都在说：账不能记在存储上**；
- **[[2026-10-29-Choi — L3G-World Real-Time Infinite World Generation with Latent 3D Gaussian Memory|L3G]] ↔ [[2026-10-26-Liu — WorldPager Zero-Stall Tiered Memory for Long-Horizon World Models|WorldPager]]**：**两堵墙，各推一面**。WorldPager 解决"位置墙"（KV 放哪、怎么预取，45 秒 → 37.5 分钟），L3G 解决"容量墙"（$O(S)$ 而非 $O(TR)$）——**但 L3G 完全没碰位置墙**（无预取、无分层，只有"当前窗口看到什么就修什么"）。**两篇合起来才是一个完整的内存系统**；
- **[[2026-10-25-Sun — TopX Text-to-Motion for Unseen Skeletons from the Skeleton File Alone|TopX]] ↔ [[UniMate — One Unified Model to Animate Diverse Skeletons|UniMate]]**：**同题不同解，且互为正反例**。UniMate 用谱编码 + SignNet 处理符号歧义；TopX 用热核签名**绕过**歧义本身（$v_{kj}^2$ 求和 = 投影算子对角元，与基/符号/重根无关）。**TopX 的 63% 重根统计正是 SignNet 类方法的失效边界**——这不是"更准"，是"换了个不受影响的量"；
- **[[2026-10-29-Li — Fight World Model Customizable Combat through Visual Interaction Proxies|FWM]] ↔ [[2026-10-26-Wu — BoxWorld Let World Engines Control and Video Generators Render|BoxWorld]]**：**同一天（10-29 入库）的两次"规则写成代码"，分歧在"状态给谁看"**。BoxWorld 的对象三字段（框 / 属性 / 状态位）驱动一个编码 agent 生成的引擎，Paired-CF 97.3%，**但 oracle（把后果当文本喂）仍是 16.2% ⇒ 缺的不是信息，是条件分支原语**。FWM 的代理则把"分支后的后果"**做成可视的**（受击闪 / 血条），所以渲染器能"读"到规则。**接口的形态决定了"规则"能不能被下游消费**；
- **[[2026-10-29-Li — Fight World Model Customizable Combat through Visual Interaction Proxies|FWM]] ↔ [[2026-10-22-Liu — AnyGameRenderer Entity-Consistent Generative Rendering Across Games|AnyGameRenderer]]**：**接口厚度轴的两端**。AnyGameRenderer 喂纯视频 + 字幕（**弱表示、通用、慢**），FWM 喂结构化代理（**强表示、快、窄——但只支持固定 2D 视角与单一品类**）。**这条轴的斜率今天可以量化了：表示越强，越贵在"只适用一个品类"上。**

## Emerging Trends

- **"接口税"正在被写进正文，而不是留在脚注里**：L3G 主动报 318×（并且用它当核心卖点），FWM 主动报"纯空间代理技能只有 46.58%"。**这是一种新的论文写法——把"我们省掉了哪一步翻译"当成第一贡献，而不是把指标刷高**。对读论文的人是好消息：**这类数字比 SOTA 表更能迁移到工程**；
- **"任意性"开始被当成一个可设计、可消掉的对象**：TopX 把"关节顺序/特征基/rest frame"三处任意性逐条列出并各自配一个设计。**这套写法可以借到任何"跨资产类型"的问题上**——比如"同一套材质参数在不同引擎里含义不同"，本质也是任意性；
- **接口的窄化正在成为可接受的代价**：L3G 绑死 VAE latent、FWM 绑死固定 2D 视角与格斗品类、TopX 绑死"有骨架文件"这一前提。**三篇都选择了"窄而快"，而不是"宽而慢"**——这与 2024–25 那批"统一一切"的口号正好反向。**对工程的含义：先做窄的、能上线的，再谈统一。**

## Key Takeaways

**1. 管线里最贵的一步通常在"模块之间"，而它不出现在任何模块的耗时里。** L3G 的 318× 是 RGB→latent 往返，NeRF 的 30 s/帧是每条光线 192 次查询，FWM 的 46.58% 是"用文本装时间窗"。**三者都不是算法慢，是翻译慢**——而翻译这一步在性能面板上往往只显示为"其他"。

**2. 降翻译税只有三种手法，且都已在今天出现：让上游直接产出下游的格式、让接口对上游的任意性免疫、让接口的形状按下游要分辨的东西来设计。** 三者的代价一致——**接口变窄**。L3G 绑死 VAE，TopX 绑死"有骨架文件"，FWM 绑死"固定 2D 视角 + 格斗品类"。**"宽而慢"与"窄而快"之间没有中间路线，只有"先窄后宽"。**

**3. 判断一个表示贵不贵，看"查询一次多少钱 × 一帧查多少次"，不要看内存。** NeRF 的权重只有几 MB，比任何体素都小，但它一帧查 1.5 亿次。**这条判据同样适用于粒子系统**：一个 64 MB 的粒子缓冲如果每帧要被随机访问十次，它比一个 512 MB 的顺序流贵得多。

**4. 消融里的"减法行"比"加法行"更能说明机制——但它也会骗人。** TopX 换掉 HK-RoPE 只贵 0.05，看上去"这个组件没用"；真相是**整套接口值 1.64，单个组件只分摊到 0.05**。**评审时该问的不是"这个模块贡献多少"，而是"拿掉它之后，剩下的部分还能不能工作"**——HK-RoPE 拿掉后系统还能跑（所以只贵 0.05），但换成学习式位置表就彻底失去"对任意骨架有定义"这个性质（所以那 0.05 是"性质"的价格，不是"精度"的价格）。

**5. 三个质量指标不同时赢，说明方法换到的是"另一种正确"，不是"更正确"。** L3G 的 PSNR/LPIPS 赢、SSIM 输（0.441 vs 0.525），且"去掉 VAE lifting"那版 PSNR 更高。**这与 10-30 的 Texture Consolidation（SSIM 赢的那个正是产生鬼影的做法）是同一类现象**：**当一个表示改变了"信息存在哪"，不同指标就会开始量不同的东西**。**遇到这种分裂，别急着选指标，先问"它们在量什么"。**

**6. 世界模型的记忆有三解，判据是"记忆跟着谁走"。** 压成定长（跟着**时间**走，$O(TR)$ 但可控）／搬上盘（跟着**位置**走，容量解耦但延迟在）／**只写缺口**（跟着**场景范围**走，$O(S)$ 但大范围探索仍会涨）。**L3G 只解决了第三解里的"读得动"，没解决"淘汰"**——$O(S)$ 在超大世界里仍会涨，而它没有剪枝、没有分层。**这是下一次要盯的地方。**
