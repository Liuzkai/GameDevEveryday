# Game Development Research — 2026-11-04

> **今日主题：局部决定不了的那一点。**
>
> 三篇来自三个毫不相干的领域——GS 渲染、WFC 理论、3D 建模——却在回答同一个问题：**"哪些东西是局部决定不了的？"**
>
> 三个答案的形状惊人一致：**那个东西沿着某个方向被「带」过去，所以必须由上游提前定下来。**
>
> AbacusGS 里是**盒内顺序**沿一个轴被带（只翻一个符号）；IW 2026 里是**行类型**沿整行被带（不能中途换值）；Merrell 2007 里**"能否补完"**根本不是局部问题（NP-完全）。
>
> 而代价也一致：**放弃一部分局部自由度**（−0.13 dB / 只能有"多个世界"不能有"每格独立" / piece 要手工拆）。

## Frontier Research

### [[2026-11-01-Ding — AbacusGS Gaussian Splatting without Per-Splat Sorting|AbacusGS — Gaussian Splatting without Per-Splat Sorting]]

**Why this matters：** 它把"每帧重排 31 个 splat"这件事拆开看，发现**真正每帧在变的信息只有 1 个比特**（相机在这片表面的哪一侧）。剩下的全部可以写进布局——于是排序从"每帧 N 个 key"变成"每帧 N/31 个 key + 一个符号位"。

**Personal Relevance：** 这条判据可以直接搬走——**当输入每帧都变时，问"输出真的每帧都变吗？变的是全部还是其中一点点？"** 你在 VFX 里做预算时反复遇到同一个形状（"每帧重新算什么"），这是它的严格版本。

关键数字（都是原文实测，RTX 6000 Ada）：

- **CPU 排序的 OpenGL 查看器：排序 24.1 → 4.6 ms，整帧 26.8 → 6.0 ms（4.5×）**；排序条目 2,058k → 35k（同口径可见集 1,099k → 35k = 31×，正好等于平均每盒 31 个 splat）；
- 质量：不微调 **−1.27 dB** → 顺序感知微调（3,000 步）后 **−0.13 dB**；紧凑格式 17.3 B/splat（3DGS PLY 是 248 B）；
- **冷水一**：只在 CPU 排序成立。GPU radix sort 时排序 1.3 ms，帧 3.8 → 2.6 ms（**1.46×**）；4K 下 13 个场景有 **4 个反而更慢**；
- **冷水二**：资产不能直接吃——每个模型要 3k/10k 步重拟合，且微调期间盒子划分与存序**冻结**。这是"按新顺序重训"，不是"转格式"；
- **冷水三（最漂亮的一条）**：用**精确**的八叉树 BSP 序反而更差（−2.89 dB，微调后 −0.246 dB，是质心深度序的两倍）。原因：**splat 会跨出格面——BSP 对格子精确，对格子里的 splat 不精确**。**当"保证的对象"和"你要的对象"差一层时，精确性是负资产。**

### [[2026-10-31-Najafgholizadeh — Infinite Worlds from One Example What Local Generators Must Share|Infinite Worlds from One Example — What Local Generators Must Share]]

**Why this matters：** 这是 [[Wave Function Collapse]] 这条线（2007 起）**一直缺的那条定理**。它证明：只要例子里有一个"**被有效性沿某条线携带的量**"（砖墙每行在灰缝之间的位置就是），那么**任何**只读局部独立随机数的生成器——不管半径多大、不管训多久——都不可能同时做到"没有违规窗口"和"统计忠实"。半径 $r$ 时违规密度**至少是 $1/r$ 阶**，而且有个构造恰好达到这个阶。

**Personal Relevance：** 这是"**降档不能解决问题**"最干净的样本。$1/r$ 意味着"把 chunk 做大一点"永远只是把缺陷从 1/8 降到 1/512——**变小有下限，归零必须换结构**。这跟你 VFX 预算里"减小 vs 归零"的区别是同一件事。

关键结果：

- **52 个公开 WFC 例子里 certify 13 个，其余 31 个一个都没有**（Fisher $p=8\times10^{-6}$，作者自己标注"变体不是独立样本"）；
- 独立随机数 + 修（mend）：13 个 certified 上**一个都不 valid**；min-coin copy（达到 $1/r$ 阶）在 Wall 上到半径 512 仍不 valid，按斜率外推要到 **≈2700**；
- 给输入之后：方法在 13 个 certified 里 **11 valid**（八度噪声单用 6 个）；全库 **45/52**（独立随机数规则 28/52）；
- **冷水一（最重要）**：**reach = 804 格**——"没有比 804 格更远的随机数能改变一个格子的颜色"。**随机访问在数学上成立，在编辑上不成立**：改一格可能改到 804 格外。对"玩家改建一块地"是硬伤；
- **冷水二**：修（mending）在方法 valid 的地方**中位数改写 18% 的格子**。作者自己的评价最狠：**"在有 copier 的地方，学习既不是世界有效的原因，也不是它新的原因。"**
- **冷水三**：只有 2D 位图、$N=3$、没有 3D/网格/玩法约束；"valid" 的定义是每千窗口 ≤1 违规，**不是零**。

## Classical Research

### [[Merrell 2007 — Example-Based Model Synthesis|Merrell 2007 — Example-Based Model Synthesis]]

**Historical Role：** **2016 年之后独立游戏 PCG 主流的真正出处**。库内 PCG 此前只有文法线（2001 城市 / 2003 立面 / 2006 建筑），约束线是空的——今天补上，两条腿才齐：**文法线管"规则怎么写"，本文管"约束怎么解"**。

作者本人页面上写得很直接：**"WFC reimplements the model synthesis algorithm…… The two algorithms are nearly identical."** 这是本库能拿到的最直接的一手归属说明。**名字扩散得比归属快**，引用时要写清楚。

**Knowledge Graph Role：** 它是 [[Wave Function Collapse]] 概念页的算法本体，也是 [[Procedural Content Generation]] 时间线上与文法线**同年同会、方法论相反**的那个岔口。

三件套（今天还全在用）：

1. **六向邻接表**：例子里"哪两个 piece 在哪个方向上相邻过"——例子的"风格"被完整编码进一张 $N^2\times6$ 的布尔表；
2. **全局传播**：迭代到不动点，剪掉"必然失败"的选择 —— **这就是 WFC 的 `propagate`**；
3. **切块 + 整块回滚**：把 NP-难问题做成能跑，**失败的代价被限制在一块里**（WFC 后来改成了"整张画布重开"——更简单，也更贵）。

**Related Concept：** [[Wave Function Collapse]]

**两处最该记住的自述限制（十九年后各自变成一条定理）：**

- 附录证明**"能否补完"是 NP-完全**（Planar 3-SAT 归约）⇒ "This global search only eliminates labeled vertices that are relatively easy to eliminate." **"总成功"在数学上不可能**；
- "it is possible that the output will be so tightly constrained that model synthesis will simply reproduce the example model over and over." —— **"过紧 ⇒ 复读机"**。而 IW 2026 证明了这句话**什么时候必然发生**：例子带一个沿行携带的量时，"只读位置"这条唯一免费的路线给出的就是"例子按绝对坐标平铺"——**一个世界**。

## Personal Learning Focus

### Normal → Easy

- **[[Wave Function Collapse]]**（新建，第 55 个概念）：只需拿走三层——① 它是**约束满足**（弧相容 + 最小熵贪心分支，**没有回溯**），不是"生成风格"；② **局部合法 ≠ 整体合理**，中间隔着一张转移表；③ 三类"局部决定不了"的分层（全局求解 / 块求解 + 固定背景 / 局部生成器）。**"失败率"是固有属性，不是 bug。**
- **"每帧重算"是最贵的默认值**（AbacusGS 的一句话判据）。把它挂到手上的半透明排序 / decal 队列 / 毛发片列表上问一遍，成本为零。

### Hard → Normal Bridge

- **IW 2026 的定理证明**（测度论 + i.i.d. 的因子）属 Hard，**不必读**。桥是**一个具体例子**：砖墙。想清楚"为什么一行砖不能中途错半格"（一行里任何一格换成别的位置，都会在那一格周围产生一个违规窗口），Theorem 1 的直觉就到手了——**相距 $2r+P$ 的两点读不到同一个随机数，所以它们的"看法"独立；而有效性要求一致；中间必然有缝。** 三句话，不需要任何记号。

## Technology Evolution

**约束求解线（今天补齐的一条完整弧线，19 年）：**

```text
1976  Wang tiles：局部可拼贴；难的是造瓦片集，不是拼
  ↓
2007  Merrell model synthesis：邻接表 + 全局传播 + 切块回滚
      + NP-完全证明（"总成功"不可能）
      + 自述"过紧 ⇒ 复读"
  ↓
2016  Gumin WFC：同一算法，单头文件 → 生态爆红
  ↓
2021-23 块求解器：为无限世界铺固定周期背景，"解不出来就保留背景"
  ↓
2026  IW 2026：证明"保留背景"是数学必然（背景 = 被携带的量本身）
      + 1/r 地板 + 必须沿该方向共享随机性 + 只读例子的证书
      + "相位周期必须整除分块周期"（唯一一条今天就能写进规范的硬规则）
```

**排序线（GS）新增第七个节点，而且是换轴的一个：**

```text
① 排得快 → ② 不排（OIT）→ ③ 换基元 → ④ 随机化（全删）→ ⑤ 路由 → ⑥ 驯服随机性
                                                                    ↓
                          ⑦ 【换轴】把顺序搬出帧：写一次，每帧一个符号位
```

> **这条"换轴"本身值得记**：①–⑥ 全部在**同一个平面内**优化（让每帧的排序更便宜或不存在），⑦ 换了一个平面（**顺序放在哪**）。判据：**当一条线上连续六个方案都在做同一件事时，下一个有效动作通常是换一个平面。**

## Important Relationships

- **"冻结一个变得慢的变量"这条轴，今天多了一格。** 库内 GI 谱系表记的是"视角 → 光照 → 几何，每代换一个被冻结的变量"（[[Goral — Modeling the Interaction of Light Between Diffuse Surfaces (1984)|Goral 1984]] 视角 / [[Sloan — Precomputed Radiance Transfer for Real-Time Rendering (2002)|Sloan 2002]] 几何与光照算子 / [[Jensen — Global Illumination using Photon Maps (1996)|Jensen 1996]] 光子）。AbacusGS 冻的是**顺序**——它在帧间变得最慢（只翻一个符号），却被每帧重算。**同一条方法论，第一次出现在渲染管线而不是 GI 里。**
- **PCG 两条线在"分块"上撞车**：[[2026-10-20-Ma — WorldStream Streaming Interactive 3D Worlds with Hierarchical Planning and Persistent State|WorldStream]] 的 boundary record（工程）↔ IW 2026 的"边界能承诺什么类型"（理论）。**WorldStream 的做法在 invariant 类约束下是对的，在 phase 类约束下不够**——相位要靠"周期整除 chunk 周期"，接缝对齐也没用。
- **AbacusGS 与 Merrell 2007 是同一个动作的两个领域版本**：都把一个"看起来是运行时的量"搬到"资产里"。前者搬顺序，后者搬"风格"（例子的邻接表）。**代价也同构：都要重新准备资产**（一次重拟合 / 一次手工拆块）。

## Emerging Trends

- **"生成器必须被给什么"正在变成可判定问题**。IW 2026 的证书是**训练前、只读例子**就能算的——这跟过去"训一个看看效果"的范式不同。若这个思路扩散，PCG 的工具链会多一个"先体检、再训练"的环节（类似 shader 编译前的 validation）。
- **"局部性"正在被拆成两个词**：**随机访问**（任意区域能独立算）与**局部可编辑**（改一处只影响附近）。IW 2026 是第一个把两者明确分开并给出代价的样本——804 格的 reach 说明**这两件事可以差三个数量级**。渲染里的"流式加载 vs 局部更新"是同一对词。
- **理论论文开始出现在图形/AI 交叉区**：本文 primary 是 `cs.LG`、cross-list 才是 `cs.GR`，作者是单机构两人、无大厂算力背书。**这是"小团队做定理"的一个样本**——与"大厂做系统"形成对照。

## Industry Signals

- AbacusGS 的 LLM Usage Statement 明写"用 Claude 做代码、实验、文献检索、图与文字，作者核验结果"——**这类声明在 2026 年的论文里越来越多，正在成为一种格式**。值得记：它把"用了什么工具"变成可引用的事实，而不是传闻。
- GS 的**资产格式战**继续：17 B/splat 是一个新的下限参照（对照 3DGS PLY 248 B、PlayCanvas 16 B）。**格式竞争的实际战场在"流式下载量 + 显存驻留"，不在 FPS**——因为它不依赖硬件。

## Watchlist

1. **AbacusGS 的 4D / 动态版**：盒子会每帧变形时，"盒内序"还稳定吗？（这是它自己没回答的问题）
2. **AbacusGS 的真机实测**：目前只有"降频 4× 的桌面 CPU + 桌面 GPU"。
3. **IW 2026 那 8 个"抗性但无证书"的例子被什么约束着**——理论目前最大的洞。作者说"至少在我们测的斑块尺寸与距离上看不见"。
4. **3D 体素 / 网格瓦片上的对应定理**：游戏里 WFC 大量用在 3D，论文只做了 2D 位图。
5. **相位周期 vs chunk 尺寸的实测**：找一个真有"周期 3 砖缝"或"周期 5 栅栏"的资产，把 chunk 宽度改成周期的倍数，看缝会不会消失。**这是今天最便宜的一个可验证动作。**

## Key Takeaways

- **先找"必须沿某条线一致的量"，再谈参数。** 有它 ⇒ 局部生成必然出缝，$1/r$ 的地板会一直跟着你；没有它 ⇒ 独立随机就够了。**判据比参数重要。**
- **"每帧重算"是最贵的默认值。** 输入每帧变 ≠ 输出每帧全变。AbacusGS 的整篇论文就是这一句话的 4.5 倍。
- **"精确"可能作用在错的对象上。** BSP 对格子精确、对 splat 不精确，结果比"不精确但作用对了对象"差一倍。**保证的粒度错一层，结论就反号。**
- **降档不能解决问题。** $1/r$ 意味着每一档都只是把缺陷变小；**变小有下限，归零要靠换结构**（共享随机性 / 存进布局 / 手工拆块）。今天三篇给的是同一个动作的三个版本。
