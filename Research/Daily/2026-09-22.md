## Frontier Research

### [[2026-09-20-ProxyBuild — Text-Guided Structured 3D Building Generation with Mesh-Anchored Procedural Proxies]]

**Why this matters**：它**填补了库中 PCG（程序化生成）域的零覆盖**——并且不是随便一篇 PCG，而是**恰好站在"程序化 × 生成式"的交点上**，与今日经典（[[Müller — Procedural Modeling of Buildings (2006)]]）构成"源头 ↔ 前沿"的闭环配对。原文引用核对时发现的两处时间跨度（见下），使这个配对从"同域"升级为"直接问答"。

**核心**：不写成规则、也从零不生成几何。输入一个**已分块但无语义标签**的建筑壳（点云重建 / LoD2 数据），**face-edge bigraph encoder 推断每个面/每条边的语义角色**（墙/屋顶/窗 vs 柱/梁/栏杆，含 Null 过滤），再由 **LLM（原文写明 GPT-5）解析文本属性 → 从资产库检索组件 → 硬约束对齐组装**。中间表示 **MAPP** = 面-边关联图 + 全图元的角色概率分布。

**三组数据（全文核对）**：

| 维度 | 关键数字 |
|---|---|
| 人评（20 人盲评，1–10 分） | **视觉 8.2 / 结构 8.1 / 文本 8.5**（对比 BuildingBlock-Box 7.5/7.7/8.4、ShellMaker 7.3/7.5/7.2、Meshy 7.1/6.7/7.9、Trellis 6.4/6.2/7.4） |
| 消融 · 去 Edge Stream | CLIP-S 0.349→0.339、UNI3D 0.438→0.407、**ACC 91.5→76.4**（细长构件识别崩） |
| 消融 · 去硬约束 | **NCR 95.7%→73.6%**、ACC 不变（91.5）→ **"知道放什么"与"放得对"是两笔账** |

**Personal Relevance**：与 VFX 无直接交集（纯离线资产生成）。但有**三条可带走的抽象**（已写入笔记）：① **"生成的结构应紧锚定在基础几何的拓扑上"** —— 评估一切生成式资产方案时的第一问是"它的结构锚在哪里"；② **可编辑性 = 修正动作落在"语义槽位"而非"网格顶点"**；③ 消融的直接教训：**结构预测准确 ≠ 实例化摆放正确**。

## Classical Research

### [[Müller — Procedural Modeling of Buildings (2006)]]

**Historical Role**：**程序化建筑（PCG 域）的奠基论文**——CGA shape 形状文法，SIGGRAPH 2006 / TOG 25(3)。作者 Pascal Müller（ETH Zürich）+ Peter Wonka（ASU）+ Haegler / Ulmer / Van Gool。**直接演化为 CityEngine**（2007 成立 Procedural Inc. → 2008 首商用版 → 2011 被 Esri 收购，规则语言至今仍叫 CGA）。

**来源**：**原文 PDF 已下载并逐节核对**（10 页，来自 Wonka 官方出版物页；CityEngine 时间线为多来源交叉，非原文）。

**核心三条**：

1. **两阶段推导（本文 key insight）**：不在"可见立面表面"上写规则——因为**"这些表面是算法的输出，而不是产生式规则的输出"**；改为 `三维体块 → component split 抽面 → 得到对齐且参数化的二维 scope → 应用立面/屋顶规则`。
2. **CGA 是顺序文法**（受 L-system 记号启发但类型不同）：原文原话——**并行文法适合刻画"随时间生长"，顺序应用规则才能刻画"结构"**；对建筑，"生长"隐喻"常常适得其反"。
3. **两个一致性机制**：**occlusion 查询**（`none/part/full` 三态 → **优雅降级**：能放窗放窗、不能放墙、全遮挡删掉；`noparent` 排除父形状是必须修正）+ **snapping 吸附线**（体块所有面 → 全局构建平面 → 楼层线自动跨全部体块对齐）。

**生产数据（原文逐图核对）**：

| 项目 | 数据 |
|---|---|
| 单楼生成 | 50k 多边形 ≈ **1 秒**（+0.5s 写盘） |
| **庞贝重建** | **190 条手写规则** → **14 亿（1.4 billion）多边形 @高 LoD** / 3100 万 @中 / 17 万 @低 |
| Beverly Hills | ~150 规则 / ~1000 栋 / **7 亿多边形** |
| 行业对照 | 《超人归来》城市模型 = **15 人年** |
| 可用性 | 职业建模师：**学 1 天 + 独立 2 天**做出小城市 |

**两条 2006 年的"预言"，今天被逐条兑现**：

- **"rule authoring is laborious"**（规则编写费力）→ **ProxyBuild 用"推断 + 检索"绕开写规则**（今日前沿）；
- **"employ shape grammars for shape understanding"**（Discussion 写下的未来方向：用形状文法做形状**理解**）→ **ProxyBuild 的 face-edge 语义推断就是这个"理解模块"**。

**Knowledge Graph Role**：补齐 PCG 域历史锚点；同时它是"**离线生成 vs 实时预算**"分工的原型——原文自述"实时化需要**尚未开发的 LOD 技术**，因为**我们不优化一致拓扑**"。

## 🔴 今日最重要发现：PCG 域从"零覆盖"到"双锚点"，而且两锚点是一次跨 20 年的直接问答

今天之前，库里 **Papers 47 篇没有一篇 PCG，Concepts 28 个没有一个程序化生成概念**。今日一次入库两篇，恰好构成完整链条：

```text
2006  Müller：结构从哪来 = 人写规则（庞贝 190 条），中间表示 = 二维 scope
        ↓  20 年后仍在解决的原文自述问题："rule authoring is laborious"
2026  ProxyBuild：结构从哪来 = 网络推断角色 + LLM 解析，中间表示 = 角色概率分布
        ↓  保留的骨架完全一样：宏观（自由体量）+ 显式中间表示 + 微观（规则/检索填充）
```

**对你这套分档/预算工作的两条跨域借条**（从经典笔记抽出来的，直接可用）：

1. **"绝对 vs 相对"参数化**：CGA 用 `r` 后缀区分"缩放的值"与"不缩放的值"（原文明确：**建筑部件并非都等比缩放**）。
   → **同构到你的五档**：**特效参数也并非都随档位等比缩放**——有些是绝对上限（贴图尺寸、灯数），有些是相对量（时长、粒子密度）。**给每个参数标一个"绝对/相对"属性，本身就是一次分档体检。**
2. **"离线生成量与运行时负载是两本账"**：2006 年生成十亿多边形不眨眼，实时化却卡在 LOD；2026 年 ProxyBuild 全程离线，同样不涉运行时。
   → 与你的预算法则同构：**成本不会消失，只会转移**（生成端多省的工，会变成运行时要还的账，或反之）。

## Important Relationships

- **[[Müller — Procedural Modeling of Buildings (2006)]] ⟷ [[2026-09-20-ProxyBuild — Text-Guided Structured 3D Building Generation with Mesh-Anchored Procedural Proxies]]** —— 同日入库、跨 20 年的**直接问答**（见上"最重要发现"）。**这是本库又一次"经典与前沿在同一天击中同一根线"（上次是 9-21 的预算五维对齐）。**
- **ProxyBuild ⟷ [[HairCS — Reconstructing Strand-Based Hair from Hair Cards]]** —— **同题异构的"表示升档"**：发片 → 发丝；无语义壳 → 语义组件。**共同母题：从不可编辑表示恢复到可编辑表示。**
- **ProxyBuild ⟷ [[Magpie — Real-Time World Renderer for Interactive Games]] / [[DLSS 5 — Generative Neural Rendering]] / [[2026-09-17-PBR-Latent — Physically Based Rendering in the Latent Space]]** —— **"生成模型只做决策层"的四个深度**：DLSS 5 只重建画面、PBR-Latent 只补物理残差、Magpie 只重画白模、ProxyBuild 只定结构角色。**四者都不让生成模型碰"资产本体/世界状态"。**
- **[[Procedural Content Generation]] ⟷ [[Particle Systems]]** —— 同族的两种程序化生成：**静态资产**（建筑/地形）vs **动态现象**（火/云）；共享同一成本语言（层级数量、屏占比 × 密度）。
- **[[Procedural Content Generation]] ⟷ [[Real-Time VFX Performance Budgeting]]** —— **真实交叉点**：PCG 生成的场景是 VFX 的承载容器。**PCG 产出多少几何/半透明植被，会直接垫高运行时的特效预算底噪。**

## Emerging Trends

1. **"生成只做决策层"模式四连**（DLSS 5 / PBR-Latent / Magpie / ProxyBuild）——**从渲染延伸到内容生成**。判据成形：**拿到任何"生成式方案"，先问它把不确定性留在哪一层、让谁做决策。**
2. **"可编辑性"成为生成式资产的硬门槛**（ProxyBuild 的编辑能力 = 修正落在语义槽位；CGA 时代是改规则）——**生成的东西进不了 DCC、改不了，就不进管线。**
3. **PCG 与 AI 的合流进入第二阶段**：第一阶段是"让 LLM 直接写规则"（论文自述：**失败**——"LLM 缺乏精确 3D 空间感知与连续数值推理"）；第二阶段是"LLM 只解析语义，结构交给专门的网络"（ProxyBuild）。**与"分层收敛"同构。**

## Key Takeaways

1. **今日最重要的成果是一次"补域"**：**PCG 域从零覆盖到"源头 + 前沿"双锚点**，且两锚点是一次**跨 20 年的直接问答**（2006 的 "rule authoring is laborious" 与 "shape understanding" 两个自述方向，2026 年被 ProxyBuild 逐条兑现）。
2. **CGA shape 的 key insight 至今有效**：**"表面是算法的输出，不是规则的输出"→ 规则（或生成）必须作用在结构化的中间表示上。** 2006 年叫"二维 scope"，2026 年叫"角色概率分布"——**本质是同一件事：给生成过程一个可对齐、可查询、可修正的工作面。**
3. **两条可直接用的跨域借条**：① **"绝对 vs 相对"参数化**（建筑部件并非都等比缩放 → 特效参数也并非都随档位等比缩放，**给每个预算参数标一个"绝对/相对"属性**）；② **"离线生成量与运行时负载是两本账"**（与"成本不会消失只会转移"同构）。
4. **消融里的方法论教训（新判据）**：**"知道放什么"与"放得对"是两笔账**——ProxyBuild 去掉硬约束后，角色预测准确率（ACC）纹丝不动而碰撞率（NCR）从 95.7% 崩到 73.6%。**评估任何"预测 + 执行"的系统，要分开测这两层。**
5. **产业侧双信号**：① **UE6 进入"职业电竞实测"阶段、首作 2027**（引擎换代节奏在加快）；② **XeSS 3 官方 UE 插件落地，"帧生成倍率"成为引擎级可配置参数**——你分档矩阵的"帧生成倍率维度"从此有引擎侧实现证据。
6. **"生成只做决策层"模式扩展到内容生成**（第 4 例 ProxyBuild）：**拿到任何生成式方案，先问它把不确定性留在哪一层、让谁做决策。**
