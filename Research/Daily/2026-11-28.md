## Classical Research

### [[Müller 2007 — Position Based Dynamics|Müller 等 2006 — 刚度是一个迭代次数]]

**Historical Role**：这是**实时物理的分岔口**。它之前的二十年，"更准"意味着"解更大的系统"；它之后，游戏里"更硬"意味着"多迭代几次"。两条路的成本结构完全不同：隐式路线买的是**每步解一次方程**，PBD 买的是**每步扫几遍约束**。

**它到底做了什么**（一句话）：不算力、不解矩阵，先显式预测位置，再把点推到满足约束的位置上，最后用位置差反推速度：

$$p\leftarrow x+\Delta t\,v;\qquad p\leftarrow p-s\,w_i\nabla C;\qquad v\leftarrow(p-x)/\Delta t$$

**核心公式里三个因子各有出处，这是全篇最该抄的一段**：

$$s=\frac{C}{\sum_j w_j\lvert\nabla_{p_j}C\rvert^{2}},\qquad \Delta p_i=-s\,w_i\nabla_{p_i}C$$

| 因子 | 出处 | 删掉会怎样 |
|---|---|---|
| 沿 $\nabla C$ 推 | **动量守恒**：内部约束对刚体运动不变 ⇒ $\nabla C\perp$ 平移/旋转 | 物体被自己的约束推着走（鬼力 ghost force） |
| 分母 $\sum w\lvert\nabla C\rvert^2$ | 对**单条**约束做一次 Newton 步 | 推过头 / 推不到位，迭代不收敛 |
| 逆质量 $w_i$ | 无限质量的点不动（$w=0$） | 钉住的顶点被拉走、重物被轻物推飞 |

**"软"是怎么变成旋钮的**：把 $\Delta p$ 乘上 $k\in[0,1]$，$n_s$ 次迭代后残余是 $\Delta p(1-k)^{n_s}$。作者嫌它对迭代数非线性，给了 $k'=1-(1-k)^{1/n_s}$，让误差变成 $\Delta p(1-k)$——**与迭代数无关**。

**然后他写下了那句宪法**：

> *"However, the resulting material stiffness is still dependent on the time step of the simulation. Real time environments typically use fixed time steps in which case this dependency is not problematic."*

**固定步长是纪律，不是物理。** 这句话解释了此后十年所有"同一资产换机器就变样"的事故。

**四个数字（Pentium 4 3 GHz，含渲染）**：1364 顶点 / 2562 三角形的布带自碰撞 **30 fps**；4264 / 8262 的撕裂场景 **47 fps**；6 刚体 + 3 布条 **>380 fps**。**注意口径：这些是"仿真 + 渲染"的整帧数，没拆开**——不能当求解器基准用。

**三处冷水**：① **2007 版没有刚体**（Future Work 明写），"PBD = 刚体求解器"是后来的事；② **碰撞约束在求解循环外生成、循环内冻结** ⇒ 可能漏碰撞，补法是加子步；③ **Gauss-Seidel 的顺序是隐式输入**——过约束时会震荡，"顺序不固定"是原文自己承认的失效条件。

**Knowledge Graph Role**：把 [[Cloth Simulation]] 时间线上 2007 那一格的"（库外）"换成一节可读的机制；给 [[Position Based Dynamics]] 提供"软 = 没解完"这一半的定义。

### [[Macklin 2016 — XPBD Position-Based Simulation of Compliant Constrained Dynamics|Macklin 等 2016 — 给"软"一个单位]]

**Historical Role**：六页的**接口修正**。它不发明新算法，只把 Servin 2006 的"柔度约束"接到 PBD 的 Gauss-Seidel 循环上。结果是：**同一个循环，刚度变成了材料参数。**

**一行公式**：

$$\Delta\lambda_j=\frac{-C_j-\tilde\alpha_j\lambda_j}{\nabla C_jM^{-1}\nabla C_j^{\mathsf T}+\tilde\alpha_j},\qquad \tilde\alpha_j=\frac{\alpha_j}{\Delta t^{2}}$$

**三个改动，各解决一件事**：

| 改动 | 作用 |
|---|---|
| 分子多 $-\tilde\alpha\lambda$ | 约束不再被推到头，留下与柔度匹配的残余 ⇒ **它是一根弹簧，不是一次投影** |
| $\alpha\to\alpha/\Delta t^2$ | **量纲逼出来的**：$\alpha$ 是 m/N（s²/kg），而分母那项 $\nabla CM^{-1}\nabla C^{\mathsf T}$ 是 1/kg——只有除以 $\Delta t^2$ 才能相加 |
| 分母多 $+\tilde\alpha$ | $\alpha=0$ 时**精确退化成 PBD 的 $k=1$** ⇒ 升级不用重写求解器 |

**"它是一根弹簧"这句话可以算出来**：由 $C+\tilde\alpha\lambda=0$ 得 $\lambda=-C\Delta t^2/\alpha$，于是

$$f=\frac{\lambda}{\Delta t^{2}}=-\frac{C}{\alpha}=-k\,C$$

**这就是"柔度"的全部内容**：约束允许被违反，违反量正比于力。**PBD 的 $k=1$ 只是 $k\to\infty$ 的那个极限。**

**四个数字**：

| 实验 | 读数 |
|---|---|
| 简谐振子（$\alpha=0.001$） | PBD 的 1/5/10 次迭代给出**三条不同的周期**；XPBD 与解析解重合 |
| 20 粒子链约束力（$\alpha=10^{-8}$） | 最大相对误差 **6% / 2% / 0.5%**（50 / 100 / 1000 次迭代） |
| 悬挂布料 64×64 / **24k 约束**（表 1） | 20→160 次迭代：PBD **0.95/1.75/3.25/5.61 ms**，XPBD **0.97/1.78/3.34/5.65 ms** ⇒ **+2%** |
| 布料形态（图 6，$k=0.01$） | PBD 随迭代**越来越硬、越来越闷**；XPBD 四档几乎不变 |

**最诚实的一句在 §6.4**：

> *"We note that **XPBD does not converge faster than PBD**, simply that behavior remains consistent at different iteration counts."*

**它不是更快的 PBD，它是"同一个行为"的 PBD。** 买的是可移植，不是速度。

**四处冷水**：① **$\alpha=0$ 时与 PBD 完全一样**，要刚还是得堆迭代；② 低迭代 ⇒ **人工柔度**（提前停止就比设定更软）；③ **只是隐式 Euler 的近似**（不像 Projective Dynamics 有变分形式）；④ **接触仍是零柔度**，"软接触"不在框架内。

**⚠️ 一条常见的时代错置**：库里多处写"XPBD + 小步长"，但**"多子步 + 每步 1 迭代"是 2019 年 Small Steps 的结论，不在这篇里**。引用时分清年份。

**Knowledge Graph Role**：给 [[Position Based Dynamics]] 提供"软 = 约束允许被违反"的另一半；把 [[Cloth Simulation]] 的 Learning Gap 第 1 条关掉。

## Personal Learning Focus

### Normal → Easy

- [[Position Based Dynamics]] —— **目标：看到一个"0–1 的滑块"，能问出三个问题**：有单位吗？改别的设置会不会变？换个引擎还能用吗？三个都否 ⇒ 它是求解器参数。**这个判据不只用于物理**：材质的 roughness、灯光的 intensity、"混合强度"都在同一道题上。
- **"软 = 没解完"这句话** —— 记住它，你就能解释两件每天都在发生的事：**为什么加迭代会变硬**（残差被删得更干净）、**为什么降帧率会变硬**（$\Delta t$ 变小，等效刚度变大）。**一个词解释两个现象，值。**
- **$\tilde\alpha=\alpha/\Delta t^2$ 的量纲推理** —— 30 秒能自己重做一遍：$\alpha$ 是 m/N、分母项是 1/kg，所以必须除 $\Delta t^2$。**这是本库见过的"量纲决定公式"最干净的样本**（比记公式有用）。

### Hard → Normal Bridge

- **"多约束下 $k$ 改的是不动点，不只是收敛速度"** —— 单约束时 $k<1$ 只是慢（照样收敛到 $C=0$）；多约束时每个约束推一部分、下一个又推回来，平衡点是一个 $k$ 决定的折中。**桥**：两根互相垂直的约束、$k=0.5$，手算两轮迭代，看它停在离两条流形都差一点的位置——**那个"都差一点"就是"软"**。
- **为什么 XPBD 的 $K\approx M$ 不改解** —— 它丢掉的是约束 Hessian（几何刚度），只改**收敛路径**，不改不动点。**桥**：把 Newton 法里的 $K$ 换成 $M$ 就是"最速下降 + 质量度量"，步长变了、终点没变。**这条是"准 Newton 也能收敛到同一个解"的最小样本。**
- **可微物理为什么绕不开 PBD 的硬边** —— 投影是分段光滑的（$\max(0,\cdot)$、归一化、碰撞集合的开关），而碰撞集合**在循环内冻结**⇒ 梯度在"这一帧有几个约束"变化时跳变。**这正好接上 [[2026-11-13-Shu — Same Physics Different Gradients A State-of-the-Art Report on Differentiable Physics Simulation|Shu 2026]] 的"接触诱导的梯度塌陷"与 [[Contact Dynamics]] 的"可微仿真必然选正则档"**——PBD 是最难可微的那一档。

## Technology Evolution

**这条线二十年只修一件事：「软」由谁定义。**

```
1995  Provot        步后修正（只修过冲的弹簧）—— 软 = 补丁
2001  Jakobsen      Verlet + 改位置（只做距离约束）—— 软 = 次数
2006  ★ PBD         一般约束 + 动量守恒 + 商业布料 —— 软 = 没解完（k ∈ [0,1]）
2013  PBF           密度约束 + 人工压力 —— 软 = 不可压缩性被违反多少
2016  ★ XPBD        柔度 α（m/N）+ 约束力 λ —— 软 = 约束允许被违反
2019  Small Steps   多子步 × 单迭代 —— 软 = 子步精度
2020  XPBD 刚体      关节 / 摩擦 / 接触进同一框架
```

**每一次改动都在同一个旋钮上换单位**：次数 → 比例 → 柔度 → 步数。而**"位置永远合法"这条底层承诺一次都没动**——这才是它在游戏里活下来的原因。

**同一条时间线的另一侧（渲染）方向相反**：

```
2012  Burley        物理量 → 10 个 0–1 旋钮（为了"处处合法、可调"）
2013  Karis         10 个 → 3 个（为了进纹理管线）
2016  XPBD          0–1 → 有单位的柔度（为了"可移植"）
```

**同一个年代，渲染在把物理量换成旋钮，物理在把旋钮换回物理量。** 两个方向都对：**渲染的旋钮要给美术用，物理的旋钮要给资产用**——美术要直觉，资产要可搬运。

## Important Relationships

- [[Position Based Dynamics]] ←→ [[Cloth Simulation]]：**同一个知识体的两个高度**。Cloth 页讲"四种解法的成本形状"，PBD 页讲"第三种解法内部那个旋钮是什么"。Cloth 页的成本恒等式（步数 × 每步代价）在 PBD 页变成三本账（约束数 × 迭代数 × 子步数）——**同一个式子的两种写法，后者的三项都能被美术直接看到**。
- [[Position Based Dynamics]] ←→ [[Contact Dynamics]]：**"接触"在两个页里的地位完全不同**。Contact 页里接触是一个需要"选转写"的子问题（精确/松弛/正则）；PBD 页里它是**又一条不等式约束**，扔进同一个循环。**买到一个循环解决一切，欠下没有真库仑摩擦、没有唯一解、没有收敛保证。**
- [[Position Based Dynamics]] ←→ [[Multigrid]]：**对同一句问题的相反回答**。多网格说"迭代数不是成本"（$O(n)$ 靠层级，不靠迭代）；PBD 说"迭代数**就是**刚度"（加迭代就变硬）。**两者的分歧点是一个物理量：耦合长度。**
- [[Macklin 2016 — XPBD Position-Based Simulation of Compliant Constrained Dynamics|XPBD 2016]] ←→ [[Burley 2012 — Physically Based Shading at Disney|Burley 2012]]：**同一年代、方向相反的参数化**。Burley 把 11 个物理量压成 10 个 0–1 旋钮（要"处处合法"）；XPBD 把 0–1 的 $k$ 换回有单位的 $\alpha$（要"处处同一"）。**一个为美术，一个为资产。**
- [[Müller 2007 — Position Based Dynamics|PBD 2006]] ←→ [[Baraff-Witkin — Large Steps in Cloth Simulation (1998)]]：**同一道题的两个答案，成本结构正好相反**。1998 说"步长与刚度解耦，代价是每步解方程"；2006 说"每步不解方程，代价是刚度和步长又绑回去"。**八年后绕回原点，但这次绕回来的是速度。**
- [[Position Based Dynamics]] ←→ [[2026-11-13-Shu — Same Physics Different Gradients A State-of-the-Art Report on Differentiable Physics Simulation|Shu 2026]]：**可微物理绕不开的那一档**。投影里有 $\max(0,\cdot)$、有归一化、有"这一帧有几个碰撞约束"的开关 ⇒ 分段光滑 + 集合可变 ⇒ 梯度在事件处跳变。**这解释了为什么 2026 年的可微工作几乎都走"正则档"。**
- [[Position Based Dynamics]] ←→ [[Budget Units]]：**又一种计价对象**。渲染的预算是像素/字节，PBD 的预算是"约束 × 迭代 × 子步"——**三项里有两项同时决定"看起来多硬"**，所以它不能像别的预算那样单独压一项。

## Emerging Trends

1. **"参数化"这条线在 2026 年已经分成两派，而且都成了论文的核心论点。** 渲染侧（ReMeDi / Burley）把物理量换成"可调的 0–1 且处处合法"；物理侧（XPBD）把 0–1 换回"有单位、可搬运"。**判据：这个参数是给谁用的——美术（要直觉）还是资产（要可移植）？** 同一件东西不可能同时满足两边，**所以引擎界面迟早要分成两层**（一层给美术的"感觉旋钮"，一层给资产的"物理量"）。这是本库对 2026 之后的一个可检验预测。
2. **"状态永远合法"作为一种设计范式，正在从物理扩散到别处。** PBD 的稳定性不来自积分器，来自"只走到被允许的位置"。本库已经见过同构的三次：蒙皮换混合空间（混完必是刚体）、MESSI 的门控 LoRA（$z=0$ 时数学上消失）、ReMeDi 的三网络（两端各自完整）。**它们的共同点：错误在结构上不可能发生，而不是被损失函数惩罚。** 检验方法仍是那一句——**去掉那个后处理项，它还成立吗？**
3. **"约束"正在取代"力"成为跨域的第一公民。** PBD 用 $C(x)$ 统一了距离、弯曲、体积、碰撞、固定；同一时期渲染侧用"约束"统一了采样（MIS / GRIS 的权重约束）、几何（单射/无翻转）。**一个领域成熟到某个程度，就会把"力/能量"这类二阶量换成一阶的"约束"**——因为约束更好写、更好查、更好证。
4. **可微物理的"硬边"已经被定位到具体机制上。** 本库现在能指名道姓地说出三个：**集合可变**（这一帧有几个碰撞约束）、**分支不可导**（$\max(0,\cdot)$）、**线性求解被当精确算子**（A1\*）。PBD 同时踩中前两个，所以它是最难可微的一档——**2026 年那批"可微布料"论文几乎都绕开 PBD 走连续介质或神经代理，原因在此。**
5. **工业界的物理论文，验收标准是"能不能被美术调"，不是"准不准"。** PBD 2006 的 Related Work 里从头到尾没有一次和"物理正确"比较，全是"可控 / 稳定 / 快"；XPBD 2016 的摘要第一句是"long-standing problem of iteration count and time step dependent constraint stiffness"——**它修的是一个"资产复用"的工程问题，不是一个物理精度问题。** 这个取向差别，是学术论文与中间件文档的分水岭。

## Industry Signals

- **两篇都出自中间件厂商，不是大学**：PBD 的作者全部在 **AGEIA**（PhysX 前身，2008 年被 NVIDIA 收购），XPBD 的三位作者全部在 **NVIDIA**。**同一条产品线，隔了九年，自己修自己。** 这解释了为什么 PBD 的 Related Work 里"稳定性/可控性"排在"精度"前面，也解释了 XPBD 为什么只有六页、为什么强调"trivial modifications to an existing PBD solver"——**它要的是让已售出的求解器能升级，而不是赢一次 benchmark。**
- **"引擎界面停在 2006 年"是一个可观察的行业事实**：Houdini Vellum、UE Chaos Cloth、PhysX Cloth 暴露的仍是 `stiffness 0–1 + iterations + substeps` 三件套，而 XPBD 的柔度 $\alpha$ 已经发表十年。**不是不知道，是"0–1 更好卖"**——美术要的是一个能从 0 拖到 1 的滑块，而不是 0.0003 m/N。**代价被转移给了资产管线**（同一件衣服换平台要重标定）。
- **NVIDIA 在物理侧的两代人都出自同一组作者**（Müller / Macklin / Chentanez），从 PhysX 到 Flex 到 Isaac 到 Warp，**这条线是"实时物理"在工业界唯一连续的一条血脉**。库内 [[2026-11-13-Shu — Same Physics Different Gradients A State-of-the-Art Report on Differentiable Physics Simulation|Shu 2026]]、[[2026-10-30-Böttcher — Total Deformation-based MPM for Perfectly Elastic Solids|Böttcher 2026]]、[[2026-10-21-Li — RLMuscle Muscle-Driven Character Animation via Reinforcement Learning|RLMuscle]] 的对照基线（Isaac / MuJoCo）都在这条血脉的下游。

## Key Takeaways

1. **"软"在 PBD 里不是材料属性，是"没解完"。** $k\in[0,1]$ 是每次迭代删掉多少残差；加迭代变硬、降帧率变硬——**一个词解释两个现象**。
2. **$k'=1-(1-k)^{1/n_s}$ 只修好了迭代，没修步长。** 作者自己写下了"material stiffness is still dependent on the time step"，并用"实时环境用固定步长"把它推给了使用者的纪律。**一句工程纪律，撑了十年。**
3. **XPBD 的全部内容是一个除法：$\tilde\alpha=\alpha/\Delta t^2$。** 为什么是平方不是一次方——**量纲逼的**（$\alpha$ 是 s²/kg，分母那项是 1/kg）。**这是"量纲决定公式"最干净的样本。**
4. **$\alpha=0$ 时 XPBD 精确退化成 PBD（$k=1$）。** 所以它不是"更好的 PBD"，是"同一行为的 PBD"：原文自己写 *"does not converge faster"*。**升级是免费的（+2% 时间），但没让刚体更刚。**
5. **同一个年代，渲染与物理在做方向相反的参数化。** Burley 把物理量换成 0–1（给美术调），XPBD 把 0–1 换回物理量（给资产搬）。**"这个参数给谁用"是判断参数化好坏的第一问。**
6. **"状态永远合法"是一种可迁移的设计范式。** PBD 的稳定性不来自积分器，来自"只走到被允许的位置"；与"混完必是刚体""$z=0$ 时数学消失"同族。**检验：去掉那个后处理项，它还成立吗？**
7. **可微物理绕开 PBD 不是偶然。** 投影里有 $\max(0,\cdot)$、有归一化、有"这一帧有几个碰撞约束"的开关 ⇒ 分段光滑 + 集合可变 ⇒ 梯度在事件处跳变。**这是"接触诱导的梯度塌陷"在 PBD 上的具体形态。**
8. **工业物理论文的验收标准是"能不能被美术调"，不是"准不准"。** PBD 的 Related Work 从头到尾没和"物理正确"比过一次；XPBD 摘要第一句是工程问题。**读这类论文时，先找它的验收对象，再判断它的数字能不能搬到你的项目里。**
